# 架构渐进重构状态

AutoSlice 正在进行渐进式模块化重构。当前只完成了 **Phase 1 的架构护栏与可测基线**；`topic_engine.py` 仍是大型单体兼容 façade，模块拆分、LLM Gateway 迁移、循环依赖消除和持久任务存储均未完成。

本文记录可由代码和自动测试复核的当前状态，不代表目标架构已经落地。

## 1. 可重复的 AST 快照

`scripts/architecture_snapshot.py` 只扫描仓库内的 Python 源码和测试源码，不读取 API 配置、模型、录播、字幕、时间轴、字体、贴图或其他用户媒体。快照不包含生成时间和本机绝对路径，因此相同源码会生成相同 JSON。

生成或检查快照：

```powershell
python -B scripts/architecture_snapshot.py
python -B scripts/architecture_snapshot.py --check
```

当前 `architecture_baseline.json` 中的事实如下：

| 指标 | 当前基线 |
|---|---:|
| 产品 Python 模块 | 31 |
| 产品源码行数 | 26,017 |
| 顶层函数 | 744 |
| 顶层类 | 36 |
| 本地模块 import 边 | 41 |
| 重复顶层函数/类名 | 0 |
| 测试对私有符号的 patch | 139 |
| `topic_engine.py` 行数 | 12,337 |
| 当前最长函数 | `topic_engine._retry_clip_review_from_artifacts_impl`，415 行 |

这些值来自源码 AST 和源码文本，不是目标值，也不是“架构已完成”的证明。以后审查快照变化时，应区分真实改善、合理新增和指标倒退，不得直接手改数字来绕过契约。

## 2. 仍然存在的有限架构债务

### 2.1 循环依赖仍未消除

当前 AST import 图中仍有一个强连通分量：

```text
subtitle_workflow -> topic_engine
topic_engine -> subtitle_workflow
```

`architecture_baseline.json` 将它标为 `debt_status: present`。测试只允许这个精确模块集合暂时存在；新增模块环会失败，不能使用通配符、目录前缀或“允许所有已知问题”之类的无限白名单。该债务计划在后续共享契约下沉后消除。

### 2.2 LLM 仍未形成最终唯一 Gateway

`llm_client.py` 当前提供配置与兼容 HTTP 传输，`topic_engine.py` 的 6 个导入别名通过对象身份断言确保没有被文件后部旧定义覆盖。但是下列实现仍由 `topic_engine.py` 持有：

- `_LLMProviderRetryCoordinator`
- `_call_llm_with_retry`
- `_decode_llm_response_json`
- `_parse_anthropic_response`
- `_parse_openai_response`
- `call_llm`

因此，Phase 1 只保证当前导入身份不会悄悄失效；它不宣称 LLM transport、provider 解析和业务重试已经迁入唯一 Gateway。

### 2.3 单体和私有 patch 债务仍然较高

`topic_engine.py` 仍有 12,337 行，当前最长函数仍有 415 行，测试仍有 139 个私有符号 patch。后续抽取必须同步删除原定义、保留公开契约，并通过身份与重复定义护栏；仅新增模块但保留单体中的第二套实现不算完成。

## 3. 当前自动护栏

### 3.1 依赖方向与重复定义

`test_architecture_contracts.py` 会检查：

- 当前依赖环不得超出有限债务基线；
- `autoslice` 和 `autoslice.*` 底层模块不得反向导入 `topic_engine`、`app` 或 `subtitle_workflow`；
- 任一模块不得出现重复顶层函数名或类名；
- LLM 传输导入别名必须与来源模块保持对象身份；
- 仍驻留在单体中的 LLM 实现必须继续如实标为债务，直到实际删除。

### 3.2 外部副作用

`test_external_boundaries.py` 在测试进程中阻断未 mock 的：

- HTTP、URL 和 socket 外连；
- FunASR、ModelScope、Hugging Face、Transformers 和真实 torch 包加载；
- `python -m pip` 包或模型安装；
- Flask 真实启动以及 5002/5010 端口绑定；
- 系统临时目录或显式批准临时根之外的媒体、字幕、时间轴、模型、字体和贴图访问；
- 携带非临时媒体路径的原生子进程调用。

测试仍允许显式 `unittest.mock`、无文件来源的伪模块和本地临时目录夹具。护栏的目标是让纯模拟回归可运行，而不是运行真实 LLM、下载模型、启动服务或处理用户录播。

## 4. 本地与 CI 验证

Phase 1 护栏命令：

```powershell
python -B -m unittest test_architecture_contracts test_external_boundaries -q
```

Windows CI 在完整回归前执行完全相同的定向命令。完整回归使用下列入口，确保在发现和导入任何测试模块之前先安装护栏，而不是依赖测试文件名或导入顺序：

```powershell
python -B scripts/run_hermetic_tests.py -q
```

普通测试仍是回归主体；前置护栏不能替代现有功能测试，也不能因为当前测试为绿色就宣称模块化重构完成。系统字体属于公开运行时资源，可以只读访问；AutoCover 测试的用户贴图目录必须显式指向临时目录，不能读取真实 `AppData` 草稿或用户素材。

真实 LLM、FunASR 下载、GPU 安装、5002/5010 服务、FFmpeg 成片和用户长录播不属于 Phase 1 自动验证范围。
