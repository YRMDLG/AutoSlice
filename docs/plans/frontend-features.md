# AutoSlice 前端与功能执行计划（公开执行规格）

> 状态：待实施；本文件是仓库内公开的前端与功能执行规格，运行时状态只记录在根目录 `ACTIVE_PLAN.md`。
>
> 目标：先把每天都会用到的字幕校对链路做稳定、顺手、可回退；再处理字幕识别质量；
> 然后把自动切片成果可靠地衔接到 AutoCover；最后收口任务状态和桌面端体验。
>
> 适用范围：AutoSlice 字幕工作台、自动切片与 AutoCover 之间的成果衔接、相关任务体验。
>
> 公开仓库、Fable 5 讨论的 wheel/CI/架构重构，以及其他发布工程不属于本计划的实现范围，
> 架构、wheel、CI 和发布后续工作不属于本文，由其他专项计划单独管理。
>
> 估算口径：以下均为有效开发时间，不含等待 CI、用户验收和外部服务排队时间；
> 每个 Action 独立验证、独立提交，不能批量混做。高频字幕可用版本预计约 3.5～6.5 个
> 有效工作日；本计划全部功能预计约 13～23 个有效工作日，实际以每个 Action 的验证结果为准。

## 1. 本计划的边界与执行原则

### 1.1 功能优先级

按实际使用频率和出错代价排序：

```text
字幕工作台高频操作
→ 字幕识别与断句质量
→ AutoCover 成果衔接与制作效率
→ 智能分析任务体验和质量概览
→ 桌面端上下文与视觉收口
→ Fable 5 / wheel / 架构后续工作（另案）
```

字幕校对是每个最终成片都会经过的环节，优先级高于只在分析异常或偶发场景使用的功能。

### 1.2 现有能力先接线，不重复开发

每个 Action 开始前必须先确认现有真实实现 owner、API 和数据格式：

- glossary、主播错词映射、字幕合并、删除、时间调整、参考标题、草稿恢复、clip mark
  等已有能力不得另起第二套生产实现；
- 根目录兼容 façade 只保留 alias 或轻量转发，不新增业务逻辑；
- 新增字段必须可选，旧 JSON、旧检查点、旧整理包和旧任务继续可读取；
- AutoCover 读取稳定成果契约，不反向 import AutoSlice 内部业务模块；
- 发现已有实现不完整时，先补测试和契约，再决定是接线、修复还是拆分。

### 1.3 自动化与人工确认边界

- 能稳定复用的步骤尽量自动完成，减少人工重复点击；
- AI 建议、批量替换、批量删除、写入主播词典和大范围时间调整必须先展示预览；
- 批量操作必须支持撤销或恢复；
- 用户手工修改、保护项和显式保存结果不能被 AI 或刷新流程覆盖；
- 无法可靠匹配时必须回退人工选择，不猜测、不静默关联；
- 不自动投稿、发布或跨平台分发。

### 1.4 普通验证的安全边界

普通单元、集成、前端行为和打包测试不得：

- 调用真实付费 LLM；
- 下载或运行 FunASR 模型；
- 使用 CUDA/GPU；
- 对用户媒体运行 FFmpeg 编码；
- 启动 Flask 或 AutoCover 服务；
- 读取用户录播、字幕、字体、贴图、报告或本地 API 配置。

每个 Action 开始和结束都确认 `5002`、`5010` 没有遗留监听。真实媒体、GPU、FunASR、FFmpeg
和 LLM 只在另行授权的短样本或指定真实验收中使用。

## 2. 准备阶段：隔离与低风险清理

准备阶段不是 Fable 5 实施阶段，目的是让后续功能开发的 diff 和验证可归因。

### Action P0：确认未提交改动的隔离方式

当前可能存在的 wheel 修复改动必须与本计划的功能改动隔离。开始实现前只做边界确认，
不得借此自动推进 wheel、CI、PipelineServices 或架构重构。

可选方式按安全性排序：

1. 在独立 worktree 或临时分支处理功能，保留主工作区的 wheel diff；
2. 对 wheel 改动建立可回退的临时补丁/安全保存，再在干净工作区开发功能；
3. 先独立收口 wheel，但必须得到单独授权，不能把它算入本计划的功能 Action。

验收：功能提交不包含 wheel 文件；能够清楚区分功能前后的架构快照和测试差异；不改写历史。

### Action FE-PREP-1：清理字幕页重复定义

目标是清理真实遗留实现，不按固定行号删除。

步骤：

1. 枚举 `subtitle_workflow.html` 当前 `<script>` 的顶层函数定义；
2. 按函数名和调用关系识别重复定义；
3. 对比旧版和后版能力，确认后版是否包含合并、删除、时间调整和状态恢复；
4. 只删除已被后版完整覆盖的旧定义；
5. 保持 API、DOM id、状态字段和用户行为不变；
6. 运行 JavaScript 语法检查、字幕状态恢复和相关集成测试。

当前已核实的重复函数包括 `selectPair`、`visibleCue`、`renderCues`、`deleteCue`、
`corrections`、`saveCorrections`。实际修改前仍需重新按当前代码核对。

验收：重复定义数量归零或有明确兼容理由；不新增第二套 owner；行为测试通过。

预计：0.25～0.75 个有效工作日。

### Action FE-PREP-2：字幕工作台脚本外置（强烈建议）

将模板中的内联 JavaScript 搬到：

```text
src/autoslice/resources/static/subtitle_workflow.js
```

本 Action 只做搬迁和加载方式调整，不改业务逻辑。必须验证：

- Flask 静态资源 URL、缓存和加载顺序正确；
- 页面 DOM 就绪后行为不变；
- Node 语法检查通过；
- 现有字幕工作台测试通过；
- 行为测试使用 DOM、`fetch`、`localStorage` 等必要 stub 或项目已有机制，
  不把“文件能加载”当成行为覆盖。

如果外置引发明显范围扩大，可以先完成 FE-PREP-1 和针对当前内联脚本的行为测试，
但最迟必须在 PRE-S4 前完成。这里的 `FE-PREP-2` 是维护准备，不是新业务功能。

预计：0.5～1 个有效工作日，若现有测试依赖 HTML 脚本切片，额外增加 0.5～1 天。

## 3. Phase 1：字幕工作台高频体验

目标：让“人工精剪后的无字幕短片 → 自动识别 → 字幕校对 → 显式保存 → 压制”
成为稳定、少重复操作、可回退的主链路。

### Action FE-S0：复核并完善现有无字幕短片自动识别

现有代码已经具备缺 SRT 扫描、`needs_transcription`、转录入口和任务完成后刷新等基础能力，
本 Action 不从零重写，只做体验和回归收口：

- 队列发现缺少 SRT 的视频并显示识别入口；
- 复用现有字幕识别任务、检查点和背景音过滤配置；
- 识别完成后自动刷新并加载 SRT；
- 刷新、断线重连和任务恢复后仍能显示正确状态；
- 明确显示实际 FunASR 模型、设备、过滤模式、CAM++ 可用性和回退方式；
- 识别失败保留可重试状态，不覆盖已有字幕；
- 不在自动切片阶段裁剪整场字幕，也不为字幕重复分析整场录播。

预计：0.25～0.75 个有效工作日。

### Action FE-S1：AI 建议批量采纳/忽略

- 当前筛选结果全部采纳或全部忽略；
- 相同 `original → corrected` 建议合并展示；
- 显示命中条数、置信度和上下文；
- 只作用于当前筛选视图；
- 用户手工修改和保护项不能被覆盖；
- 批量操作支持撤销；
- 高风险单字替换默认要求确认。

预计：0.5～1 个有效工作日。

### Action FE-S2：额外词条和主播错词映射

- 增加本视频额外词条输入；
- 实际请求体同时包含默认专名词表、用户附加词条和主播错词映射；
- 显示实际主播、默认专名数、额外词条数和固定纠错数；
- 额外词条只追加，不覆盖默认词表；
- 反复出现的错误词可在展示命中上下文后加入主播词库；
- 写入 `asr_replacements` 前必须确认影响范围；
- 词典变化使相关 ASR/校对检查点正确失效；
- 这只是可见、可编辑、可回退的词典配置，不做反馈训练数据库。

预计：0.5～1 个有效工作日。

### Action FE-S3：预览不落正式校对字幕

- 预览只使用当前内存 cues 或临时字幕；
- 不更新正式校对 SRT，不改变 `protectedEdits`；
- 显式保存才落盘；
- 压制前要求使用已保存字幕；
- 临时文件和预览 URL 正确清理；
- 刷新后恢复最后一次显式保存状态；
- 预览失败不能损坏已有正式字幕。

预计：0.5～1.5 个有效工作日；若需要后端临时字幕输入接口，另加 0.5～1.5 天。

### Action FE-S4：合并、删除和时间调整统一交互

- 单击字幕后才显示低频操作；未选中时不占用界面空间；
- hover 或选中态显示向上合并、向下合并、删除和时间调整；
- 控件分组并留出间距，不再拥挤成一排；
- 多选删除前展示正文和时间范围；
- 删除支持恢复；
- 合并后的时间范围从首条开始到末条结束，并能重新打开继续编辑；
- 增加起始/结束时间调整、整段前移/后移 N 秒；
- 禁止负时间、负时长和非法范围；
- 合并、删除和时间调整不会覆盖其他字幕的人工修改。

预计：0.5～1.5 个有效工作日。

### Action FE-S5：字幕质检列表

只展示候选，不自动删除。检查：

- 疑似背景音乱码；
- 完全重复；
- 纯符号或异常短句；
- 低置信度且语义异常；
- 删除后造成的大段空白；
- 相邻 cue 间异常 gap；
- 超长文本和屏幕溢出风险；
- 分段后残留单字、连接词错位或前条尾字漂移。

每条质检结果需要给出原因、定位字幕、建议动作和撤销/忽略入口。

预计：0.5～1 个有效工作日。

本阶段字幕工作台预计：**3～6 个有效工作日**（含 FE-S0～FE-S5，不含 FE-PREP-1/FE-PREP-2）。

## 4. Phase 2：字幕识别与断句质量

### Action ASR-A1：背景音三模式

提供关闭、软过滤、严格过滤三种模式：

- 关闭：保留原始识别行为；
- 软过滤：尽量压低背景音和非主要说话人，但保留可恢复结果；
- 严格过滤：仅用于确认是单人直播的场景，明确提示可能吞掉人声。

字幕工作台默认启用可关闭的背景音排除模式；智能分析整场录播默认不静默丢弃非主要说话人。
优先使用 CAM++，缺失时回退基础降噪/门限，并显示实际模式、说话人数量、删除段数、
删除秒数、模型/设备和回退原因。不得宣称单一混合音轨可以 100% 分离等音量的同时人声。

预计：1～2 个有效工作日。

### Action ASR-A2：断句实测和修复

使用代表性短片记录 gap、标点、停顿触发来源、词中截断、尾字漂移和超长 cue，
再逐步调整停顿、标点、逗号和字数规则。硬性单行长度上限必须保留：即使词字时间戳
无法完美对齐，也要拆成连续可读字幕；ASS 压制前还要结合画布、字号、描边和安全边距
再次检查，不能依赖自动换行。

自动分段应避免“前一段最后一个字跑到后一段前面再空一格”的形式；同时保护“所以、但是、然后”等
可以自然开句的连接词。AI 排版建议默认只预览，不自动覆盖用户确认结果。

预计：1～2 个有效工作日。

## 5. Phase 3：AutoCover 衔接与制作效率

### Action COVER-C0：稳定匹配标题、爆点锚点和最终短片

扩展现有整理包或 JSON，不在输出目录新增大量用户可读 Markdown。可选字段包括：

- clip 起止和时间基准；
- `slice_anchor`、`slice_anchor_source`；
- `cover_anchor_seconds`；
- 投稿价值分和理由；
- 投稿标题；
- 原始切片、最终精剪路径和校对 SRT 路径。

`cover_anchor_seconds` 必须是最终短片内部时间，初始换算为：

```text
slice_anchor - clip_start_seconds
```

人工精剪、重命名、多段录播或元数据不足导致映射不可靠时必须拒绝自动关联并回退人工选择，
不得猜测。AutoCover 只读取稳定成果契约，不反向 import AutoSlice 内部业务模块。旧整理包和没有
可选字段的任务继续可用。

预计：0.5～1.5 个有效工作日。

### Action COVER-C1：爆点附近选帧

- 爆点附近加密采样，同时保留全片均匀抽帧；
- 优先使用无字幕精剪原片，字幕版仅作回退；
- 先按爆点相关性和画质排序，再在局部窗口内考虑字幕风险；
- 不使用 OpenCV 人脸识别，不做人物主体自动避让；
- 用户仍可通过底部时间轴手动选帧。

预计：1～1.5 个有效工作日。

### Action COVER-C2：AI 封面文案

使用最终短片校对 SRT、`editorial_interest_reason`、`publish_title` 和角色信息。
Luna 生成候选，Terra 检查原话准确性、爆点和点击欲，自动选择一组，前端保留其他候选快速切换。
主题使用黄字，爆点使用强调色，对话按角色使用不同颜色，前端显示 role 标签。
没有 SRT 时使用已有标题和理由兜底，不在 AutoCover 内重新启动耗时 ASR。

预计：1～2 个有效工作日。

### Action COVER-C3：封面规则 profile 化

把历史主播特例从 Python `if/else` 和硬编码替换表迁入 profile。默认产品文案保持通用，
不绑定单一主播；存在旧主播 profile 时保持兼容，缺 profile 时使用通用默认值。

预计：0.5～1 个有效工作日。

## 6. Phase 4：任务体验与分析质量

### Action TASK-T1：任务恢复、状态和取消

让 `topic_v2` 消费 SSE init 快照，区分 `queued`、`running`、`done`、`error`、
`cancelled`、`interrupted`；为 queued/running 提供取消；interrupted 显示中断原因和检查点续跑提示；
继续使用 SSE，不新增高频轮询。

预计：0.5～1 个有效工作日。

### Action TASK-T2：跨分块上下文补全

不让相邻块完全重叠并自由输出。保留核心输出区间，附加前后 60～90 秒只读上下文，
再对相邻候选做确定性合并，并继续使用去重和边界复核。

预计：1～2 个有效工作日。

### Action TASK-T3：结果质量概览

展示最终切片数量、时长分布、投稿价值分、弹幕峰值、锚点来源和边缘候选数量。
只用于排序和选择，不恢复每小时配额。

预计：0.5～1 个有效工作日。

## 7. Phase 5：桌面端衔接与观感收口

### Action UI-U1：当前任务上下文

三个页面保持独立，不重写成大型 SPA，也不优先做跨端口 iframe。使用紧凑上下文条显示当前视频、
主播、阶段、上一步产物、下一步操作、结果目录、字幕校对入口和 AutoCover 入口。

预计：1～2 个有效工作日。

### Action UI-U2：AutoCover 服务就绪提示

打开 AutoCover 前探测 5010；未启动时给出明确提示；端口被占用时显示实际错误；
保持 loopback 和 Host/Origin 安全边界。

预计：0.5 个有效工作日。

### Action UI-U3：桌面端截图审阅和交互收口

主要验证 1440×900 和 1920×1080：

- 预览区不无意义占满；
- “文案”和“样式”同区；
- 选中画布文字后右侧同步选中对应元素；
- 低频操作按选中状态出现；
- 生成预览不高频闪烁；
- 缩放时画布仍可拖动并保持轨迹；
- 拖动文字或贴图不会二次缩放背景；
- 刷新后草稿、选帧和最后成功预览恢复。

预计：1～2 个有效工作日。

## 8. 明确不做和暂不纳入

明确不做：

- 每小时固定切片数量或自动凑片；
- 自动投稿、自动发布和跨平台自动分发；
- 整场录播字幕压制；
- 重型本地多模态模型；
- OpenCV 人脸选帧和自动人物主体避让；
- 自动根据背景修改用户颜色；
- 未经确认自动删除字幕；
- 未经确认自动写入主播错词映射；
- 反馈训练数据库。

暂不纳入本计划：

- wheel 自动包发现和打包门禁；
- GitHub Actions 门禁调整；
- PipelineServices；
- pipeline 阶段 dataclass；
- 全项目严格类型检查；
- 兼容 shim 删除；
- 全仓库 EOL 重写；
- Fable 5 讨论中的后续架构重构建议。

这些内容继续由 `其他专项计划` 单独管理。

## 9. 推荐实施顺序

### 9.1 准备 Action

```text
P0：确认当前未提交 wheel 改动如何与功能开发隔离
FE-PREP-1：清理字幕页重复定义
FE-PREP-2：外置字幕工作台 JavaScript（强烈建议，最迟在 S4 前完成）
```
