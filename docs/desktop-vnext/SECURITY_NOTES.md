# Desktop vNext 安全与发布可靠性备注

> 作用：提炼 2026-10-04 安全审计中已经复核、对 Desktop vNext 有长期价值的结论。完整审计仍保留在工具/工作目录中；本文件不是完整渗透测试报告，也不替代发布前依赖和安装包审计。

## 1. 当前安全定位

Desktop vNext 是单机、单用户、本地信任边界内的 Windows 桌面应用。当前真实风险主要不是传统 Web 漏洞，而是：

- 用户素材、视频、字幕和文件名进入 FFmpeg / libass 等外部工具后的可靠性；
- 源视频、源 SRT、既有成片和封面不被误覆盖；
- 本地 token、配置和个人样式不被打进发布包或泄漏到日志；
- 后台任务、单实例 IPC 和异常媒体导致的可用性问题；
- 安装器、升级和用户数据目录的权限边界。

当前没有证据表明 Desktop vNext 存在可被外部远程触发的高危代码执行、SQL 注入、危险反序列化或认证绕过问题。

## 2. 已修复：ASS 路径单引号可靠性问题

2026-10-04 审计在旧实现中复现：当视频/字幕派生出的 ASS 文件名包含 `'`（例如 `Bob's episode`）时，libass 路径解析可能失败，导致字幕预览或压制硬失败。

这属于**出片可靠性问题，不是字幕交互语义问题**。

2026-10-07 发布整理时，代码已经改为：

- 预览和压制在临时工作目录中使用安全 ASCII ASS 文件名；输入视频和输出视频使用绝对路径，不受工作目录切换影响；
- 正式 ASS 保留原始项目文件名，临时副本在进程结束后清理；
- 增加包含英文单引号文件名的定向回归测试；
- 保留字幕时间轴、快捷键、AI 采纳/跳过和正式保存契约。

本次本机验证使用隔离模拟测试，未运行真实 FFmpeg 编码。真实 FFmpeg 路径与最终媒体结果仍需 CI 或单独的媒体验收确认。

## 3. Desktop 与 Web/LAN 的路径边界不同

Web/LAN 模式使用 `security_policy` 处理 Host、Origin、token 和允许根目录等策略。

Desktop Qt 链路不是统一经过 `security_policy`，而是依赖各 workflow 的局部不变量：

- 项目目录来自投稿根目录扫描；
- 字幕压制校验同目录、正式后缀和内容摘要；
- 封面导出写入明确项目目录并使用冲突递增；
- 源视频、源 SRT 和受保护路径有显式不可覆盖约束；
- 临时输出优先使用临时文件 + 原子发布。

因此未来如果新增“导出到任意目录”“批量处理任意路径”等能力，不能假设 Desktop 已存在一个集中式路径安全网关，必须为新 workflow 明确边界和回归测试。

## 4. 单实例 IPC 的定位

当前单实例 IPC 主要用于防误开多个桌面实例，不是安全边界。

已知理论风险：同机、同用户环境中的其他进程可能干扰本地 socket / named pipe，造成窗口骚扰、多开或草稿竞争。

当前处理：

- 记录为低优先级本机可用性风险；
- 不作为当前发布阻塞项；
- 不为了“安全”引入与实际收益不匹配的复杂认证机制；
- 如果未来 IPC 承载文件路径、命令或业务数据，再重新升级威胁模型。

## 5. 凭据与本地配置

`.gitignore` 已覆盖 `api_config.json`、`autoslice.local.json`、`title_style_profile.json` 等本地文件，但 Git 忽略规则**不能替代打包排除规则**。

正式发布配置必须显式确认这些文件不会进入 PyInstaller staging 或安装包。

日志、错误弹窗和网络 header 继续遵守：

- token 不进入 repr / 日志；
- 错误信息不打印配置文件正文；
- UI 可以显示必要路径错误，但不泄漏凭据。

## 6. 安装与发布门槛

当前仓库只有发布方向，没有完成的 PyInstaller `.spec` 和 Inno Setup `.iss`，因此安装权限、升级、卸载和发布包内容尚未完成审计。

正式发布前至少完成：

- PyInstaller onedir 的真实 `.spec` 或等价可复现配置；
- Inno Setup 的真实 `.iss`；
- 默认不要求管理员权限，除非未来有明确必要性；
- 可写用户数据继续放 `%LOCALAPPDATA%\AutoSlice`，不写 Program Files；
- 显式排除本地 token、个人配置、个人样式和测试产物；
- 验证首次安装、升级、卸载、重装和快捷方式启动；
- 检查 PySide6、Pillow、libmpv、requests/httpx 等发布依赖的已知 CVE 和版本状态；
- 对最终打包产物重新做一次文件清单和凭据扫描。

## 7. 已接受 / 暂不处理的风险

以下问题目前不升级为代码整改任务：

- Desktop 不接 Web/LAN `security_policy`；
- 单实例 IPC 可预测性；
- 本地单用户模式没有额外登录认证；
- 异常原文进入 UI，只要不包含 token 或敏感配置正文。

## 8. 证据边界

2026-10-04 的完整安全审计包含真实 FFmpeg 定向复现和静态代码检查，但没有完成：

- 依赖 CVE 在线核对；
- 最终 PyInstaller / Inno Setup 产物审计；
- 大规模 fuzzing；
- 安装、升级、卸载全流程。

因此当前结论应表述为：

> **源码审计未发现外部可触发的高危安全阻塞；ASS 路径问题已有代码修复和回归用例，真实媒体验收、发布工程和依赖审计尚未完成。**
