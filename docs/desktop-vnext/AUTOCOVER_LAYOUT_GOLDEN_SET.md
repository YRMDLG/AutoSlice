# AutoCover 基础构图黄金测试集 v0.1

> 日期：2026-10-01
> 目的：把“基础封面自动摆放”从抽象原则变成可测试的画面类型与期望布局。
> 状态：人工规格，不要求逐像素复刻；用于验证默认构图是否稳定、快速、不过度模板化。
> 主画布：4:3。16:9 作为同步风险检查。

## 统一术语

- A：让 B 成立所需的最少上下文，视觉较弱；
- B：最值得占视觉注意力的信息，视觉最强；
- 主体：人物、双人、关键 UI、聊天记录、游戏目标、证据区域等不应被大面积遮挡的视觉对象；
- 安全区：4:3 主画布内可稳定显示且不会被平台裁切/控件影响的区域；
- 空区：纹理和关键信息相对少、适合放文字的区域。

基础系统的目标不是“设计得惊艳”，而是“第一秒给出一个不会犯明显错、并且还算顺眼的构图”。

## Case 01：单人主体在右侧

画面特征：
- 人物脸和上半身主要在右 35%；
- 左侧背景相对干净；
- A+B 都存在。

期望：
- 主关系：左侧文字 / 右侧留主体；
- A：左上或左中，小；
- B：左中或左下，大；
- 不应跨过脸部中心线。

失败示例：
- B 横跨画面中部盖住脸；
- A/B 都堆在人物身上；
- 右边明明很满还强行右字左人。

## Case 02：单人主体在左侧

画面特征：
- 人物主要在左 35%；
- 右侧有稳定空区；
- A+B 都存在。

期望：
- 主关系：右侧文字 / 左侧留主体；
- A 靠右上；
- B 靠右中或右下；
- 对齐方式可右对齐或居中于右侧文字区。

反重复：
如果最近连续多张都是“右字左人”，且上下区域也可用，可尝试上方/下方关系作为同分备选。

## Case 03：人物居中，表情是核心

画面特征：
- 人脸/上半身位于中部；
- 左右都没有足够完整的大空区；
- 表情本身有价值。

期望：
- 避免左右大字夹脸；
- 首选：上方文字 / 中下留主体，或下方文字 / 中上留主体；
- A 可缩成很小的一行；
- B 不应盖住眼睛、嘴和主要表情区域。

仅 B 时：
- B 优先放在人物头顶上方或胸口以下的安全区域，而不是直接压脸。

## Case 04：人物极近景 / 大头占满画面

画面特征：
- 脸占画面非常大；
- 四周只有窄边可用；
- 文字很容易遮挡表情。

期望：
- 默认减少文字面积；
- 有 A+B 时可主动舍弃 A，只保留 B；
- B 放上边或下边的窄安全带；
- 字号可以比普通封面小一档。

禁止：
- 为了“保持两块”把 A/B 压在人脸上。

## Case 05：双人左右分布

画面特征：
- 左右各有一名明显人物；
- 中间或上下存在一定空间；
- 文案有 A+B。

期望：
- 优先上方/下方文字，不遮两张脸；
- 若 A/B 是明确对话双方，可尝试 A 左 / B 右的分置关系；
- B 仍需更强，不做对称等权两个大字块。

风险：
- 双人画面默认不能把任意一个人当“背景杂物”直接盖掉。

## Case 06：双人靠在同一侧

画面特征：
- 两人都集中在右侧或左侧；
- 另一边比较空。

期望：
- 把两人视为一个复合主体；
- 文字整体放到另一侧；
- A/B 可形成上下层级；
- 不使用“对话分置两侧”，除非人物实际分离且可对应。

这是为了防止系统看到“双人”就机械选择左右对话布局。

## Case 07：游戏画面，中心目标重要

画面特征：
- 游戏 UI 较复杂；
- 中央 BOSS / 角色 / 目标是内容核心；
- 四周也可能有 HUD。

期望：
- 文字尽量使用上缘或下缘；
- 不盖中心目标；
- 不压关键血条、比分、提示词；
- 如果上下都复杂，宁可缩小文字、只保留 B。

基础系统不需要理解游戏规则，但要把“中心高显著区域”和长条 UI 视为应避让区域。

## Case 08：聊天记录 / SC / 评论 / 证据画面

画面特征：
- 画面本身的文字内容就是证据；
- 大面积区域都包含可读文本；
- A/B 只是辅助说明。

期望：
- 优先保留证据区；
- A/B 尽量放边缘或空白边；
- 必要时只保留 B；
- 不通过大面积压暗/模糊毁掉原证据。

与普通人物封面不同：这里“画面文字”本身就是主体。

## Case 09：外部视频 / 二创反应画面

画面特征：
- 一边是主播反应，一边是外部视频内容；
- 两部分都可能重要。

期望：
- 先判断哪一部分是当前标题的证据；
- 文案放在第三个相对空区，或使用上下关系；
- 不默认覆盖外部视频核心内容；
- 若没有安全区，可只放 B 且缩小。

这类画面不能机械按“人脸在哪边，字就放另一边”，因为另一边也可能是关键内容。

## Case 10：画面整体非常杂乱

画面特征：
- 到处是 UI、弹幕、背景纹理；
- 没有明显空区。

期望：
- 不强行找“完美空区”；
- 只保留 B 或弱化 A；
- 使用简单半透明暗底 / 局部压暗（若该能力已实现）；
- 文字放安全区中相对最可读的位置；
- 优先可读性，不追求花哨。

失败示例：
- 为了避让而把文字缩到几乎不可读；
- 让 A/B 分散到两个更乱的位置。

## Case 11：大面积暗背景

画面特征：
- 某一侧或上下有大块暗色区域；
- 主体清楚；
- 文字对比很好做。

期望：
- 优先利用天然暗区；
- 不额外压暗整张图；
- 允许 B 做得更大；
- A 可以靠近 B 形成紧凑层级。

反重复：
如果左/右都同样干净，近期布局历史决定使用哪边。

## Case 12：大面积亮背景

画面特征：
- 背景非常亮或高曝光；
- 白字容易吃掉。

期望：
- 位置仍由主体/空区决定；
- 样式系统选择更强描边/深色字或局部暗底；
- 不能为了文字可读性随意把画面整体压得过暗。

这是“样式适配”而不是“布局模板”问题。

## Case 13：只有 B，短而强

文案：
- A 为空；
- B 很短，例如 4~8 个汉字。

画面特征：
- 有明显安全空区。

期望：
- B 可以明显放大；
- 优先居中于最佳空区，而不是永远左上；
- 允许偏上 / 偏下；
- 近期历史用于避免连续同位置。

这是基础系统里变化感的重要来源之一。

## Case 14：A 很短，B 很长

文案：
- A 只有 2~5 个字；
- B 接近两行。

期望：
- A 做成小标签/小上下文；
- B 占主要文本面积；
- A 不需要和 B 同宽；
- 不把 A 拉大只为了“视觉平衡”。

示例关系：
A 小字贴近 B 上方，或在另一角作为很轻的信息。

## Case 15：A 很长，B 很短

文案：
- A 提供必要背景，但偏长；
- B 是非常短的爆点词。

期望：
- 先尝试进一步压缩 A；
- 若不能压缩，A 可拆两行但字号仍弱；
- B 可以放大形成强对比；
- 如果 A 占用过多空间，应考虑只保留 B 并等待用户手动补充。

禁止：
- 让 A 反过来成为整张封面最大元素。

## Case 16：A/B 是对话关系

文案：
- A = 对方说的话；
- B = 主播回应；
- 画面中有两个可对应主体，或左右空间明确。

期望：
- 可使用 A 左 / B 右；
- A/B 位置应与视觉主体方向一致；
- B 仍然更醒目；
- 如果人物并非左右分离，则回退到普通上下/同侧布局。

这是少数允许“双区文字”的基础关系。

## Case 17：画面没有明确人物主体

画面特征：
- 风景、房间、纯游戏环境、舞台远景等；
- 没有明确脸部/人物锚点。

期望：
- 以空区/复杂度为主要依据；
- 可以使用更自由的左/右/上/下关系；
- 近期历史反重复权重可以提高；
- 不需要为了寻找“人物”而启用昂贵分析。

这类画面是基础系统最适合做轻量变化的地方。

## Case 18：中心本身有大字幕 / 烧录字

画面特征：
- 当前帧中已经存在明显视频字幕；
- 文字带位于中下或中部。

期望：
- 基础构图应避开烧录字幕带；
- 如果候选帧系统有邻域更干净帧，可在帧条上标推荐；
- 不自动替换用户当前帧；
- 若用户坚持该帧，则文字优先放上方或两侧。

这是旧版 subtitle_risk 能力的合理复用途径。

## Case 19：4:3 正常，但 16:9 风险

画面特征：
- 4:3 主画布中 A/B 很合理；
- 同步到 16:9 后位置显得太靠中心、太散或主体关系变差。

期望：
- 4:3 仍保持主设计；
- 16:9 小预览给出风险提示；
- 不自动改变 4:3；
- 用户点 16:9 后可做比例专属位置微调。

基础目标不是让两个比例完全一样，而是让主比例先好看，第二比例不出大问题。

## Case 20：16:9 正常，但 4:3 会裁掉关键信息

画面特征：
- 原视频是 16:9；
- 关键人物或证据位于左右边缘；
- 4:3 裁切后风险明显。

期望：
- 因为 4:3 是主画布，默认背景焦点优先保住 4:3 关键主体；
- 16:9 可以自然多显示左右内容；
- 文字位置围绕 4:3 主体重新选择；
- 不允许为了 16:9 完整而牺牲 4:3 主画面。

## Case 21：最近三张连续同构图

历史：
- 最近 3~5 张都使用“左字右人”。

当前画面：
- 左侧和下方都属于可接受空区。

期望：
- 不在质量明显下降的情况下，优先尝试“下方文字 / 中上留主体”；
- 如果下方明显更差，仍可继续左字右人；
- 反重复是 tie-breaker，不是硬性禁用。

这条非常重要：不能为了“不同”生成更差的基础封面。

## Case 22：最近配色重复，但布局合适

历史：
- 连续多张都是黄字黑描边；
- 当前画面仍然最适合左字右人。

期望：
- 基础布局不必为了颜色重复而乱换位置；
- 视觉样式系统可在用户允许的个人色板中轻量变化；
- 若用户历史偏好高度集中，也可以继续黄字，不为了变化强行换成陌生颜色。

“反重复”不等于随机化。

## Case 23：画面本身已经很像封面

画面特征：
- 主体位置漂亮；
- 背景干净；
- 画面有天然构图；
- B 很短。

期望：
- 少做就是多做；
- 只放一个小而有力的 B；
- 不自动加 A；
- 不为了“系统存在感”添加额外贴纸、暗层或复杂排版。

这是基础系统需要学会“别动太多”的案例。

## Case 24：歌回 / 舞台 / 录播氛围型内容

画面特征：
- 舞台、唱歌、灯光或较完整场景；
- 情绪和氛围比“爆点”更重要。

期望：
- 文字数量少；
- 允许 A+B 都较克制，甚至只显示系列/曲名信息；
- 不强制大黄字和夸张爆点；
- 布局优先保留完整舞台和人物。

用于防止系统把所有内容都做成同一种“冲突切片封面”。

## Case 25：素材 / 贴图已经占据一侧

画面特征：
- 用户手动加入人物 PNG、表情包或截图；
- 新素材占据明显区域。

期望：
- 用户手动素材拥有高优先级；
- 自动文字重新选择剩余安全区；
- 后台重新分析不得把用户素材移动走；
- 若用户已经手动拖过文字，则后续后台不得自动重排文字。

这条对应“用户一旦接管，自动系统退场”的原则。

# 基础布局决策流程 v0.1

建议基础流程：

1. 确定 4:3 背景裁切与当前主体/证据保护区；
2. 从画面生成 4 个基础候选区域：左、右、上、下；
3. 计算每个区域：
   - 纹理/边缘复杂度；
   - 平均亮度与局部对比；
   - 与显著主体重叠；
   - 与烧录字幕带重叠；
   - 可用面积；
   - 16:9 同步风险；
4. 根据文案形态过滤：
   - A+B：需要足够空间容纳层级；
   - 单 B：允许更灵活居中；
   - 对话：只有满足双主体条件才启用左右分置；
5. 得到 1~3 个“都能用”的布局；
6. 使用近期构图历史做 tie-break；
7. 立即显示最优；
8. 后台更高级分析只能给建议，不能擅自重排已编辑内容。

# 验收标准

基础构图不是追求每次“最好看”，而是先满足：
- 不挡脸；
- 不盖关键证据；
- 不和烧录字幕打架；
- 文字在缩略图下仍可读；
- 4:3 主画布优先；
- 16:9 不出现明显事故；
- 不为了反重复选择显著更差方案；
- 不需要等 AI；
- 项目切换不会被分析阻塞。

若这些都满足，再讨论更高级的美学排序和 AI 方案。
