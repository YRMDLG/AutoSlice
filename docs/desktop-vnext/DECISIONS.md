# Desktop vNext 冻结决策清单

> 本文件用简明 ADR-like 条目记录已经冻结的方向。新决策应追加条目或明确取代旧条目，不在多个阶段计划中重复写一套“当前结论”。

## D-001：产品定位是直播切片员的 AI 辅助速切工作台

- 状态：生效
- 决策：AutoSlice 帮助完成字幕校对、封面包装、压制和投稿前检查，核心价值是减少重复操作和等待。
- 边界：不做剪辑器、复杂特效工具、花式字幕、运营平台、自动投稿或 Photoshop 替代品。
- 原因：真实工作流是“剪映完成视频 → 字幕校对 → AutoCover → 压制 → 投稿”，产品需要补齐包装环节而不是吞掉剪辑环节。

## D-002：主导航固定为字幕 / 封面 / 设置

- 状态：生效
- 决策：桌面端一级导航只保留字幕、封面、设置；项目和任务状态是共享上下文，不另做常驻 Dashboard。
- 原因：用户按工作流切换页面，当前动作优先于后台参数和任务列表。

## D-003：字幕交互语义冻结

- 状态：生效
- 决策：保留现有字幕播放、列表、时间轴、编辑框、快捷键、AI 建议、草稿、正式保存和后台压制语义。
- 约束：选中、播放、hover 和 playhead 分离；字幕块移动优先于空白 seek；AI 只提供采纳/跳过；原始 SRT 不被草稿覆盖。
- 原因：字幕是高频工作台，交互语义已经经过多轮实机纠偏，封面和架构重构不得顺手改变它。

## D-004：`DesktopWindow` 只做壳和编排

- 状态：生效
- 决策：窗口负责生命周期、导航、项目选择、页面装配和简短状态；领域状态放在页面模型、service、`WorkspaceContext` 或任务对象中。
- 原因：避免窗口膨胀成第二个业务状态机，保证字幕、封面和异步任务可以独立演进。

## D-005：AutoCover 与字幕、播放器隔离

- 状态：生效
- 决策：AutoCover 只接受项目/视频上下文和 playhead 快照，不读取 `DesktopWindow`、播放器内部对象或字幕文档内部状态，也不反向 seek 播放器。
- 原因：封面只需要原始帧和语义上下文；反向依赖会让切页、重启和任务取消互相串线。

## D-006：`CoverDocument` 是封面唯一主模型

- 状态：生效
- 决策：A/B、背景、图片、贴图、形状、双比例 profile、对象层级和可恢复状态都以 `CoverDocument` 持久化；对象使用稳定 id 和归一化坐标。
- 兼容：`CoverDraft` 只保留 v1～v3 草稿读取、迁移和旧调用方兼容，不创建第二套新业务状态。
- 原因：字符串标题、背景数值和页面控件字段无法可靠表达独立对象、双比例覆盖和撤销历史。

## D-007：4:3 与 16:9 共享对象身份、独立布局覆盖

- 状态：生效
- 决策：两个比例共享同一套对象和文案，但位置、尺寸、背景缩放/平移、取景和必要的可见状态可以分别保存和导出。
- 原因：同一封面内容需要适配不同投稿位置，强行按像素缩放会破坏主体和文字安全区。

## D-008：基础文案确定性，AI 默认不运行

- 状态：生效
- 决策：基础模式只提取、清洗和压缩已有标题/字幕事实，失败时回退短原文；A 是最小上下文，B 是主视觉信息。AI 只有用户主动触发才运行。
- 约束：不补造事实、不把字幕预览直接绘制到封面、不以空泛悬念替代真实爆点。
- 原因：封面必须在没有模型、额度或网络的情况下完整可用，并且能解释每个字的来源。

## D-009：AI 输出必须是可编辑候选

- 状态：生效
- 决策：AI 或 mock 只返回结构化文案/布局候选，落地为可编辑 `CoverDocument`；不可编辑 PNG 不是工作结果。
- 当前状态：本地 mock 三候选已接入，真实 relay、质量和额度提示后置。

## D-010：项目扫描按需、源目录为事实来源

- 状态：生效
- 决策：字幕页和封面页共享项目扫描结果；项目文件夹、视频和 SRT 是事实来源，草稿/数据库只补充编辑和缓存状态。切换项目不默认扫描全片。
- 原因：用户可能没有 manifest、数据库记录或自动切片结果，封面仍应能打开；全片扫描会拖慢高频工作流。

## D-011：异步任务必须使用 generation/token

- 状态：生效
- 决策：取帧、附近帧、预览、AI、波形和压制结果带项目/视频/文档代际；迟到回调不匹配时丢弃，不能覆盖新上下文。
- 原因：切项目和切页是常规动作，靠控件生命周期或“最后回调获胜”会产生隐蔽串线。

## D-012：拖动采用暂态更新，释放后提交

- 状态：生效
- 决策：文字、背景、图片、贴图和形状拖动期间只更新轻量暂态；释放或明确提交后写入文档、Undo/Redo、草稿和预览队列。
- 原因：保证拖动实时反馈、避免每个鼠标事件污染历史，也避免后台任务在半成品状态上反复排队。

## D-013：素材能力保持轻量，不建设完整图层软件

- 状态：生效
- 决策：图片/贴图支持导入、移动、缩放、旋转、复制、删除、隐藏、锁定和基础层级；形状只覆盖圆圈、箭头和矩形。
- 暂缓：复杂蒙版、钢笔、路径、滤镜、动画、模板市场和在线素材平台。

## D-014：自动保存可恢复草稿，正式输出分层

- 状态：生效
- 决策：编辑自动保存项目/视频独立草稿、选帧、锁帧、预览和双比例状态；正式字幕和封面输出仍走显式保存/导出契约，不覆盖源文件或已有成品。
- 原因：重启和切换项目后继续编辑比依赖浏览器存储可靠；自动保存不能改变用户正式结果。

## D-015：性能优先保护 UI 线程

- 状态：生效
- 决策：UI 线程不做整图渲染、取帧、波形、FFmpeg、模型调用或全片扫描；昂贵操作后台化、可取消、带缓存和可见错误。
- 原因：封面拖动、字幕编辑和切页必须保持直接反馈，性能问题不能靠增加参数解释掩盖。

## D-016：部署和 owner 保持单一来源

- 状态：生效
- 决策：`src/autoslice` 与 `src/autoslice_cover` 是生产 owner；`autocover_tool` 只保留旧入口和兼容边界。`启动.py` 继续管理既有服务入口，桌面壳和安装包另行验收。
- 约束：不在兼容模块加入新业务逻辑，不把历史打包实验直接当成发布承诺。

## D-017：视觉验收独立于自动化测试

- 状态：生效
- 决策：单测、集成测试和静态检查只证明代码契约的一部分；字体、默认构图、窗口空间、信息架构和真实连续生产必须由用户用真实项目验收。
- 原因：当前 AutoCover 已出现“功能齐但界面像调试后台”的反馈，自动化绿不能替代产品判断。

## D-019：画布与导出共用同一套几何与排版

- 状态：生效
- 决策：背景放置、素材尺寸、旋转中心与方向、图层顺序、文字字号与断行由 `cover_layout` 统一计算，Qt 画布在导出像素坐标系中按同一结果绘制，Pillow 导出也走同一入口。
- 原因：两端各算一套时出现过背景平移方向相反、旋转方向相反、对齐与贴图尺寸不一致；以像素对照测试守住这一约束。

## D-020：字幕快捷键只在字幕页生效

- 状态：生效
- 决策：窗口级的字幕快捷键（Delete、Space、Q/W、Ctrl+B、Ctrl+Z/Y 等）只在字幕页启用；封面页的撤销、重做和删除由封面编辑器处理。字幕页上的语义不变。
- 原因：此前在封面页按 Delete 会删除字幕行，撤销作用于字幕而非封面。

## D-021：封面文字框采用固定字号 + 行宽

- 状态：生效
- 决策：`TextObject.style.font_size` 是实际字号，`rect.width` / `wrap.max_width` 是行宽，文字按行宽重新换行，不再在区域内自动缩字；选中框贴合实际文字。旧文档按升级前实际显示的字号与行宽写回，`CoverDocument.text_revision` 标记已升级。
- 原因：区域内自动缩字时，用户拖大框，字可能因为行宽上限或行数上限不变大，“无法放大”；固定字号与剪映、Canva 等工具的心智一致。

## D-033：本地同音检查；打包脚本放在主力机上跑；全片候选帧点选不重排

- 状态：生效（打包脚本未构建验证）
- 决策：
  1. **同音检查**（`desktop/homophone.py` + AI 面板里的闪电按钮）：用 pypinyin 找“发音和术语表里的词一样、写法不同”的字幕片段（“紫雨亭”→“子语庭”），出成待确认建议，和 AI 建议走同一个队列和采纳/跳过/撤销；纯本地、不花额度、不需要配置 AI。两字词要求声调也一样，三字及以上只比拼音；术语来自固定词、主播配置和你确认过的学到术语。AI 检查时顺带并入，AI 已经给过建议的那几条以 AI 为准。没装 pypinyin 整体关闭，面板里提示怎么装。
  2. **打包**：`packaging/` 放 PyInstaller spec、Inno Setup 脚本和 `build_windows.ps1`，**在你的主力机上运行**，脚本只复制已有的 libmpv / ffmpeg、不下载。安装版不带 torch，识别用设置里指定的另一个 Python，识别子进程需要的纯源码打包时放进 `worker_src`。
  3. **“全片/更多”挑出的候选帧点选不再重排**：以前点一张，取帧完成后帧条会按这一帧重新居中成附近帧，其它候选就没了，没法逐张大图对比。现在候选帧条里点一张只换大图并勾选对应缩略图，切页再回来也不变，点“当前帧”才回到附近帧。
- 原因：真实旧字幕里 4/7 处改动是同音或近音；打包要装 PyInstaller / Inno Setup，不该装在别人的电脑上；对比大图是选封面底图的核心动作。
- 证据与限制：同音检查在本机仅有的 2 份真实字幕（294 条）上用默认术语表 0 命中（没有误报，也没有真阳性——那里的错词不在术语表里），效果取决于你学到的术语表有多大；打包脚本只做了语法检查和源码模式下的 `--smoke`。

## D-032：字幕识别回到桌面端——多引擎接口、子进程运行、用你自己的校对稿选引擎

- 状态：生效（框架），默认引擎待你的主机上 `bench` 结果确认
- 决策：新增 `desktop/asr/`：统一引擎接口 + 注册表（Qwen3-ASR 1.7B 为默认，原 FunASR 留作对照基线）、按静音切块的流水线（检查点续跑、原子写出、不覆盖已有字幕）、热词、自检、对比工具；字幕页给没有字幕的视频一个“识别字幕”入口，设置页加“字幕识别”卡片。
  1. **识别在子进程里跑**：显存随进程结束释放、崩溃不带走界面、可指定另一个 Python 环境；取消就是结束进程，靠检查点续跑。
  2. **准确度用数据定，不用论文定**：`bench` 拿你自己校对过的旧字幕当标准答案，量字错率（等于你要手改的字数占比）、热词命中、速度、显存；有无热词各测一遍。
  3. **复用旧识别验证过的分段规划器**，换引擎不改一条 ≤16 字、停顿 0.65 秒切、不留标点的排版习惯；分段时按项目文件夹激活主播配置，你确认过的固定纠错因此自动生效。
  4. **只对没有字幕的视频识别，不覆盖**：已有字幕的校对状态按条序号记，覆盖会错位。
  5. 修了共享拆分函数里的老问题：超长字幕硬切会把英文词切开（`emoj | i`）。
- 原因：之前 2060 6GB 跑不动，识别留在了网页版；现在主机是 4060 8GB，桌面端要自己能产出字幕，网页版才能逐步退场。写代码的机器是别人的电脑，没法下模型和实测，所以验证全部做成用户在主机上运行的命令（`doctor --probe`、`bench`）。
- 风险：Qwen3 适配没碰过真模型（接口细节做了宽容解析并有测试）；`qwen-asr` 在 Windows 上能否直接安装未验证；没有说话人过滤。详见 [ASR.md](ASR.md)。

## D-031：学习旧切片——只读扫描本机档案，按文件夹存事实，学到的要确认才生效

- 状态：生效
- 决策：新增 `archive/`（扫描器、SQLite 证据库、可插拔抽取器、报告、建议、运行时知识）和设置页“学习旧切片”面板、命令行。
  1. **只读、本机、可清除**：不改不写档案，产物只在应用数据目录；`digest.json` 是可整份交给 GPT 的小摘要（有体积上限，无视频、无完整路径）；一键清除。
  2. **按文件夹存事实**：库里每个文件夹一行、事实挂在各自的表里，文件夹变了只重抽它；汇总全靠 SQL 现算，不维护会算错的“增量汇总表”。指纹 + 抽取版本都没变就整个跳过（4000 个文件夹复扫 0.8 秒），可取消可续跑。
  3. **学到的只是建议，用户确认才生效**：固定纠错（写本机覆盖词库）、术语、标题范例、字幕阈值；固定纠错要求精度 ≥0.8（改过次数 /（改过 + 别处原样保留）），否则“意思→ins”这类多数时候是对的词会被改坏。
  4. **检索式取用，不整份塞给大模型**：术语表另存（不受 200 条上限约束），AI 字幕检查只带和当前字幕有关的几十个；投稿文案挑最像的旧标题；字幕质量提醒学过才按个人习惯定阈值，没学过行为不变。
  5. **接口留给后续接手**：抽取器是可插拔的（表、列、版本号），数据布局假设和待办写在 [ARCHIVE_LEARNING.md](ARCHIVE_LEARNING.md)，用户把 digest 交给 GPT 即可继续优化。
- 原因：用户保留了从刚开始做切片到现在的全部数据，量特别大且只在本机，无法直接交给 AI；需要一套既能在本机跑完、又能让后续优化不碰原始数据的框架。真实数据（147 条字幕，7 处改动）也证明通用阈值太松、固定纠错必须看精度。
- 同时：字幕质量提醒新增“边界重复”（上一条末尾的字和下一条开头重复，识别断句漏出来的字；真实数据命中 1/1、误报 0）。

## D-030：把“碳黑·钴蓝”视觉体系带进封面与设置；工具栏放不下时收成图标

- 状态：生效
- 决策：之前几轮界面工作（视觉质感、重绘图标与源流黑体、全局动效、弹层动效）在 `desktop-ui-opus55v2` 上，现合并进封面分支；封面分支已把 `window.py` 拆成 `window_*.py` 一组模块，所以对旧 `window.py` 的界面改动按函数逐块移植到新位置。封面编辑器与设置页按同一套语言重做：
  1. 封面工具栏按钮统一用“工具按钮”外观和同一套图标；画布比例、文字对齐改成和字幕页筛选一样的分段控件；窄窗口下低频按钮（同步、批量出图、投稿文案、下一个）先收成只显示图标，还放不下再收文字/素材/形状/AI 改一改，“导出 4:3 + 16:9”主按钮文字永远完整；输出摘要挪到画布下方提示行右侧，放不下时右侧省略（`ToolbarButton` / `FitToolbar` / `ElidedLabel`，按钮 `text()` 不变）。
  2. 右侧面板的动作按钮（强调所选、垫爆炸贴、换一版文案、复制/删除/前后移/隐藏/锁定、导入、抠出人物、取帧等）都带图标；数字框、多行文案框补上深色样式；选中的帧缩略图画 2px 强调边框，时间戳叠在缩略图上，窄窗口也读得全。
  3. 设置页改成限宽（880）卡片：每块一张卡片，AI 接口表单标签对齐、输入框与下拉撑满、“保存”为主按钮；空的纠错词库不再留一个孤零零的按钮；下拉框全部换成带动效的弹层。
  4. 菜单（形状/素材/模板/已隐藏、帧缩略图右键、颜色按钮）都接入 `MenuFx`，按钮 `setMenu` 弹出时由 Show 事件让出投影留白；动态创建的对话框创建后补挂动效。
- 原因：之前几轮界面工作只覆盖了字幕页；封面分支后来加了十几个控件（AI 方案、强调、爆炸贴、模板、抠图、虚化压暗等），沿用旧样式显得杂乱；在 1366×768 这样的笔记本分辨率上工具栏被截断（主按钮只剩“导出 4:3 + 16”），设置页在宽屏上输入框被拉成一条线、“保存”按钮底部被裁。
- 验证：自动排查脚本在 1280×720、1366×768、1600×900、1920×1080 四个尺寸下遍历字幕页（含 AI 面板展开）、封面页（选中文字/底图/形状）、设置页和三个对话框，检查被截断的文字、被压扁的输入框、超出父控件的控件和未接入动效的控件、仍是原生样式的下拉框与菜单，最终全部为 0 处。
- 注意：Qt 样式表的 `min-height` 会在控件上生效，盖过 `setFixedHeight`（按钮会被撑到 32px、“保存”被裁）；按钮高度统一交给样式表。heredoc、补丁脚本里写 `\n` 要小心被当成真换行。

## D-029：精修效果做成可编辑对象；日更版式用模板

- 状态：生效
- 决策：参考切片封面里最常见的几种精修（D-028 的调研），不引入需要下载的模型或素材：
  1. 形状加“爆炸贴”（长短交错的尖角）和“集中线”（四周往中心收的效果线，中间留空给人物）。顶点由 `document_layout` 统一算，画布和导出画同一套；集中线中间空地点下去仍是点底图，只有点到线圈才选中它。
  2. “垫爆炸贴”：在选中文字的强调词（没有就整段字）后面放一个比字大一圈的爆炸贴，两个比例各自对准自己的字，跟着字的角度转；放在所有字下面；“AI 改一改”也能用。强调词换行时尽量不拆到两行，爆炸贴才盖得住整个词。
  3. 两帧拼图（反应 + 证据）：帧条缩略图右键“作为小图拼进封面”，那一帧作为带白边、稍微歪一点的小图放在右上；图片对象加边框（颜色、宽度，画在图片边缘以内），右侧面板可调。底图不变。
  4. 模板：把排好的封面存为模板（A/B 的字体配色、两个比例里的位置，贴纸、形状、导入的图片和固定的字），换个视频一键套用；文案和强调词不动，从视频截的拼图小图和底图不进模板，爆炸贴套用时按新文案重新垫；再套或换模板会先拿掉上一次加的东西。批量出图可选一个模板给新封面套上（已有草稿的不动）。模板只存本机。
  5. 人物抠图：底图面板“抠出人物”把主播抠出来，作为一个能单独拖动、缩放的人物图层放进封面（刚放进去时两个比例都正好对准底图里那个人，看起来没动），底图自动虚化。参考日更切片号折跃O_o（泽音切片）的抠图封面，两种用法：①人物清楚、背景糊掉、字放在一侧；②把底图放大拖到她在看的东西（截图、聊天、游戏画面）上当背景，人物缩小放到角落。参考封面都不加白边，所以白边默认关、在人物图层上勾“人物白边”才加（同一次抠图存了带边、不带边两张，切换就是换图）。人物被画面下沿切开时默认“贴住底边”：缩小、挪动时下沿只能压到封面底边以下、不会悬空露出切口（缩放以左上角为锚，不夹住的话一缩小切口就露出来）。底图面板的“虚化”“压暗”是底图的通用效果，不抠人也能用；虚化在原图上按原图像素算半径，画布和导出共用同一张模糊图。抠人物时同时生成一张“人已抹掉”的背景图（与底图同尺寸：人物范围连同往外约 3.5% 画面高度，在 640 长边的小图上用多尺度推拉填补，再放大羽化贴回），背景的虚化、压暗基于它：此前整张图连人一起虚化，人物周围会有一圈自己的粉色光晕，垂下来的发梢在背景里留一个模糊的鬼影（用户在真实封面上指出“抠图效果还有提升空间”），内容当背景、人物挪到角落时原位置的头发也会残留。背景对象记下这张图（`clean` / `clean_for`），换了底图、对应的人物图层被删或隐藏时自动回到原底图；模板不带它。人物图层和截帧小图一样不进模板。两条路：数据目录 models/birefnet_lite.onnx 存在时用 BiRefNet 模型（onnxruntime，发丝级边缘）；没有模型时用本机 OpenCV 的 GrabCut，只在人物区域里按接近原分辨率抠、补洞，再用彩色导向滤波把边缘贴到发丝上（第一版在半分辨率整张图上抠，头发外层常被切掉，用户反馈不够精细）。两条路都以看图标出的人物框、脸框为准、直播界面为背景，只留和脸连着的那一块；模型由用户同意后下载（2026-10-14 从 ModelScope 的 onnx-community/BiRefNet_lite-ONNX 下载 onnx/model.onnx，224 MB，MIT），程序本身不联网；CPU 推理关掉内存池、线程不开满，笔记本上每张 11～14 秒（开满反而越跑越慢）；没装 OpenCV 时按钮提示不可用。抠图结果按人物所在的框裁成小图（外加一圈留给白边），另记一个 JSON 写人物框和原图尺寸，用来对准位置。第一版把抠图做成底图的属性、跟着底图走，人物不能单独挪，也就做不出“内容当背景 + 人物在角落”，于是改成独立图层。
  6. 投稿文案：封面页“投稿文案”让 AI 按这位切片员以前的标题口吻写 3 个备选标题、简介和标签，弹窗里改完一键复制；只写字幕里有的事。
- 原因：日更切片号的封面版式基本固定、常用这几种精修；之前只能手动拼图层，做一张精修封面要很久，也没法让每期版式一致。抠图先用不需要下载的 GrabCut，效果不够再考虑专门的抠图模型（需要用户同意下载）。

## D-028：封面按日更切片号的做法来：原话 + 关键词强调、表情帧、避开直播界面取景

- 状态：生效（修订 D-026 的文案标准与取景方式）
- 决策：参考泽音、永雏塔菲、东雪莲、阿梓等主播日更切片号和高播放切片的封面：投稿标题交代来龙去脉，封面放标题爆点浓缩成的一两句，或主播自带情绪的一句原话（4～12 字，一行），关键词单独换色；主播表情要有戏；常见精修是抠图外发光、爆炸贴、效果线。据此：
  1. 文字对象加“强调词”（`TextObject.emphasis`，两个比例共享）和强调色（`TextStyle.accent`，空为按填充和描边自动配对比色）。强调只换颜色，断行、字号、选中框不变；画布与导出共用 `document_layout.emphasize` 切出的片段，有强调时导出先整段描边再整段填色。
  2. AI 文案分两种：“标题浓缩”（每次 2～4 组，同一个爆点换说法、换语序、加反问）和“原话”（只在原话自带情绪时给 0～2 组），按好坏排序；封面字必须和标题是同一个爆点，不许拿只有看完视频才懂的细节当 B，挑选时这类一票否决。每组标 1～2 个强调词（文案里原样出现的片段，去掉标点后不能等于整句），标题提炼那句也让 AI 标。
  3. 没锁帧时，AI 在爆点前后取几帧挑表情最有戏的一张，候选都排在这一帧上，并对这一帧重新标框（飘过的弹幕、弹窗每帧都不一样）；套用方案时底图跟着换，可撤销；锁帧时绝不换。
  4. 看图模型不再给 4:3 取景框，只标脸、人物和画面自带的字/界面各在哪；本地按框搜裁切：整张脸留在画面里、最多剪到刘海、脸高不超过画面一半，字带（下方、上方、上下或左右一侧）避开界面和脸；宽松/特写两档，另有“人在一侧、字在另一侧”的构图。排完再量字压没压界面或脸，压到的不交给 AI 挑。前几张候选先用最好的几句文案配满各种构图。
  5. AI 候选和“AI 改一改”的移字用“引子在上”的叠放（A 小字在上、B 大字在下，按读的顺序）；原“标题在上”（B 大字在上、A 小字在下）保留给快速方案。
  6. “AI 改一改”：把封面现状（已强调的词、倾斜、外描边、配色、放大倍数）告诉 AI，让它给最多 3 个修改方案，每个方案组合 1～3 个一键操作（移字、拉近拉远、放大 B、缩小 A、强调关键词、字倾斜、加外描边、换配色、换文案）。每个方案先在本地算出改后的样子，弹窗里改前、改后缩略图对照；改完和现在一样的（包括本来就在那儿的移字）不显示；改完文字出画会整组收回画面内。
- 原因：上一版 AI 方案在直播界面密集的画面上几乎全被一票否决（模型给的 4:3 框把聊天栏框进去、字压在画面原有的字上），文案为了“只看封面能懂”写成概括句，没有强调手段，截图里的脸也常是面无表情。第一轮改完用户反馈：方案二、三的文案是视频细节（「粉丝投了第四首歌」），“AI 改一改”建议强调一个已经强调过的词、点了没效果——于是改为标题浓缩、组合方案带预览。抠图、爆炸贴等精修需要下载模型或素材，另行确认后再做。

## D-027：工具要有“成长性”：从日常操作里静默学习，看得见、能撤回

- 状态：生效
- 决策：不让用户专门训练或打分，只从自然操作里学：保存校对字幕时学常见识别错词（同一对改动在两个视频里都出现才写进本机覆盖词库）；每次导出记一条封面作品（构图、配色、文案、用了哪个方案、之后改了几步），快速方案据此避开最近用过的构图和配色，也给 AI 当口味范例。学到的东西在设置页“成长记录”里可见、可忽略；只存本机。主播专属的梗和事件词放在主播档案的 cover_rules.emphasis_terms，代码只留通用规则。

## D-026：封面重新接入 AI，但只做选择题

- 状态：生效（取代 D-023 中“去掉 AI 方案”的部分：当时去掉的是不调用模型的本地 mock）；文案标准与取景方式已由 D-028 修订
- 决策：AI 由用户点击触发、不阻塞手动编辑，不让 AI 给坐标。文字模型写“只看封面能懂”的 A/B（逐字出自标题和字幕，可补虚词），候选里固定包含标题提炼的那句；看图模型看原画面给人物取景框、特写框和字放哪侧更干净；本地按框取景（人物约占六成高度、其余留给字）排出十几张候选并渲染成编号总图，看图模型对照原画面挑“稳妥 / 换个构图 / 大胆一点”，压脸、压原有字、看不懂、字太小一票否决。“AI 改一改”只从工具能一键做到的操作里给建议（移字、拉近拉远、放大 B、缩小 A、换文案），点“应用”即改、可撤销；没问题就不提。模型接口在设置页配置（支持 OpenAI Responses、OpenAI 兼容、Anthropic），写入已有的 api_config.json；非本机 http 地址须显式允许。

## D-025：封面编辑时不再后台渲染预览图

- 状态：生效
- 决策：画布就是所见即所得的预览，编辑、拖动、撤销时不再在后台用 Pillow 渲染预览 JPG，只有导出才走 Pillow；画布与导出的一致性靠共用 `cover_layout` 几何和像素对照测试保证。底图只在路径变化（换帧、导入、撤销、换项目）时重新解码；导出按钮以“底图已加载”为准，导出直接开始，不再先等一次预览渲染。
- 原因：那张预览图渲染完后没有任何界面显示它，却在每次改动后占用一次后台渲染；导出前强制重渲预览也只是让用户多等一轮。

## D-024：封面不做裁切；锁定与视频更新的语义

- 状态：生效
- 决策：不提供图片/底图裁切（`crop` 字段只为兼容保留），取景靠缩放与平移。锁定是对象级状态：可点选和改外观，不能拖动、方向键移动或删除，快速方案与比例同步不改动它。视频文件变化时旧草稿不作为有效草稿自动套用，但封面沿用原文字、样式和素材，从新视频同一时刻重新取帧且不重新排版。
- 原因：裁切属于文档明确不做的复杂图层能力；锁定的价值就是“排好了别再动”；切片员常在修完字幕后重新导出视频，丢掉已调好的封面代价最高。
