# Desktop vNext 当前状态

> 状态日期：2026-11-25（界面改版一节）；其余各节沿用 2026-10-19 起的记录。本文记录当前工作区能确认的实现状态和已知问题，不把历史测试结果写成最终实机验收结论。

## 状态结论

Desktop vNext 已经从“基础壳和局部能力”进入“功能基本铺开、集中实机收口”的阶段。字幕模块的交互语义已经冻结；AutoCover Beta 的核心编辑模型、双比例画布、素材、选帧、保存和导出链路已经接通。下一阶段的重点是 Beta UI Cleanup 和统一实机验收，而不是继续把所有参数堆到主界面。

当前最重要的判断是：**功能基本齐全不等于产品已经验收完成。用户实际反馈优先于测试通过；不能用单测全绿代替视觉、字体、构图和连续生产验收。**

**第三轮：实际操作走查（D-045）**：用真实窗口启动桌面端（临时投稿目录、隔离数据目录、AI 接口置空），在程序内发送鼠标、键盘、输入法事件逐页操作，逐帧抓屏核对动效。发现并修掉：
- **“恢复字幕草稿”这类询问框看不见、窗口像卡死**：Qt 内部创建的对话框（`QMessageBox.question` 等）没有常驻 Python 包装，挂在它下面的对话框动效对象被回收，动画回调失效，对话框停在全透明，只剩变暗的遮罩。现在对话框动效对象由应用级监视器持有，另加兜底（动画时长过后仍透明就直接显示）。有回归测试（旧代码上失败）。
- **底部两张卡会变矮、两列不齐**：存会话时把当时的时间轴高度当成“用户拖过的高度”记下（切页时是 0、旧版布局的高度也照记），下次打开就用它。现在只记用户亲手拖过的高度，存在新键 `timeline_card_height`，旧版的 `timeline_height` 不再沿用；AI 检查卡有统计时说明不再占行（放进右上角状态的悬停提示），不会比左边时间轴高。
- **改字后不闪**：闪光只挂在委托的编辑路径上，实际用的行内编辑框提交时没触发；改到提交处。
- **重启后建议展开在没选中的行下**：建议只在选中的那一句下面展开，选中哪句就跟到哪句；Alt A / Alt S 遇到看不见的建议先跳过去展开，不直接改。
- **换主题后建议的绿底 / 红底还是旧主题的颜色**：换主题时重新生成。
- **封面页数字框套了两层框**（输入动效挂到了数字框内部的输入框上）；**画布底板里多出一个方框**（画布自带的底色和细边，换主题后还会被样式表刷回不透明）；**导出按钮中间一道缝**。
- 字幕表格悬停时弹“单击直接编辑……”提示，挡住下一行，去掉（底部提示行已写明）。
- 时间轴波形按整段高位电平做显示增益，录音小声时不再贴成一条线（采样数据不变）。
- 按设计稿补齐：字幕行编辑态（这一行加高，两行输入框 + “完成 / 取消 · 时间 · 字数” + 按键提示；序号换强调色）、右键菜单收短（顶层只留编辑、定位、拆分、与下一条合并、删除，裁剪贴合与试听收进子菜单）、项目下拉（两位序号、标题 + 状态两行、当前项打勾，底部“刷新项目列表”和排序）、设置页分区（标题和说明在框外、框里一行一项带细线、96px 标签列、服务商改分段按钮、路径等宽单行、投稿目录下显示扫描结果）、导航“设置”换滑杆图标。
- 截图脚本的示例音轨改成音量起伏，截图里的波形像说话。
- 回归中又发现一处：编辑态那一行加高后，编辑时点别的行，按下就收起这一行、下面的行上移，松手落到别的行（或被当成点时间码）。现在按下只提交文字，行高等松手后再复原，光标按点在那一行里的位置放。

## 字幕模块：语义冻结

字幕页的以下语义作为 Desktop vNext 的稳定契约：

- 项目按投稿根目录扫描；项目文件夹是项目事实来源，草稿和缓存只补充编辑状态。
- 播放器、字幕列表、轻量时间轴和 AI 建议区共享当前项目上下文，但各自的选中、播放和 hover 状态不混用。
- 单击字幕文字进入编辑；编辑框内的字符、空格、Delete 和换行由编辑框处理，提交或失焦后恢复单份正文显示。
- 非编辑态的播放/暂停、删除、撤销/重做和列表上下移动保持既有快捷键语义。
- 时间轴空白处点击定位并暂停；按住移动进行 scrub；字幕块中部优先移动，左右边缘调整起止时间；scrub 不改变字幕选中态。
- 唯一选中字幕、播放所在字幕和 hover 三种状态分开显示，playhead 是独立的细竖线；具体配色随主题变化（D-041：选中只留强调色细框，播放是略亮的中性底，hover 只轻微提亮）。
- AI 检查由用户主动启动，在后台运行，可切换到封面页；页面加载、刷新、切换项目和恢复会话不自动调用 AI。
- 建议只提供“采纳”和“跳过”；采纳写入同一字幕文档并进入撤销、dirty、草稿和正式保存，跳过不改正文并移出待确认队列。
- 自动保存只写可恢复草稿，不覆盖原始 SRT；显式保存校对字幕后才写正式 `*_校对.srt`。
- 字幕压制沿用旧工作流和默认样式，作为后台任务运行，不把压制状态机塞进主窗口的页面控件。

本轮文档整理不修改字幕语义，也不借整理之名重新设计字幕交互。

## AutoCover 专项优化（desktop-cover-opus55 分支）

- **封面 AI（D-026）**：设置页可配置 AI 接口（支持 OpenAI Responses `/v1/responses`、OpenAI 兼容、Anthropic；粘贴完整地址自动识别；http 须勾选允许；“测试连接”分别验证文字和看图模型）。方案区“AI 方案”：看图模型给人物取景框，本地按框取景排十几张候选，看图模型看成品挑稳妥 / 换个构图 / 大胆一点（压脸、压原有字、看不懂的淘汰）；文案要求只看封面能懂并固定包含标题那句；AI 文案也进“换一版”。工具栏“AI 改一改”给能一键应用的修改。顺带修复：只有 B 的封面套用带 A 的方案时 A 会丢失。
- **精修效果与模板（D-029）**：形状新增爆炸贴、集中线（中间空地仍能拖底图）；文字面板“垫爆炸贴”一键把爆炸贴垫在强调词后面（“AI 改一改”也会建议），强调词换行时不再被拆开；帧条缩略图右键“作为小图拼进封面”做反应 + 证据拼图，小图带可调白边；方案区“模板”可把排好的封面存为模板、换个视频一键套用，批量出图也能给新封面选模板。底图面板“抠出人物”：主播变成能单独拖动缩放的人物图层，底图里的人同时被抹掉再虚化，人物周围没有光晕和重影（底图面板可调“虚化”“压暗”，不抠人也能用；人物图层可勾“人物白边”，被画面下沿切开的人物默认“贴住底边”，缩小挪动不露切口），可做“人物清楚 + 背景糊掉”或“内容放大当背景 + 人物在角落”两种；有 BiRefNet 模型文件（数据目录 models/birefnet_lite.onnx）时用模型抠到发丝，没有时用 OpenCV 在人物区域里抠并按发丝贴边，按钮提示会说明当前是哪种（本机已放好模型，用模型时每张约 12～20 秒，在后台跑）。工具栏“投稿文案”：AI 按以前的标题口吻写 3 个备选标题、简介和标签，一键复制。
- **同音检查、打包脚本、候选帧（D-033）**：AI 面板里的闪电按钮做本地同音检查（需要 pypinyin，已写进 `requirements-qt-desktop.txt`，下次用 `启动Qt桌面端.cmd` 会自动装）；`packaging/` 里是安装包构建脚本，在主力机上运行，见 [PACKAGING.md](PACKAGING.md)（没构建验证过）；封面页“全片/更多”挑出的候选帧，点一张只换大图、候选保留。
- **字幕识别（D-032）**：字幕页选没有字幕的视频，顶部“识别字幕”；设置页“字幕识别”选引擎/模型/Python，带自检和加载试跑；命令行 `python -m autoslice.desktop.asr doctor|setup|run|bench`。识别在子进程里跑、可取消可续跑、不覆盖已有字幕，热词和你确认过的固定纠错自动生效。**真实模型还没在带显卡的主机上跑过**：先 `doctor --probe`，再用 `bench` 拿你的校对稿选引擎，见 [ASR.md](ASR.md)。
- **学习旧切片（D-031）**：设置页“学习旧切片”和命令行 `python -m autoslice.desktop.archive`：只读扫描你本机的历史投稿文件夹（可多个、可停、可续、没变的跳过），学纠错习惯、候选术语、标题口吻、字幕习惯、旧封面特征；出 `report.md` 和可整份交给 GPT 的 `digest.json`；学到的固定纠错、术语、标题范例、字幕阈值要在“学到的建议”里确认才生效，AI 字幕检查、投稿文案、字幕质量提醒随后用上。字幕质量提醒另加“边界重复”。**还没在你的真实旧数据上跑过**：先 `inspect` 看布局，规格和接手待办见 [ARCHIVE_LEARNING.md](ARCHIVE_LEARNING.md)，整体改进清单见 [IMPROVEMENT_BACKLOG.md](IMPROVEMENT_BACKLOG.md)。
- **界面（D-030）**：合并 `desktop-ui-opus55v2` 的“碳黑·钴蓝”质感、重绘图标、源流黑体和全局/弹层动效到封面分支（`window.py` 拆分后按函数移植）；封面工具栏改为分段比例 + 工具按钮 + 图标，窄窗口按优先级收成图标，输出摘要挪到画布下方；右侧面板动作按钮带图标，选中帧有蓝色粗边框、时间戳叠在缩略图上；设置页改成限宽卡片，AI 接口表单对齐、按钮高度修正；菜单与下拉框统一弹层动效。四个常见分辨率下的自动排查全部为 0 处，真实窗口、DPI 与手感仍需在主力机上验收。
- **时间轴默认高度**：没拖过时间轴时默认 150 像素，波形不用先拖大就看得清；拖过的按记住的高度。
- **封面参考日更切片号（D-028）**：文字可设强调词（选中文字点“强调所选”或直接输入），只换颜色，强调色默认按配色自动挑；AI 文案以“标题浓缩”为主（同一个爆点换说法），只在原话自带情绪时给原话，并自动标强调词；没锁帧时 AI 在爆点前后挑表情最有戏的一帧并对它重新标框，套用方案时底图跟着换（可撤销）；看图模型只标脸和直播界面的位置，本地算裁切（保住整张脸和刘海、脸不超过画面一半），避开聊天栏和画面原有的字，另有人在一侧、字在另一侧的构图，压到界面的候选先筛掉；AI 候选用“引子在上”的叠放。“AI 改一改”改为组合方案（如“放大 + 倾斜 + 外描边”），弹窗里改前改后缩略图对照，没变化的不显示，改完文字不出画。真实中转实测：直播界面密集的画面不再整批被否决，三张方案都扣着标题爆点；一次 AI 方案约 1～1.5 分钟，“AI 改一改”约 10～25 秒。
- **样式与素材**：一键预设（含黄青双色、双层描边、底条）、外描边与底条控件、色块按钮；风格记忆按主播继承并在导出时记忆；工具栏常驻素材与形状入口，素材库为缩略图网格；新素材插在文字之下，前移/后移一次越过相邻层。

需要实机确认：默认字体（濑户体）下的字宽和断行、上下分置在不同主播画面上的观感、预设配色是否符合习惯、附近帧推荐是否有用。

## 当前未完成与已知问题

### 必须先做：Beta UI Cleanup

当前 UI 仍有明显的“功能堆叠感”，不能把现有界面当成最终设计目标：

- 右侧上下文面板同时暴露文案、字号、样式、素材、强调框、层级、AI 和低频数字参数，信息架构没有按当前动作收口。
- 画布被顶部、右侧和底部控件挤压，4:3 场景尤其明显；画布没有稳定占据工作区中心。
- 素材、AI、颜色/描边/阴影、旋转/层级和精确数值应改为抽屉、展开区或“更多”入口，右侧一次只展示当前对象真正需要的内容。
- A/B 应优先通过画布对象直接选择；不应在右侧永久摆放一整套工程参数。
- 本次代码已补上可见的导出信息和错误提示、SVG 操作图标、附近帧选中反馈与缩略图样式；这些实现仍需真实窗口和字体下的视觉复核。
- 撤销/重做、快速方案和画布统一消费文档状态，Qt 画布与 Pillow 渲染统一解析实际字体来源，减少预览、保存和导出之间的状态分叉。
- 设计审计发现的全局 QSS、小窗口截断和状态可见性问题仍应继续实机复核；不能把单测通过视为 UI 收口完成。
