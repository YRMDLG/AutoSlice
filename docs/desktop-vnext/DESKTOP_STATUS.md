# Desktop vNext 当前状态

> 状态日期：2026-10-08。本文记录当前工作区能确认的实现状态和已知问题，不把历史测试结果写成最终实机验收结论。

## 状态结论

Desktop vNext 已经从“基础壳和局部能力”进入“功能基本铺开、集中实机收口”的阶段。字幕模块的交互语义已经冻结；AutoCover Beta 的核心编辑模型、双比例画布、素材、选帧、保存和导出链路已经接通。下一阶段的重点是 Beta UI Cleanup 和统一实机验收，而不是继续把所有参数堆到主界面。

当前最重要的判断是：**功能基本齐全不等于产品已经验收完成。用户实际反馈优先于测试通过；不能用单测全绿代替视觉、字体、构图和连续生产验收。**

## 字幕模块：语义冻结

字幕页的以下语义作为 Desktop vNext 的稳定契约：

- 项目按投稿根目录扫描；项目文件夹是项目事实来源，草稿和缓存只补充编辑状态。
- 播放器、字幕列表、轻量时间轴和 AI 建议区共享当前项目上下文，但各自的选中、播放和 hover 状态不混用。
- 单击字幕文字进入编辑；编辑框内的字符、空格、Delete 和换行由编辑框处理，提交或失焦后恢复单份正文显示。
- 非编辑态的播放/暂停、删除、撤销/重做和列表上下移动保持既有快捷键语义。
- 时间轴空白处点击定位并暂停；按住移动进行 scrub；字幕块中部优先移动，左右边缘调整起止时间；scrub 不改变字幕选中态。
- 唯一选中字幕使用青绿色主状态，播放所在字幕使用较弱的蓝灰状态，hover 只轻微提亮，playhead 是独立的细竖线。
- AI 检查由用户主动启动，在后台运行，可切换到封面页；页面加载、刷新、切换项目和恢复会话不自动调用 AI。
- 建议只提供“采纳”和“跳过”；采纳写入同一字幕文档并进入撤销、dirty、草稿和正式保存，跳过不改正文并移出待确认队列。
- 自动保存只写可恢复草稿，不覆盖原始 SRT；显式保存校对字幕后才写正式 `*_校对.srt`。
- 字幕压制沿用旧工作流和默认样式，作为后台任务运行，不把压制状态机塞进主窗口的页面控件。

本轮文档整理不修改字幕语义，也不借整理之名重新设计字幕交互。

## AutoCover Beta：已经铺开的能力

当前桌面 AutoCover 已接入下列能力，具体实现以 `src/autoslice/desktop/` 和 `src/autoslice_cover/` 的真实 owner 为准：

- `CoverDocument` 作为持久化主模型，`CoverDraft` 负责旧版本草稿兼容和迁移。
- A/B 两个独立 `TextObject`，可以分别选中、编辑、拖动、缩放、隐藏、删除和保存。
- `BackgroundObject` 支持从原始视频取帧、导入底图、平移、缩放、`cover/contain` 取景；裁切不做（D-024），`crop` 字段只为兼容保留。
- 4:3 与 16:9 共用一套对象，但分别保存文字位置、尺寸、背景缩放、平移和取景状态，并可分别导出。
- `ImageObject`、`StickerObject` 和 `ShapeObject` 已进入模型和画布边界；图片/旧版贴图支持导入、移动、缩放、旋转、复制、删除、前移和后移，强调形状覆盖圆圈、箭头和矩形。
- 统一的文档快照 Undo/Redo 已接入；拖动过程只更新轻量暂态，释放鼠标后才提交历史和自动保存。
- 从字幕页进入封面页时继承当前 playhead；封面底图从原始视频取帧，不把字幕预览层烧进封面。
- 附近帧后台渐进生成；支持锁定当前帧，以及用户主动扩大采样范围的“寻找更多画面”。锁定状态写入 `SourceRef`，草稿恢复后仍然有效。
- 基础文案采用确定性提取和压缩，保留 A（上下文）/B（主视觉信息）结构；当前字幕和附近字幕只参与语义上下文，不直接绘制到封面。
- 默认布局复用安全区域、边缘能量、anchor 和 slot 思路；文字 fit 使用实际字体 bbox 搜索字号和断行，避免 1–2 字孤短尾行。
- 字体文件入口支持 TTF、TTC、OTF；未指定时继续使用已经验证的默认字体路径。
- 旧版素材库接入按需扫描，支持最近、常用和主播优先的素材排序；风格记忆与导出历史提供连续生产所需的轻量回退信息。
- 封面 AI 已接入真实模型接口（D-026）：找爆点、写文案、看图出三套方案、AI 点评；需在设置页配置接口后使用，尚未经过用户用真实中转验收。
- 项目草稿、选帧、双比例导出和轻量历史已经落盘；项目切换、取帧、附近帧和方案缩略图使用 generation token 丢弃迟到回调。

## AutoCover 专项优化（desktop-cover-opus55 分支）

以下为代码实现证据，已在投稿目录里的一条真实 1080p 直播切片上端到端跑通（取帧、自动构图、双比例导出、Windows 字体下的界面截图），尚未经过用户实机验收：

- **所见即所得**：画布与 Pillow 导出改为共用 `cover_layout` / `autoslice_cover.document_layout` 的几何、字号和断行；像素对照测试中画布与导出平均差约 1.3（满分 255）。修复了背景平移方向相反、文字旋转中心和方向不同、右对齐导出失效、贴图尺寸与透明度不一致、形状旋转丢失、图层不按 z 排序、画布放大超过导出上限、画布绘制图片对象抛异常等问题。
- **编辑写回**：右侧文案框改字此前不写入文档，已修复；文案与样式两比例共享，位置、尺寸、字号和对齐按比例保存；删除文字块在两个比例同时生效。
- **文本框**：改为剪映/Canva 式的“固定字号 + 行宽”，选中框贴合文字；四角依次为删除、旋转（吸附 0°/±90°/180°）、复制、等比缩放，左右两侧为改宽手柄，旋转后的对象按旋转框命中。旧草稿按原先实际显示的字号与行宽升级（`text_revision`）。A/B 是两个独立文本框，“换一版”只替换文字，保留位置与字号；复制出的文本框不参与换一版，删除时直接移除。
- **拖动手感**：画布改为分层位图缓存（选中对象单独一层，其余对象上下两层），拖动只平移选中层，不再逐帧重新描边；真实切片上每帧从约 55ms 降到约 3ms，静态重绘从约 54ms 降到约 3ms。释放鼠标不再同步写盘（防抖保存，关窗前补写），精确重画延后到空闲时。
- **新建文字**：工具栏“文字”新建文本框（沿用主文案样式，选中后直接输入）；双击画布上的文字即可改字。右侧不再常驻 A/B 切换按钮，直接在画布上点选文本框。
- **快速方案**：右侧顶部三张方案缩略图，点击套用（可撤销），“换一批”轮换文案和配色；没有播放位置时自动从全片挑首帧。“导出 4:3 + 16:9”改为主按钮，配色预设常驻文字面板。
- **断行**：词内普通断点代价从 0.12 提到 0.2，宁可字号小一点也不拆“居然”“韩娱”这类词。
- **账号风格**：配色预设改为参考“绝对忠诚的Y”切片封面的全黄、黄青、黄红（红字白边）、黄紫（紫字白边）等；描边按字号比例（约 8%）并随缩放跟随；风格记忆保留 A 的双色；新增“标题在上”构图，“换一批”在不同构图间轮换。
- **批量出图**：工具栏“批量出图”给投稿目录里的多个视频一次出 4:3 + 16:9，默认勾选未导出过的，可中途停止；没有草稿的自动选帧排版并存成草稿。
- **删减**：按用户决定移除 AI 三个方案（本地 mock）、另一比例小预览、文字的 X/Y 与旋转数值；顺带修复改字号时选中文本框被写回到 B 位置的问题。对话框统一深色背景（此前所有弹窗是白底浅字）。
- **补齐功能**：画布上直接打字（双击文字或新建文字后就地输入，实时显示）；帧条“全片”按画质挑 7 张、进度条拖动选帧；“同步到另一比例”一键套用当前比例的文字和素材位置；素材菜单列出最近使用的素材一键插入；素材库此前按整条标题匹配主播分组、实际不生效，改为按主播名优先。
- **对照文档补齐**：被删除或隐藏的文字和素材可从工具栏“已隐藏”恢复（此前去掉 A/B 按钮后隐藏的 A 无法找回）；对象可锁定；图片/贴图透明度、形状线条与填充可调；导出记录可回看；“下一个”切到下一个视频；视频重新导出后沿用原排版并从同一时刻重新取帧（此前旧草稿会被新封面覆盖，界面只显示英文状态）。删除永远不可见的空状态面板死代码。裁切明确不做（D-024）。
- **快捷键**：字幕页的 Delete、Space、Q/W、Ctrl+B、Ctrl+Z/Y 只在字幕页生效；封面页有自己的撤销/重做。此前在封面页按 Delete 会删除字幕行。
- **基础文案**：截取对齐语义边界，不再把“居然”切成“然”；保留原文“！”“？！”；从截掉的前半句提取 A；“⁉”等符号正确拆分标题。
- **默认构图**：参考 smartcrop.js 的肤色/细节/饱和度显著图，加居中主体先验；人物居中时 A 在上缘、B 在下缘、居中大字，人物偏侧时文字去另一侧；从 16:9 裁 4:3 时自动保住贴边人物；4:3 选上下分置时 16:9 跟随。
- **选帧**：附近帧逐帧并行、渐进显示；复用旧版画质评分标出明显更好的一帧（只标记不换帧）；“寻找更多画面”按画质挑选；同一视频只探测一次元信息。
- **代码整理**：封面编辑器（原 3000 行）、封面服务（1330 行）、画布和主窗口（2700 行）按职责拆成混入类，方法原样搬运；删除死代码和“无文档”的旧标题框链路，合并两份后台任务类；比例覆盖统一走 `set_profile_override`，撤销历史统一走 `_record_history`；去掉编辑时每次改动都在后台渲染一张没人看的预览图（D-025）。每一步都跑完整测试，并在真实切片上与改动前逐像素对比截图。
- **成长底座（D-027）**：字幕纠错记忆（保存校对时学常见错词，两个视频都改过才记住，进 AI 检查的固定纠错建议）；封面作品库（每次导出记构图、配色、文案、方案）和防千篇一律（第二、三套快速方案优先给最近没用过的构图和配色）；设置页“成长记录”可查看、可忽略。主播专属梗词挪进主播档案；文案加两条通用规则（预告句降权、反转词加分）；自动排版保证 A 字号不超过 B 的 75%。
- **封面 AI（D-026）**：设置页可配置 AI 接口（支持 OpenAI Responses `/v1/responses`、OpenAI 兼容、Anthropic；粘贴完整地址自动识别；http 须勾选允许；“测试连接”分别验证文字和看图模型）。方案区“AI 方案”：看图模型给人物取景框，本地按框取景排十几张候选，看图模型看成品挑稳妥 / 换个构图 / 大胆一点（压脸、压原有字、看不懂的淘汰）；文案要求只看封面能懂并固定包含标题那句；AI 文案也进“换一版”。工具栏“AI 改一改”给能一键应用的修改。一次 AI 方案约 40～70 秒。顺带修复：只有 B 的封面套用带 A 的方案时 A 会丢失。
- **样式与素材**：一键预设（含黄青双色、双层描边、底条）、外描边与底条控件、色块按钮；风格记忆按主播继承并在导出时记忆；工具栏常驻素材与形状入口，素材库为缩略图网格；新素材插在文字之下，前移/后移一次越过相邻层。

需要实机确认：默认字体（濑户体）下的字宽和断行、上下分置在不同主播画面上的观感、预设配色是否符合习惯、附近帧推荐是否有用。

## 当前未完成与已知问题

### 必须先做：Beta UI Cleanup

当前 UI 仍有明显的“功能堆叠感”，不能把现有界面当成最终设计目标：

- 右侧上下文面板同时暴露文案、字号、样式、素材、强调框、层级、AI 和低频数字参数，信息架构没有按当前动作收口。
- 画布被顶部、右侧和底部控件挤压，4:3 场景尤其明显；画布没有稳定占据工作区中心。
- 素材、AI、颜色/描边/阴影、旋转/层级和精确数值应改为抽屉、展开区或“更多”入口，右侧一次只展示当前对象真正需要的内容。
- A/B 应优先通过画布对象直接选择；不应在右侧永久摆放一整套工程参数。
- 本次代码已补上可见的导出信息和错误提示、SVG 操作图标、附近帧选中反馈与缩略图样式；这些实现仍需真实窗口和字体下的视觉复核。
- 撤销/重做、快速方案和画布统一消费文档状态，Qt 画布与 Pillow 渲染统一解析实际字体来源，减少预览、保存和导出之间的状态分叉。
- 设计审计发现的全局 QSS、小窗口截断和状态可见性问题仍应继续实机复核；不能把单测通过视为 UI 收口完成。
- 原始改动清单及本次实施对照见 [UI_CLEANUP_PLAN.md](UI_CLEANUP_PLAN.md)。

### 需要统一实机验收

- 默认字体在目标 Windows 机器上的加载、fallback、字宽和实际视觉层级。
- 默认构图在真实截图、人物主体、界面文字和字幕区域下的安全性。
- 基础文案的质量、A/B 关系、孤短尾行回退和不同标题类型的稳定性。
- 4:3 / 16:9 独立微调后的保存、恢复、预览和分别导出。
- 附近帧渐进生成、锁帧和“找更多画面”在切换项目、刷新和重启后的行为。
- 图片、贴图和强调形状的命中、拖动、旋转、层级与 Undo/Redo。
- 多视频连续生产、导出历史、失败恢复和源文件不变性。

### 发布前已知可靠性与发布工程缺口

- ASS 路径单引号问题已有代码修复和回归用例：预览及压制改为在安全工作目录读取相对 ASS 文件名；本次未运行真实 FFmpeg 编码，真实媒体结果仍需验收。详见 [SECURITY_NOTES.md](SECURITY_NOTES.md)。

- 发布前还必须验证 per-user 安装、`%LOCALAPPDATA%\AutoSlice` 可写数据目录、本地 token/配置不进入分发包、安装/升级/卸载/重装，以及发布依赖的 CVE/版本状态。

### 尚未完成的产品能力

- AutoCover Beta UI Cleanup 和统一视觉基线尚未完成。
- 封面 AI 的线上质量、调用耗时和额度提示仍需用真实中转验收；AI 选帧、投稿标题/简介还没做。

## 当前工作区与分支约束

- 当前开发主线为 `desktop-vnext-dev`；最新代码及本文档随该分支推送。`main` 保留现有 Web 工作流；克隆、环境、验证和直接推送步骤见 [协作说明](../../CONTRIBUTING.md)。
- 判断“工作区是否干净”必须同时区分三类状态：tracked diff、untracked files、ignored artifacts。`git diff HEAD` 为空只能说明已跟踪文件没有 diff，不能说明整个工作区没有本地文件。
- 当前存在未跟踪/忽略的计划、审计、截图、测试日志和 `work/` 产物；这些不能被自动删除、覆盖或误当成第二套当前规范。
- 多 agent 并行时，审阅 agent 默认只读；需要改代码的 agent 应优先使用独立 worktree/临时分支，避免多个 agent 在同一工作树上互相覆盖或基于过期 HEAD 写计划。
- 未经用户明确要求，不 force push、不清理未知文件、不顺手提交其他 agent 的工作。
