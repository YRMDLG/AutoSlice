# AutoCover vNext 当前产品与交互规范

> 本文是 AutoCover Beta 的当前有效规范，描述产品边界、编辑模型、交互语义和验收重点。当前桌面实现仍需要一次 Beta UI Cleanup；现有控件全部展开、右侧面板堆叠和参数编辑器感不是设计目标。
>
> 用户实际反馈优先于测试通过。测试证明契约可靠，不代表字体、默认构图、文案质量和信息架构已经通过视觉验收。

## 1. 目标与边界

AutoCover 是 AutoSlice 工作流中的快速封面编辑器：从当前视频继承项目和播放头，选择不带字幕烧录的原始画面，生成确定性的基础 A/B 文案，允许用户直接编辑对象，分别完成 4:3 与 16:9 的轻量微调，然后导出可投稿图片。

它提供设计辅助能力，不承担完整视觉设计软件的职责：

- 保留对象移动、缩放、旋转、隐藏、删除、复制和基础层级，保证封面可以被人接管。
- 不做 Photoshop/Canva 式复杂图层面板、蒙版、贝塞尔路径、滤镜、动画、模板市场和素材交易。
- 不改变字幕语义，不把字幕预览层烧进封面底图，不把字幕页的状态机塞进封面页。
- 不依赖 AI 才能完成封面；AI 默认不运行，基础模式必须离线、确定、可回退。

## 2. 进入与最小工作流

一次封面任务以项目、视频和播放头快照为上下文：

```text
当前项目/视频
  → 继承字幕页 playhead
  → 从原始视频生成当前帧和附近帧
  → 选择或锁定底图
  → 生成基础 A/B 文案
  → 在画布编辑对象
  → 保存草稿与预览
  → 分别导出 4:3 / 16:9
  → 进入下一个视频
```

具体约束：

1. 封面底图只从原始视频取帧，绝不把字幕预览、ASS 或播放器叠加层截图进去。
2. 进入封面页时继承当前 playhead，但封面页只读取播放头快照，不反向 seek 播放器。
3. 附近帧按需、后台、渐进生成；切换项目不默认扫描整片。
4. 用户点击“锁定当前帧”后，候选帧、基础文案和 AI 候选不得替换该取景帧；锁定状态写入 `SourceRef` 并在草稿恢复后保留。
5. 用户点击“寻找更多画面”才扩大采样范围；操作过程要显示来源和失败原因，不静默改变已选帧。

## 3. 双比例画布

支持两个独立导出目标：

| 比例 | 默认尺寸 | 用途 | 编辑语义 |
|---|---:|---|---|
| 4:3 | 1440×1080 | 主封面/首页推荐等 | 默认进入的主画布，可独立保存布局覆盖 |
| 16:9 | 1920×1080 | 个人空间等横向场景 | 共享同一组对象，位置、尺寸、背景取景可以独立微调 |

双比例共享文案和对象身份，但不是把一个像素矩形强行缩放两次：

- 文档保存基础对象值和每个比例的 profile override。
- 文字位置、文字框尺寸、背景缩放、平移、适配方式和必要的可见状态可以按比例覆盖。
- 切换比例不能丢失另一比例的微调；刷新、项目切换和重启后应恢复最后成功预览。
- 导出时按目标 profile 计算实际字体 bbox、换行、边界和背景裁切，不能沿用另一比例的像素结果。

## 4. `CoverDocument` 主模型

`CoverDocument` 是当前版本的持久化主模型，当前文档版本为 v4。模型是纯数据边界，不依赖 Qt、Pillow 或媒体文件；服务层负责取帧、草稿、预览和导出，画布负责显示和手势。

根级字段包括：

- `version`、文字样式 revision：用于版本校验和迁移。
- `source`：视频身份、选中时间、底图资源和 `frame_locked`。
- `profiles`：4:3 和 16:9 的尺寸、安全区、导出后缀和对象覆盖。
- `objects`：稳定 `id` 的可渲染对象序列；不能用列表下标当身份。
- `active_profile`、`selected_object_id`：可恢复编辑状态，不改变对象本身的渲染语义。

所有对象使用与画布无关的归一化坐标或明确变换值；Qt 像素矩形只存在于视图适配层。对象共有 `id`、`kind`、`transform`、`z_index`、`visible` 和 `locked` 等字段。文档修改通过返回新快照完成，便于 Undo/Redo、异步代际检查和原子保存。

### 对象类型

| 类型 | 责任 | 当前支持的关键字段 |
|---|---|---|
| `BackgroundObject` | 视频帧或导入底图 | `asset`、`fit_mode=cover/contain`、`scale`、`pan_x/y`、可选裁切 |
| `TextObject` | A/B 或其他文字块 | `text`、`copy_role`、归一化 `rect`、换行规则、对齐、字体样式、旋转和层级 |
| `ImageObject` | 用户导入图片 | 资源引用、透明度、裁切、移动/缩放/旋转和层级 |
| `StickerObject` | 旧版贴图或素材库贴图 | 资源引用、分类、透明度、移动/缩放/旋转、复制和层级 |
| `ShapeObject` | 强调和指示形状 | `circle`、`arrow`、`rect`，填充/描边/宽高和变换 |

对象默认可见、可选中、可保存；锁定对象不响应普通拖动。渲染顺序由 `z_index` 和稳定对象身份决定，不能由控件排列顺序偶然决定。

### `CoverDraft` 兼容层

`CoverDraft` 继续存在，但只负责读取旧草稿 v1～v3 和为旧调用方提供兼容值。新业务状态、新 UI 和新渲染逻辑都以 `CoverDocument` 为准：

- 读取旧草稿时迁移为 v4，并尽量原子保存迁移结果。
- 旧字段 `title`、`text_x/y`、`background_x/y/scale` 不能再扩展成第二套编辑模型。
- 新增对象、双比例覆盖、锁帧和层级只能写入 `CoverDocument`。

## 5. A/B 文案结构

基础模式把封面文案拆成两个独立文字对象：

- **A：上下文**，只提供让 B 成立的最小背景、诱因或关系；可以为空，字号和描边层级低于 B。
- **B：主视觉信息**，承载最有记忆点的原话、结果、反差或强信息，是主要阅读对象。

A 和 B 必须分别拥有自己的 `id`、文字、文字框、字号、字体、填充、描边、阴影、行距、对齐、旋转、位置和可见性。用户可以只改 B、只隐藏 A，或把两个对象拖到不同区域；系统不能先把 A/B 拼回一个字符串再编辑。

默认层级和安全距离用于保证初始构图清楚，但用户一旦手动拖动，后台任务不能偷偷把对象重新排回默认位置。B 不因“更大”而压住主体；A 不应与 B 叠成一块同权重的大字。

## 6. 基础文案规则

基础文案不调用 AI，不补造事实，不把字幕原文直接当成画布文字：

1. 从投稿标题、当前字幕和附近字幕中做确定性提取、清洗和压缩。
2. 当前字幕和附近字幕只作为语义上下文参与提取，不直接绘制到封面。
3. 优先保留可核对的作品名、物品名、数字、结果、角色反应和强原话。
4. A 只保留让 B 成立的最小上下文，B 优先落在真实爆点或现场反应上。
5. “换一版基础文案”只循环本地候选，不偷偷调用 AI 或改写成没有来源的事实。
6. 无法可靠提炼时，回退到短的完整原文片段；不生成“究竟发生了什么”等空泛悬念代替事实。
7. fit 使用实际字体 bbox 搜索字号和断行，避免最后出现 1～2 字孤短尾行；显式换行要被保留。

案例和可接受替代以 [AUTOCOVER_COPY_GOLDEN_SET.md](AUTOCOVER_COPY_GOLDEN_SET.md) 为准。

## 7. 默认布局与风格继承

默认布局沿用安全区域、边缘能量、anchor 和 slot 的思路：

- 中央主体显著时，优先把文案放进上缘或下缘安全带。
- 左右空区明显时，才把文案放进侧边槽位。
- 默认布局必须避开人物、主体和原图文字的高风险区域；没有可靠证据时宁可使用保守位置。
- 用户手动移动后，后台默认布局和候选只提供可选结果，不覆盖手工位置。
- 颜色、字体、描边和强调色继承当前项目/主播的稳定风格记忆，但可由用户覆盖；继承失败时使用已验证的默认样式。
- 字体路径必须可验证。缺少用户字体时明确显示 fallback，不把机器上的偶然字体当成产品保证。

布局黄金案例和边界见 [AUTOCOVER_LAYOUT_GOLDEN_SET.md](AUTOCOVER_LAYOUT_GOLDEN_SET.md)；编辑模型的长期约束见 [AUTOCOVER_EDITOR_MODEL_PLAN.md](AUTOCOVER_EDITOR_MODEL_PLAN.md)。

## 8. 素材与对象操作

素材入口按需扫描旧版素材库和用户导入目录，排序优先级为最近、常用、当前主播/项目相关，再显示其他素材。素材能力包括：

- 导入图片或贴图；
- 在画布中移动、缩放、旋转和基础层级调整；
- 复制、删除、隐藏、锁定和恢复；
- 形状工具创建圆圈、箭头和矩形；
- 同一对象在 4:3、16:9 中分别保存必要的变换覆盖；
- 对象操作进入同一套文档快照 Undo/Redo。

不在文字编辑面板永久展开素材和形状参数。用户选择对象后，右侧只显示当前对象真正需要的属性；低频的旋转、层级和精确值进入“更多”。

## 9. AI 三候选 Beta

AI 是显式、可选、可回退的辅助入口：

- 默认 `enabled=false`，页面初始化、刷新、切换视频和基础文案都不运行 AI。
- 当前 Beta 提供结构化本地 mock 三候选：稳妥、换个构图、更加大胆；候选包含标签、差异说明、理由、置信度和可编辑 `CoverDocument`。
- 候选必须先以预览呈现，用户选择后才写入当前文档；不能以不可编辑 PNG 作为工作结果。
- 真实 relay、额度提示、缓存和质量评估属于后续工作；接入后仍须保持用户主动触发和同输入复用缓存。
- AI 建议不能替换锁定帧，不能覆盖用户手工移动过的对象，不能改变 A/B 事实语义。

## 10. 保存、历史、导出与连续生产

- 编辑过程自动保存可恢复草稿；拖动时先更新轻量暂态，释放鼠标后再提交文档、写草稿和排队预览。
- Undo/Redo 使用完整 `CoverDocument` 快照；拖动过程不把每个鼠标事件写成一条历史。
- 草稿按项目和视频隔离，保存源视频身份、选中帧、锁帧、对象、双比例 profile、最后成功预览和必要的导出历史。
- 预览、导出和另一比例任务带 generation token；旧项目或旧文档的迟到回调必须丢弃。
- 导出 4:3 与 16:9 为两个明确文件；命名递增且不覆盖已有源视频或既有成品。
- 连续生产按视频逐个恢复，不要求用户重新分析队列第一个视频；导出失败保留草稿和可见错误。
- 导出前以当前 profile 重新计算字体 bbox、背景取景和所有对象；预览和正式导出共用同一布局结果，避免“画布看起来对、文件导出错位”。

## 11. Beta UI Cleanup 规则

当前 UI 处于“功能铺开后集中收口”状态，以下规则是下一阶段目标：

- 画布始终是中心，顶部只保留比例、撤销/重做和导出等工作流动作。
- 右侧一次只展示当前对象、当前动作所需的属性；不把整套属性检查表长期摊平。
- 素材使用独立抽屉，AI 使用独立抽屉或浮层，颜色/描边/阴影进入“样式”，旋转/层级/精确数值进入“更多”。
- A/B 优先点击画布对象直接选择，不在右侧永久摆放两个大按钮。
- 底部附近帧条保持轻量；“锁定帧”和“寻找更多画面”是当前取帧动作，不扩展成全片管理器。
- 测试通过后仍要用真实项目、真实字体和真实窗口尺寸验收；视觉反馈可以推翻“功能已完成”的判断。

## 12. 验收清单

一次完整验收至少覆盖：

- 进入封面页继承正确 playhead，底图没有字幕烧录。
- 锁定帧后切换候选、运行基础文案和 mock AI 不替换底图。
- A/B 独立编辑、字体 bbox、断行、拖动、缩放、隐藏和删除符合预期。
- 4:3 / 16:9 各自微调、刷新恢复、分别导出且对象没有串位。
- 图片、贴图、形状的命中、旋转、层级、复制、删除和撤销/重做可用。
- 切换项目时旧取帧、附近帧、预览和 AI 回调不会覆盖新项目。
- 草稿恢复后选帧、锁帧、对象和最后成功预览都存在。
- 默认字体、默认构图和基础文案在真实素材下通过人工视觉检查。
- Beta UI Cleanup 后，右侧面板不再把全部参数作为常驻主界面。
