# AutoSlice 用户需求与偏好

> 作用：记录用户已经明确表达的真实需求、偏好、禁忌和验收标准。这里优先保存“用户实际怎么用”，而不是产品经理式假设。

## 1. 基本路径和项目扫描

- 默认投稿目录：`submissions/`。
- 目录下以视频标题命名的文件夹视为投稿项目。
- 用户需要“刷新项目列表”快速重新扫描。
- 项目目录是事实来源；数据库、草稿和缓存只能补充状态。
- 不要求每个项目都有 manifest、数据库记录或自动切片结果。

## 2. 用户真正高频的功能

优先级最高：
1. 字幕校对。
2. AutoCover 封面制作。
3. 字幕压制。
4. 可恢复草稿和连续生产。

不再优先：
- 自动分析录播；
- 自动切片；
- 默认全片扫描；
- 高性能消耗的“智能分析”流程。

原因：这些能力在用户机器上的性能成本高，而真实收益低。

## 3. 字幕页需求

用户希望边看视频边判断字幕，不希望来回切剪映。

交互要求：
- 单击字幕正文进入编辑，不要双击。
- 行内编辑直接完成手工修改。
- AI 建议只保留“采纳 / 跳过”。
- Delete 删除字幕必须直接、稳定。
- 快捷键在非编辑态要全局稳定。
- 编辑框获得焦点时，Space/Q/W/Delete 等不得误触窗口动作。
- 播放位置和选中字幕必须区分。
- 时间轴指针必须可拖动。
- 空白轨道点击应定位；拖动 playhead 应连续 scrub。
- 字幕块覆盖区域仍要支持拖块和调边界。

视觉偏好：
- 正文比序号和时间更突出；
- 项目列表紧凑；
- AI 侧栏不要占大面积；
- 长文本自然换行；
- UI 清爽，不要“太糙”。## 4. 字幕冻结语义

用户已经多轮验证并认可：
- 空白时间轴单击：seek + pause。
- 空白拖动超过阈值：框选。
- 时间轴字幕块单击：只改变选择，不 seek。
- 底部字幕行单击：选择并 seek 到 cue start。
- 字幕块中部拖动：移动 cue。
- 左右边缘拖动：调整起止。
- timing move/resize 不移动 playhead。
- Ctrl 点击 toggle；Shift 点击 range。
- Delete 删除当前选择并进入单次 undo。
- playhead 独立可拖。
- snap 默认开启，Alt 可绕过。
- 水平滚动只控制视野，不等于播放位置。

快捷键：
- Space：播放/暂停（编辑态外）。
- Q：把 active cue 起点裁到 playhead。
- W：把 active cue 终点裁到 playhead。
- Ctrl+B：split。
- F1/F2/F3/F4：既有试听语义保持。
- 编辑状态下这些快捷键不得抢输入。

## 5. AutoCover 基本目标

用户要的是：
> 快速做一个比“随便截帧+随便放字”更好的封面，而不是做精切海报。

AutoCover 必须：
- 快；
- 可直接手改；
- 不阻塞项目切换；
- 不要求用户理解内部坐标；
- 默认结果至少可作为起点；
- 不把 AI 作为必经步骤。

用户最在意：
- 画布操作手感；
- 文案质量；
- 默认构图；
- 双比例；
- 素材调用效率；
- 导出清楚；
- 连续做多个项目不会疲劳。## 6. AutoCover 文字交互要求

旧版已经验证好用的交互优先级高于“重新设计”。

必须保持：
- 鼠标按在哪里，就从哪里抓住文字，不跳左上角。
- 拖动过程中鼠标离开对象仍应继续当前手势。
- 中心吸附和辅助线只在需要时出现。
- 吸附不能抢控制权。
- 用户手动移动后，后台分析不能偷偷把文字重排。
- A/B 是独立文字对象，不应先拼成一个大字符串再自动换行。
- A 可以不存在；B 是主视觉。
- A/B 可分别拖动、调字号、改样式、隐藏或删除。
- 手动换行优先，自动换行不能产生明显难看的 1–2 字尾行。
- 选中态只叠加边界/抓手，不应改变正式文字外观。

文字能力需要覆盖：
- 字体；
- 字号；
- 填充色；
- 描边色/宽度；
- 阴影；
- 行距；
- 对齐；
- 自动/手动换行；
- 旋转能力在底层保留。

## 7. AutoCover 背景和构图要求

背景不是“截图硬塞进画布”。

需要：
- 平移；
- 缩放；
- cover / contain；
- 每个比例独立取景；
- 默认尽量避开人物脸、眼睛、嘴和关键证据区域；
- 无可靠识别时宁可用保守布局，也不要假装智能。

用户对旧版的评价：
- 旧版选帧“能用”，但智能推荐价值一般。
- 旧版文字拖动和吸附没有明显问题，应该继承。
- 旧版 4:3 / 16:9 比较方便。
- 旧版切项目时被自动选帧阻塞非常烦，必须修掉。## 8. AutoCover 文案要求

基础文案必须确定性、可解释：
- 不造事实；
- 不做营销号式改写；
- 不用空泛“究竟发生了什么”；
- 不把整条投稿标题直接塞进封面；
- 不把字幕画面烧进封面。

语义结构：
- A = 让 B 成立所需的最小上下文；
- B = 最值得视觉强调的信息；
- 最多两个块；
- 可以只有 B。

用户已明确认为“标题摘要式文案”几乎没用。
如果系统提炼不可靠，应回退到短的完整原文片段。

基础文案不能因为“AI 更聪明”就变成默认 AI 请求。

## 9. 素材与风格要求

素材库需要优化，而不是继续做成大全：
- 最近使用优先；
- 高频优先；
- 当前主播/项目相关优先；
- 支持导入自定义图片；
- 支持表情包、箭头、强调素材；
- 素材对象支持移动、缩放、旋转、复制、删除和简单层级。

用户不需要素材商城、模板市场或在线社区。

风格继承：
- 可以继承字体、字号层级、颜色、描边、阴影、行距、常用素材偏好；
- 不继承旧封面的精确 x/y；
- 不继承旧背景帧；
- 不继承具体文案；
- 不继承完全相同构图。## 10. AI 要求

用户关注额度和无效调用。

原则：
- 默认不调用；
- 页面打开不调用；
- 项目刷新不调用；
- 基础文案不调用；
- 相同输入优先缓存；
- 能本地确定解决的事情不要浪费 AI。

AI 可以做：
- 封面审核；
- 三个候选方案；
- 构图建议；
- 反重复提醒；
- 未来学习用户选择。

已冻结候选方向：
- 稳妥；
- 换个构图；
- 大胆一点。

AI 应推荐一个候选，但用户手动应用。
AI 可以明确返回“这次没有明显更优方案”。

AI 不能：
- 自动替换用户锁定帧；
- 自动覆盖用户手工布局；
- 用一个审美分数替用户决定好坏；
- 直接生成不可编辑整图作为最终工作结果。

## 11. UI 和视觉偏好

用户不接受“功能面板 / 管理后台”式 AutoCover。

期望：
- 画布是绝对主角；
- 一次只显示当前对象真正需要的属性；
- 素材、AI、低频参数按需展开；
- 不长期露出 X/Y 等工程坐标；
- 右侧面板不能把所有功能一次铺开；
- 界面要清爽、紧凑、明确下一步做什么。用户会直接通过实机截图评价结果；如果截图明显不好，不能用“测试全绿”反驳。

## 12. 双比例和导出

需要明确的 4:3 / 16:9 主画布切换。

要求：
- 同一对象身份；
- 每个比例可独立微调位置、尺寸和背景取景；
- 切换比例不丢状态；
- 分别导出；
- 文件名、比例、尺寸要在导出前明确；
- 不静默覆盖旧文件；
- 导出历史至少可以轻量回看。

## 13. 性能要求

用户对卡顿非常敏感。

必须：
- UI 线程不做取帧、整图渲染、波形、FFmpeg、模型调用或全片分析。
- 拖动过程中只做轻量本地更新。
- 鼠标释放后再写文档、Undo/Redo、自动保存和预览。
- 项目切换必须立即响应。
- 旧任务迟到回调不能污染新项目。
- 附近帧渐进生成，不等待全部完成再显示页面。

## 14. 发布和部署要求

目标是正常 Windows 应用：
- 安装一次；
- 桌面快捷方式启动；
- 不把 CMD 脚本作为最终使用方式；
- PyInstaller onedir + Inno Setup 是当前发布方向；
- 发布版本无控制台窗口。

## 15. 需求变更原则

用户会在真实使用后改变设计结论，这是正常的。

新的真实体验反馈优先级：
1. 实机操作感受；
2. 实际截图和导出；
3. 已冻结的产品原则；
4. 自动化测试；
5. 早期设计稿或阶段计划。

如果实现与真实体验冲突，应改实现或规范，而不是要求用户适应错误设计。
