# Desktop vNext 后续路线

> 本文是产品路线，不是逐 Action 执行计划。代码实现、测试证据、提交策略和真实媒体授权仍以项目规则及单独计划为准。

## 路线判断

当前已经完成“把功能基本装齐”的阶段，下一步必须集中收口使用体验和实机证据。用户已经明确希望先把功能装齐，再一次性测试并集中反馈；因此后续不再一边扩展功能、一边把当前 UI 当成验收目标。

## 近期：AutoCover Beta UI Cleanup + 统一实机验收

这是下一阶段的最高优先级，完成前不继续扩大 AutoCover 的常驻参数面板。

### UI Cleanup

- 以画布为中心重新安排空间，减少顶部、右侧和底部对 4:3 画布的挤压。
- 右侧面板遵循“当前对象、当前动作、最少必要控件”的规则；文字只显示文案、字号、对齐和样式/更多入口。
- 素材、图片导入、贴图和形状放进独立抽屉或工具入口；AI 放进独立抽屉/浮层。
- 颜色、描边、阴影收进“样式”；旋转、层级、精确数值收进“更多”。
- A/B 优先通过画布对象直接选中，不在文字面板永久显示一整组 A/B 工程按钮。
- 附近帧、锁帧和找更多保持底部轻量操作，不扩展成全片扫描控制台。
- 清理大段说明文案、重复状态和无动作价值的参数，让默认页面安静。

### 统一实机验收

使用真实项目、真实视频、真实字体和目标窗口尺寸一次性验证：

- 字体加载、fallback、字宽、描边和阴影在 4:3 / 16:9 下的实际观感。
- 默认构图避开人物、主体、界面文字和字幕区域的能力。
- 基础文案的 A/B 关系、事实保真、换行和不同标题类型的稳定性。
- 选帧、附近帧、锁帧、找更多以及项目切换/刷新/重启后的恢复。
- 图片、贴图、形状的命中、旋转、层级、复制、删除、Undo/Redo。
- 双比例独立微调、预览、导出、连续生产和失败恢复。
- 字幕页与封面页来回切换时，项目上下文和后台任务不串线。

验收输出应同时记录：通过项、视觉问题、实际复现步骤、影响范围和下一步；“单测绿”只能作为其中一项证据。

## 中期：稳定文案与布局质量

在 UI Cleanup 和实机验收完成后，按质量优先顺序推进：

1. **文案质量**：扩充文案黄金集，覆盖数字异常、诱因/结果、原话反应、单段强句、警告和多角色对话；把失败回退变成可解释状态。
2. **LayoutEngine**：把实际字体测量、可用安全区、主体避让、A/B 关系、profile override 和导出布局统一到可测试的布局引擎，减少画布、预览和导出三套计算。
3. **字体和风格验收**：整理默认字体、字体文件选择、主播/项目风格记忆和 fallback 的产品提示，避免依赖某台机器的偶然字体。
4. **风格记忆**：在用户主动保存或确认后，记忆稳定的颜色、描边、字号层级和常用素材；不把一次临时调整默认为长期偏好。
5. **连续生产**：完善多视频草稿索引、导出历史、失败重试、源文件变更提示和下一视频快捷入口。

## 中后期：真实 AI relay 与可编辑候选

真实 AI relay 只有在本地基础模式稳定后才进入：

- AI 默认仍关闭，所有调用由用户主动触发，并明确提示成本和等待。
- relay 只返回结构化文案、构图角色和建议字段；本地 LayoutEngine 负责坐标、字体、换行和最终图片。
- 候选必须是可编辑的 `CoverDocument`，不能返回不可编辑成图。
- 相同输入按源视频、标题/字幕上下文、模型和规则版本缓存；源文件或文档变化时失效。
- 真实质量用黄金集和人工实机评分验证，不用“请求成功”代替内容验收。

字幕 AI 保持独立路线：封面 relay 不得复用字幕建议的 UI 状态机，也不改变字幕语义冻结。

## 暂缓或不做

在当前产品边界内，以下事项不进入 Desktop vNext 路线：

- 视频剪辑、镜头重排、复杂时间线和剪映替代。
- Photoshop/Canva 式复杂图层、蒙版、贝塞尔、通道、曲线、Liquify、动画和滤镜系统。
- 花式字幕、字幕模板市场、复杂动效和字幕运营平台。
- 模板市场、公开素材社区、在线账号、多人协作、云同步和跨平台发布。
- 自动投稿、自动上传、运营数据面板和全片无人值守包装。
- 默认运行 AI、默认整片扫描、默认抠主体、默认自动改写事实。
- 为了验收而对整场长录播做字幕压制或无必要的整片重编码。

## 进入下一阶段的门槛

只有同时满足以下条件，才把重点从 UI Cleanup 转向中期质量：

- 真实窗口尺寸下画布、右侧面板和附近帧布局完成统一验收。
- 真实字体、默认构图和基础文案黄金集完成一轮人工复核。
- 双比例、素材、草稿、generation token 和导出在至少一个真实项目上完整走通。
- 已知的高影响问题有复现步骤和决定（修复、暂缓或明确不做）。
- 本轮验证结果已写入状态文档，未用历史测试或单测结果代替实机结论。
