# AutoCover 基础文案黄金测试集 v0.1

> 日期：2026-10-01
> 目的：验证“无 AI 基础文案提取器”是否真的比旧 AutoCover 的机械拆句更好。
> 来源：绝对忠诚的Y公开 Bilibili 投稿标题样本。
> 状态：人工期望集，不是永久真理；后续真实使用反馈优先。

## 使用方式

每个案例记录：
- 原始投稿标题；
- 关系类型；
- 期望 A（可为空）；
- 期望 B；
- 可接受替代；
- 设计理由。

验收重点不是逐字 100% 相同，而是：
1. 不把完整长标题机械铺满；
2. B 抓住真正有视觉价值的信息；
3. A 只补最少上下文；
4. 不编造标题中不存在的事实；
5. 强原话优先于中性概括；
6. 能正确判断“只需要 B”的情况。

## Case 01：万楼

原题：〖泽音〗泽音一个晚上居然被冲了万楼？！😱原因居然是这个？！👀

- 类型：时间 / 异常事件
- A：一个晚上
- B：被冲万楼了？！
- 可接受：仅 B「被冲万楼了？！」
- 不推荐：「原因居然是这个」作为主 B
- 理由：数字异常本身就是点击点，“一个晚上”只负责增强反差。

## Case 02：脚惩罚

原题：〖泽音〗逆天音姐听到公主说要用脚惩罚她时🥵高兴的发出了鸟叫😅

- 类型：诱因 → 荒诞反应
- A：听到要用脚惩罚
- B：高兴到发出鸟叫
- 可接受：A「脚惩罚她」 / B「居然高兴到鸟叫」
- 理由：不能只保留“脚惩罚”，真正的梗是反常反应。

## Case 03：18 岁虚假宣传

原题：〖泽音〗(音量警告)刚上播不清醒的音音 嘴滑承认18岁是虚假宣传 然后大吼大叫试图让音悦生👂🐉 闹麻了😓

- 类型：事件 → 爆点
- A：刚上播不清醒
- B：18岁是虚假宣传？！
- 可接受：仅 B
- 理由：“大吼大叫”是后续反应，核心记忆点是“18岁虚假宣传”。

## Case 04：牛姐喝晕

原题：〖泽音〗坏比音悦生哄骗音音给牛姐打电话😈结果得知牛姐喝晕过去后😱秒变温柔音音💖唐牛真的好甜🥰

- 类型：事件 → 反差反应
- A：得知牛姐喝晕了
- B：秒变温柔音音
- 可接受：A「给牛姐打电话」 / B「突然变温柔了」
- 理由：UP 主末尾“唐牛真的好甜”不应自动压过事件本身。

## Case 05：线下大屏

原题：〖泽音〗看大家给音姐弄大屏😮“感觉去线下得要更低调了😰”“穿洞洞鞋拿purax的是音音！🤩”“嘘嘘嘘！不要再说了”

- 类型：背景 → 强原话
- A：大家给音姐弄大屏
- B：嘘！不要再说了
- 可接受：B「去线下得更低调了」
- 理由：优先选择能体现现场反应的原话，而不是把三句原话全塞进去。

## Case 06：看旧节奏天国切片

原题：〖泽音〗看自己以前玩节奏天国的切片👀“机器人好惨啊😂感觉不经过我毒手还好一点🤣”

- 类型：背景 → 原话
- A：看以前的节奏天国切片
- B：机器人好惨啊
- 可接受：B「不经过我毒手还好一点」
- 理由：画面背景需要一点上下文，但主视觉应落在有情绪的原话。

## Case 07：反光图钓鱼

原题：〖泽音〗坏东西音姐故意发了个带反光的图😡“就是想看音悦生的反应啊🤭”钓钓钓！再上当我就是猪！

- 类型：行为 → 结果 / 宣言
- A：故意发带反光的图
- B：再上当我就是猪！
- 可接受：A「就是想看你们反应」 / B「再上当我就是猪」
- 理由：最后一句最像封面强句。

## Case 08：汽水

原题：〖泽音〗流氓音姐张口就是“想拍一下了🥵音悦生屁股这么翘，一定能顶瓶汽水吧🤭”

- 类型：单段强原话
- A：音悦生屁股这么翘
- B：一定能顶瓶汽水吧
- 可接受：仅 B「一定能顶瓶汽水吧」
- 理由：原话本身已经足够，不需要系统制造新的概括。

## Case 09：模仿伍佰

原题：〖泽音〗天才模仿生模仿伍佰老师👍把高音都留给了音姐唱🤣“不要这个也学啊！🤬”

- 类型：事件 → 反应
- A：把高音都留给音姐
- B：不要这个也学啊！
- 可接受：A「模仿伍佰老师」 / B 同上
- 理由：B 是清晰、有情绪的现场反应。

## Case 10：神秘人物退钱

原题：〖泽音〗音姐直播间突入神秘人物👀气的音姐大骂音悦生要他退钱！😰究竟发生了什么🤔

- 类型：事件 → 强结果
- A：直播间突入神秘人物
- B：退钱！
- 可接受：B「气到大喊退钱」
- 不推荐：「究竟发生了什么」作为 B
- 理由：末尾悬念词是标题包装，不应优先于真实爆点。

## Case 11：苦主小音

原题：〖泽音〗苦主小音幻想音悦生以后对别人说天衣无缝情话😰“音音心里就一阵心酸😭”

- 类型：情境 → 原话反应
- A：想到你以后对别人说情话
- B：音音心里一阵心酸
- 可接受：A 更短「以后对别人说情话」 / B 同上
- 理由：B 必须保留角色反应，而不是概括为“吃醋”。

## Case 12：请勿外放

原题：〖泽音〗警告：本视频请勿外放！音姐打《啊。啊。啊。》太隐晦了🥵

- 类型：警告 + 事件
- A：音姐打《啊。啊。啊。》
- B：本视频请勿外放！
- 可接受：A「太隐晦了」 / B「请勿外放！」
- 理由：警告语自身具有非常强的缩略图识别力。

## Case 13：掷铁饼者

原题：〖泽音〗V圈不得不品的一环《掷铁饼者的传奇故事》“我以为在吹牛，结果是真的😰”

- 类型：对象 → 反差原话
- A：掷铁饼者的传奇故事
- B：我以为在吹牛，结果是真的
- 可接受：B「结果居然是真的」
- 理由：不要把“V圈不得不品的一环”这种包装句当视觉主句。

## Case 14：醉酒牛舌

原题：〖糖&牛〗下头音姐想吃醉酒牛舌了🥵“牛舌挺好吃的😘”“滚啦你🙄”

- 类型：对话
- A：牛舌挺好吃的
- B：滚啦你
- 可接受：A「想吃醉酒牛舌」 / B 同上
- 理由：这是典型两方对话，B 用短反应最有画面感。

## Case 15：销毁证据

原题：〖糖&牛〗BW糖牛要打一架了👀音姐要狠狠爆牛哥口嗨之仇🤬结果可恶牛哥居然要下架切片员视频销毁证据😡坏事做尽！

- 类型：背景 → 荒诞结果
- A：BW糖牛要打一架了
- B：下架视频销毁证据？！
- 可接受：A「要爆口嗨之仇」 / B「销毁证据？！」
- 理由：末尾结果比前面的普通“打一架”更值得视觉强调。

## Case 16：红色感叹号

原题：〖糖&牛〗坏比音姐疑似想爆猛料👀牛哥直言威胁你要爆什么出来😡吓得音姐不敢说了，生怕牛哥明天就把她红色感叹号了🤭

- 类型：诱因 → 后果
- A：音姐疑似想爆猛料
- B：明天就红色感叹号了
- 可接受：B「吓得不敢说了」
- 理由：“红色感叹号”是更有记忆点的具体后果。

## Case 17：舔腋窝

原题：〖泽音〗坏比音姐突然说了个冷知识🤔“你的舌头舔不到你的腋窝”👀“没人试一下吗”“想到七百个人在舔自己腋窝就想轻哼”🤭

- 类型：原话 → 荒诞联想
- A：舌头舔不到自己的腋窝
- B：七百个人都在舔腋窝？
- 可接受：B「没人试一下吗」
- 注意：基础模式不得凭空加入“都”，若严格抽取应写「想到七百个人在舔自己腋窝」
- 理由：这是测试“不要为了好听而越界改写”的重要案例。

## Case 18：B站新礼物退钱

原题：〖泽音〗B站新礼物‘退钱’把音姐吓死了🤣“你们很吓人，一群紫色字发退钱😡”

- 类型：对象 → 反应原话
- A：B站新礼物「退钱」
- B：一群紫色字发退钱！
- 可接受：B「你们很吓人」
- 理由：保留事件对象，B 使用具体视觉化原话。

## Case 19：BW 票

原题：〖泽音〗音姐安慰没抢到BW票的音悦生们😭“大家不要激动啊😰黄牛就是利用这种心理赚的钱 总会有机会的😘”

- 类型：背景 → 观点 / 安慰
- A：没抢到BW票
- B：总会有机会的
- 可接受：B「黄牛就是利用这种心理赚钱」
- 理由：不是每条都必须做“爆点”；温和内容应该允许温和封面。

## Case 20：直播点鸭子

原题：〖泽音〗音悦生直播点鸭子😰“点鸭子你去菜场啊来我们这🤔”“原来是菜场啊 我以为是超市呢🤭”“我恨我秒懂🤬”

- 类型：背景 → 最终反应
- A：直播点鸭子
- B：我恨我秒懂！
- 可接受：A「点鸭子你去菜场啊」 / B 同上
- 理由：三段对话不应全部进入封面，最后反应承担视觉重点。

## 补充边界案例：系列型标题

原题示例：〖泽音〗晚安小音音💤节奏天国小音😎

这种标题不应被强行解释成“事件 → 爆点”。

建议：
- A：晚安小音音
- B：节奏天国小音

它用于验证：
- 系列身份可以作为 A；
- B 只是当期内容，不需要制造虚假冲突；
- 基础系统应允许“没有爆点”的正常封面。

## v0.1 期望得到的规则

从 20 个案例反推，基础提取器至少需要区分：
1. 强原话；
2. 事件 / 对象；
3. 诱因；
4. 结果 / 后果；
5. 角色反应；
6. 标题包装语（例如“究竟发生了什么”）；
7. UP 主主观尾评；
8. 系列标签；
9. 对话双方；
10. 单 B 足以成立的情况。

下一轮实现前，应先用这些案例做规则原型，再扩大测试集。

## 基础文案提取器 v0.1：规则原型

这部分不是最终实现，只用于把“看起来合理”压成可测试逻辑。

### Step 1：预清洗
- 去掉开头账号 / 主播统一前缀，如 〖泽音〗、〖糖&牛〗；
- emoji 默认作为语义边界信号，不直接决定内容价值；
- 保留引号内原话；
- 标记而不是立即删除“警告 / 系列 / 游戏名 / 节目名”等结构词；
- 把“究竟发生了什么”“原因居然是这个”等纯包装悬念语降低权重；
- 把明显 UP 主尾评单独标记，不默认作为 B。

### Step 2：语义片段化
按以下边界切候选片段：
- ！？。；
- 引号边界；
- emoji 边界；
- 然后 / 结果 / 随后 / 没想到 / 但是 / 却 / 吓得 / 气得 等关系词；
- 多段连续原话分别保留。

目标不是得到“正确语法句”，而是得到可竞争的封面信息单元。

### Step 3：B 候选评分

每个片段计算一个可解释的启发式分数。

加分信号：
- 引号内强原话；
- 明确结果 / 后果；
- 明显反差；
- 强情绪词；
- 异常数字或数量；
- 极短且有独立意义；
- 具体名词 / 动作，而不是抽象概括；
- 标题靠后且由“结果 / 然后 / 吓得”等引出的片段。

减分信号：
- “究竟发生了什么 / 原因居然是这个”等包装句；
- 纯 UP 主评价；
- 只说明视频类别、没有事件信息；
- 太长；
- 单独拿出来完全失去指代对象；
- 重复前一个片段。

B 评分只用于排序候选，不允许凭空改写。

### Step 4：判断是否需要 A

选出最高 B 后先做“独立成立”检查。

倾向不需要 A：
- B 本身包含明确对象 + 动作 / 结果；
- B 是完整强原话；
- B 是足够明确的异常事件；
- B 已经接近封面最大可接受长度。

倾向需要 A：
- B 只有反应，例如“玩不过你们”；
- B 缺少对象，例如“退钱！”；
- B 是答句 / 结果，但不知道前因；
- B 依赖对话另一方才能成立。

A 的目标不是“第二重要句”，而是：
**用最少字符补足 B 的上下文。**

### Step 5：A 候选选择

优先级：
1. 与 B 有直接因果 / 对话关系的前置片段；
2. 明确对象或事件名；
3. 对方原话 / 问题；
4. 必要时间或场景；
5. 系列标签。

A 应比 B 更短、更弱。
如果 A 不能明显提升 B 的理解度，则舍弃 A。

### Step 6：生成 2~4 套基础组合

不只保存一套答案：
- Best：最高分 A/B；
- Alt-1：替换 B 为第二高分强原话 / 结果；
- Alt-2：尝试仅 B；
- Alt-3：必要时换一个上下文 A。

默认只显示 Best。
“换文案”在这些组合中即时循环，不调用 AI。

### Step 7：硬约束

基础模式必须遵守：
- 最多 2 个文字块；
- 每块可内部换行，但不能把一条长标题拆成 4~6 个同级块；
- 默认 B 视觉权重大于 A；
- 不新增原题没有的事实、角色、结果；
- 不为了“更有点击感”擅自做强改写；
- 系列 / 歌切 / 温和内容允许没有爆点；
- 规则判断不确定时，宁可保守抽取，不要自作聪明。

### Step 8：失败回退

当规则无法可靠判断：
1. 优先使用最短、信息最完整的原题片段作为 B；
2. 必要时显示用户原题的安全截断版本；
3. 绝不阻塞画布；
4. 用户始终可直接点击文字覆盖。

这保证基础系统判断失败时仍然“能用”，而不是生成鬼文案。

## 黄金测试集的第一阶段验收方式

实现规则原型后，不只判断 exact string。

每个 Case 至少检查：
- B 是否命中期望核心语义；
- 是否错误选中包装悬念句；
- 是否错误把 UP 主尾评当主句；
- 是否无意义地强制生成 A；
- 是否超过两块；
- 是否发生基础模式禁止的改写；
- 是否在系列 / 温和案例上强行制造冲突。

建议先做到 20 个 Case 中大多数“方向正确”，再扩大到 50~100 条真实标题。
不要为了单个 Case 堆大量特殊 if；若修一个案例导致其它案例退化，应优先修改通用规则。
