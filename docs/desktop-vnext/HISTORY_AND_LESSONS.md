# Desktop vNext 历史与经验教训

> 作用：保存项目演进中“为什么这样做”的背景，尤其记录已经踩过的坑。它不是当前规范；当前规范仍以 PRODUCT / AUTOCOVER_SPEC / ARCHITECTURE / DECISIONS 为准。

## 1. Desktop vNext 起点

项目重启的原因不是“旧版完全不能用”，而是旧项目越来越大，历史服务、Web UI、AutoCover、字幕和自动切片互相牵连，维护成本开始超过收益。

用户明确希望重新聚焦：
- 不再把自动分析录播/自动切片放在主线；
- 重点服务字幕校对和 AutoCover；
- 做正常 Windows 桌面应用；
- 尽量恢复旧工作流里已经顺手的体验。

核心原则逐渐形成：
> 迁移能力，不机械迁移旧 UI；继承已经验证的行为，不为了“新版”重新发明一切。

## 2. Desktop-04.5：桌面技术选型

冻结方向：
- PySide6 / Qt Widgets；
- libmpv 首选；
- PyInstaller 无控制台 EXE；
- Inno Setup；
- 正常安装后的桌面快捷方式。

这一阶段完成了 Qt 三页壳和无控制台 EXE 实验。

经验：
- 桌面壳可以重做，但服务 owner 和旧功能边界必须明确；
- 发布路径要与开发脚本分离。

## 3. Desktop-04.6：真实项目和草稿

接入：
- 投稿目录真实扫描；
- SRT 编辑和保存；
- 草稿恢复；
- 窗口状态；
- 单实例。

经验：
- 项目文件夹比数据库更可靠，项目目录应是事实来源；
- 草稿必须是补充状态，不能反过来决定项目是否存在。

## 4. Desktop-05：播放器

接入 libmpv：
- 暂停定位；
- D3D11 硬解；
- 精确 seek。

经验：
- 播放器是适配器，不应该持有字幕业务状态；
- 用户最在意“点了以后发生什么”，不是播放器参数有多少。## 5. Desktop-06 / 06.5：字幕交互纠偏

主要修复：
- 快捷键统一入口；
- 选中和播放位置区分；
- 行内编辑；
- 定位逻辑；
- 时间轴高亮；
- 双层文本和焦点问题。

重要结论：
- 字幕单击编辑，不双击；
- 选中字幕不等于播放位置；
- 编辑态和全局快捷键必须隔离；
- 时间轴交互要按“空白 / block / edge / playhead”明确命中优先级。

这些语义后来被冻结，后续不应轻易改变。

## 6. Desktop-07.5 / 07.6：UI 与时间轴收口

改进：
- 左侧导航；
- AI 侧栏重排；
- 去冗余顶栏；
- playhead scrub；
- 空白轨道定位；
- 1366×768 适配。

经验：
- 桌面 UI 不是“把所有参数都显示出来”；
- 高频内容必须占空间，状态和说明要收起来；
- 用户对卡顿和焦点抢占非常敏感。

## 7. Desktop-08：字幕压制闭环

接入：
- 既有 burn_subtitles；
- NVENC 与回退；
- 同名避让；
- 后台任务；
- 退出行为。

经验：
- 已经有稳定 owner 的能力应复用，不复制一套 FFmpeg 命令；
- 后台任务和 UI 生命周期要分离。

## 8. AutoCover vNext 第一轮：功能先接通

最初桌面 AutoCover 先把能力接起来：
- 当前项目/视频；
- 导入图片；
- 时间戳取帧；
- 16:9 预览；
- 标题位置、字号、描边、阴影；
- 草稿和导出。随后接入：
- lib/服务异步任务；
- 画布拖动；
- 背景缩放；
- playhead 交接；
- 4:3 主画布；
- 附近帧。

用户第一次实机反馈非常明确：
> “极其糙，需要各种调整，这糙的我连测试都不想测试。”

教训：
- 功能接通不等于产品可用；
- 参数式 UI 很容易变成“后台管理器”；
- 真实截图比代码结构更能说明问题。

## 9. AutoCover 产品重新定位

通过多轮讨论冻结：
- AutoCover = 快速编辑器 + 可选 AI 创意辅助 + 防重复记忆；
- 速切不等于固定模板；
- 风格可以稳定，但构图不能机械重复；
- AI 默认不参与；
- 基础系统负责下限，AI 只负责可选上限。

关键概念：
- 4:3 主画布；
- 16:9 双比例；
- A/B 文案；
- 附近帧；
- 帧锁定；
- 被动风格学习；
- AI 三候选；
- 连续生产；
- 导出检查。

## 10. 旧版 AutoCover 审计

旧版被重新当作“行为基线”检查。

用户评价：
- 旧版选帧能用，但智能价值有限；
- 旧版 AI 文案慢且质量差，几乎不用；
- 旧版贴图库有价值，但排序需要优化；
- 旧版吸附没有明显问题；
- 旧版 4:3 / 16:9 方便；
- 旧版项目切换被自动取帧阻塞很烦。

因此形成原则：
> 旧版不是 UI 目标，但已经验证好用的交互必须优先继承。

## 11. UX-01：发现 DesktopWindow 和 AutoCover 风险

架构审查发现：
- DesktopWindow 已明显膨胀；
- AutoCover 模块边界相对清晰；
- AI review 状态机仍有抽离空间；
- 项目上下文和异步任务需要更统一 generation/token。冻结：
- 不为了代码漂亮立刻大拆 DesktopWindow；
- 从此不继续把新业务状态机塞进去；
- AutoCover 保持独立 widget/canvas/service/model 边界。

## 12. UX-02：第一次“修手感”仍然不够

尝试修：
- 文字拖动 offset；
- 选择反馈；
- 中心吸附；
- 首屏状态；
- 导出说明。

虽然技术上更正确，但实机仍然不好用。

典型问题：
- 文字框交互仍不像旧版；
- 背景构图像截图硬塞；
- 参数和安全区依然抢用户控制。

教训：
> 坐标正确 ≠ 编辑器好用。

## 13. UX-03：双画布和自由移动仍未解决根因

加入：
- 4:3 / 16:9 主画布切换；
- 弱化安全锁；
- 更自由的拖动；
- 默认布局调整。

结果仍差。

根因逐渐明确：
- 当前模型把封面当“背景 + 一个字符串”；
- 文本没有真正对象化；
- 继续修坐标会形成补丁系统。

## 14. UX-04 / Phase 1：CoverDocument

重建领域模型：
- CoverDocument；
- BackgroundObject；
- TextObject；
- ImageObject；
- StickerObject；
- ShapeObject；
- Transform；
- LayoutProfile；
- 迁移层。

CoverDraft 降级为兼容 DTO。

这是重要架构修正，但 Phase 1 不改 UI，所以用户看到“完全没修”是事实而不是 bug。教训：
> 地基改造必须明确告诉用户“这轮不会有可见变化”，否则技术完成感会与使用感严重错位。

## 15. Phase 2：对象化 Canvas

接入：
- TextObject 编辑；
- BackgroundObject 编辑；
- 双比例 profile；
- Qt/QTest。

实机仍不满意。

主要问题：
- 文字外观和正式 renderer 分叉；
- 文本框语义与旧版不同；
- 拖动和排版仍缺乏旧版手感。

## 16. Phase 2.1：迁移旧版文字行为

重新阅读旧版 app.js 行为：
- 按下点保持；
- window 级拖动；
- 8px 中心吸附；
- 单右下角 resize handle；
- +/- 调字号；
- 方向键微调；
- 点击空白取消选择。

这一步确立：
> 新模型可以保留，但交互应优先行为等价迁移，不要凭空创新。

## 17. Phase 2.2A：WYSIWYG 修复

发现三套文字链：
- Canvas 用 Qt 默认绘制；
- Preview 走 Draft；
- Export 走旧 renderer。

导致黑字/白字/描边不一致。

修复方向：
- 共享 TextStyle；
- 共享换行规则；
- Qt 与 renderer 使用同一字体/填充/描边/阴影/行距；
- Preview/Export 直接消费 CoverDocument。

随后又发现历史 v4 草稿已经持久化错误样式，需要 style_revision 做一次性迁移。

教训：
> 改默认值不能修已经持久化的坏数据；模型升级必须有显式 revision 和 migration。## 18. Phase 2.2B：拖动性能与基础文案

定位拖动卡顿：
每个 mouseMove 都在写文档、同步控件、重启 autosave、重启 preview。

修成：
- mouseMove 只更新暂态；
- mouseRelease 一次提交；
- preview/save debounce。

这成为后续所有画布对象的性能契约。

同时撤回“伪封面钩子”：
- 基础模式只提取/压缩；
- 不造事实；
- 不用 AI；
- 不把长标题硬塞进一个 TextObject。

## 19. Phase 2.2C / 2.2D：A/B 和排版

先拆成 A/B 两个对象，但第一次仍然失败：
- 两个块仍像一坨；
- A/B 层级弱；
- 1～2 字短尾行；
- 默认覆盖主体。

之后重新读取旧版：
- clause 拆分；
- 视觉宽度；
- 行平衡；
- context/quote/emphasis 层级；
- _text_area；
- _fit_text；
- anchor/slot。

重要教训：
> “拆成两个对象”仍不等于“排版正确”；默认布局要先确定可用区域，再 fit 文本。

## 20. Beta 功能铺开

用户决定停止逐截图小修，先把应有功能一次铺开后集中测试。

Beta 接入：
- A/B 独立文字；
- Background；
- 双比例；
- Image/Sticker/Shape；
- Undo/Redo；
- 附近帧、锁帧、找更多；
- 素材；
- 风格继承；
- AI mock 三候选；
- 导出历史；
- 双比例导出。随后用户再次实机指出：
> 功能很多，但界面“很怪”。

原因：
- 右侧面板重新堆满所有参数；
- 画布被 UI 挤压；
- 当前动作没有信息层级；
- 素材、AI、文字样式、层级、数值同时抢注意力。

因此下一阶段正式定为：
**AutoCover Beta UI Cleanup**。

## 21. 当前最大的经验

### 经验 A：不要把测试通过当产品通过

多次出现：
- 18 tests passed；
- 69 tests passed；
- 75 tests passed；
但真实截图仍然不可用。

以后必须区分：
- 技术检查；
- 产品实机验收。

### 经验 B：用户已经验证好的旧行为很值钱

旧版不一定漂亮，但某些手感经过长期使用：
- 文字拖动；
- 吸附；
- 双比例；
- 素材调用。

这些不应因为“新版架构”而丢失。

### 经验 C：UI Cleanup 应在功能铺开后集中做

太早美化会反复推翻；
太晚又会堆成参数后台。

当前正处于正确节点：
- 能力基本齐；
- 下一步只做信息架构和交互收口。

### 经验 D：性能是功能的一部分

拖动卡顿时，再好的默认构图也没有意义。
UI 线程保护、暂态手势、release commit、generation/token 都属于产品体验。

### 经验 E：不要把 AI 当万能补丁

AI 不能修：
- 坏拖动；
- 坏信息架构；
- 坏字体链；
- 坏对象模型。

必须先把确定性编辑器做顺，再让 AI 提供额外价值。## 22. 接下来怎么继续

当前推荐顺序：
1. AutoCover Beta UI Cleanup。
2. 用户一次性统一实机测试。
3. 按“交互 / 视觉 / 文案 / 性能 / Bug”分类反馈。
4. 集中修复，不再一张截图一个 Work 批次。
5. 验收后再接真实 AI relay。
6. 再评估 LayoutEngine 和长期风格记忆。
