# AutoCover 编辑器计划（讨论稿）

> 状态：仅保存设计方向，尚未实现。
> 原则：下一阶段先重建编辑器骨架，再把已经打通的真实取帧、导入图、拖标题、背景平移缩放、草稿、导出能力接回去；不继续美化当前参数面板式布局。

## 1. 产品定位

AutoCover 不做“小 Canva”，也不做复杂海报设计器。
它服务 AutoSlice 的真实投稿流程：从视频里快速找一帧，完成构图、标题和少量视觉调整，然后导出 Bilibili 封面。

目标体验：
- 剪映 / CapCut 的取帧效率；
- Canva 的低门槛素材入口；
- Figma 的上下文属性面板；
- Photoshop 的上下文快捷操作；
- 保持 AutoSlice 自己简洁、快速、少步骤。

## 2. 核心编辑模型

不再采用“投稿项目 + 素材参数 + 小画布 + 永久参数栏”的表单式结构。
改成“画布优先”的创作工具：

- 全局投稿项目栏保留，但在封面编辑时允许折叠或弱化；
- AutoCover 主区以大尺寸 16:9 画布为核心；
- 左侧只保留窄工具入口 rail，不常驻大素材面板；
- 底部提供可收起的候选帧 / 选帧条；
- 右侧属性面板根据当前选中对象动态变化；
- 高频操作直接发生在画布上。
## 3. 目标布局

建议骨架：

```text
┌──────────────────────────────────────────────────────────────┐
│ 当前项目             ↶  ↷          画布缩放       导出封面 │
├────┬───────────────────────────────────────────────┬─────────┤
│ 帧 │                                               │         │
│ 图 │                                               │  动态   │
│ 字 │                  大 画 布                      │  属性   │
│ AI │                                               │  面板   │
│    │                                               │         │
├────┴───────────────────────────────────────────────┴─────────┤
│             可收起的视频候选帧 / 选帧条                     │
└──────────────────────────────────────────────────────────────┘
```

左侧 rail 只负责切换工具：
- 帧：视频取帧 / 候选帧；
- 图：导入图片；
- 字：添加或编辑标题；
- AI：显式打开标题 / 构图建议。

工具内容按需展开，关闭后把空间还给画布。

## 4. 右侧上下文属性

右栏不永久显示同一套 X/Y/字号/缩放参数，而是“选中什么，就编辑什么”。

### 选中标题
- 多行标题文本；
- 字体、字号、颜色；
- 左 / 中 / 右对齐；
- 描边颜色 / 粗细；
- 阴影；
- 最大宽度；
- X/Y 只作为精调。
### 选中背景
- 构图位置；
- 缩放；
- 填满；
- 适合；
- 居中；
- 重置构图；
- 后续再考虑亮度、模糊、饱和度。

### 未选中对象
- 画布比例和分辨率；
- 安全区域；
- 输出设置；
- 项目级状态。

## 5. 画布直接操作

- 点击标题选中；
- 拖标题移动；
- 点击 / 拖背景调整构图；
- 滚轮缩放背景；
- 选中对象时显示轻量边界框；
- 画布附近可出现小型上下文工具条，只放高频操作；
- 不选中对象时尽量保持画面干净。

标题上下文工具条可包含：
- 编辑文字；
- 字号；
- 颜色；
- 对齐。

背景上下文工具条可包含：
- 填满；
- 适合；
- 居中；
- 重置。

## 6. 视频取帧工作流

从字幕页进入封面页时，只读继承当前 playhead 时间，不反向 seek、不改变字幕页状态。
封面页底部显示当前时间附近的一排候选帧，例如：
- -2s；
- -1s；
- -0.5s；
- 当前帧；
- +0.5s；
- +1s；
- +2s。

用户点击某张缩略图即可将其设为背景。
需要更精确时，可在轻量选帧条上拖小 playhead。
选完背景后，候选帧条可以收起，把空间还给画布。

## 7. P0 编辑体验

### Undo / Redo
必须支持 Ctrl+Z / Ctrl+Shift+Z（或 Ctrl+Y）。
至少覆盖：
- 标题移动；
- 背景移动；
- 背景缩放；
- 字号 / 样式变化；
- 标题文本变化；
- 更换背景。

### 对齐与吸附
拖动标题时提供轻量：
- 画布水平中心线；
- 画布垂直中心线；
- 安全边距；
- 接近中心 / 安全线时吸附。

## 8. 草稿和保存

草稿应持续自动保存。
“保存草稿”不应成为高频主按钮。
界面只需弱提示：
- 正在保存；
- 已保存；
- 保存失败。

用户真正需要主动点击的主要动作是“导出封面”。
## 9. AI 的位置

AI 不自动调用，不在正常编辑时消耗额度。
只作为上下文入口：
- ✨ 标题建议；
- ✨ 构图建议。

建议结果缓存。
第一阶段不做重型自动生成、不做复杂模板市场。

## 10. 默认样式

新草稿默认值应克制：
- 标题宽度约占画布 60%–70%；
- 默认最多 2–3 行；
- 字号不应一上来覆盖半个画面；
- 合理行距；
- 默认放在安全区域；
- 描边适中。

旧草稿保持原值，不强制迁移视觉数据。

## 11. 当前已有能力的处理

以下能力已经打通，下一轮重建编辑器骨架时必须保留并重新接入：
- 真实 MP4 取帧；
- 本地图导入；
- 私有缓存；
- 标题拖动；
- 背景平移 / 缩放；
- 草稿保存 / 恢复；
- 预览与最终 JPG 构图一致；
- 字幕页 playhead 只读交接；
- 安全递增导出。

当前 UI 只是功能原型，不作为最终布局继续打补丁。

## 12. 暂不做
- 模板市场；
- 完整图层系统；
- 复杂滤镜；
- 自动上传 Bilibili；
- 重型 AI 生成；
- 大量专业设计软件功能。
## 13. 进一步讨论：阶段上下文 + 对象上下文

新增核心原则：AutoCover 不应“把所有功能同时摆出来”，而应根据用户当前阶段和当前选中对象，只给出真正需要的操作。

### 阶段上下文
- 选帧阶段：重点是快速浏览当前 playhead 附近候选帧，不显示大量文字/构图参数。
- 构图阶段：选定背景后，候选帧条可收起，把空间还给画布。
- 输出阶段：导出属于文档级操作，不属于某个对象属性。

### 对象上下文
- 选中标题：右栏显示文字、字号、颜色、描边、阴影、最大宽度、对齐等。
- 选中背景：右栏显示构图、缩放、填满、适合、居中、重置。
- 未选中对象：右栏显示画布/文档级信息。

## 14. 进一步讨论：构图模式与直接操作

背景不应始终处于“随便拖”的状态，以免和标题拖动冲突。
建议背景选中后提供“调整构图”模式：

- 平时点击背景只是选中背景；
- 点击“调整构图”后，拖动=平移，滚轮=缩放；
- Enter/完成按钮提交，Esc/取消回退；
- 画布状态栏动态提示当前鼠标/键盘能做什么。

标题仍保持直接操作：点击选中，拖动移动；完整属性在右栏，高频属性可用轻量上下文工具条贴近对象显示。

## 15. 进一步讨论：顶层命令与自动保存

- “导出”应从对象属性栏移到应用顶层工具栏，作为文档级动作。
- “保存草稿”按钮应逐步消失，草稿持续自动保存；界面只显示“正在保存 / 已保存 / 保存失败”。
- 顶层建议保留 Undo / Redo、画布缩放、导出。
- 后续可考虑 Tab 进入“专注画布”，临时隐藏项目栏与属性栏，但不是 P0。
- 左侧 rail 继续做减法：帧、图片、文字、AI 只是入口，不机械复制 Canva 的大素材侧栏。

## 16. 进一步讨论：候选帧与 AI

候选帧条是视频来源封面的核心优势：
- 从字幕页 playhead 进入封面；
- 自动展示当前时间附近若干帧；
- 点击即可成为背景；
- 需要时可进一步拖小 playhead 精确选帧；
- 选定后候选帧条可折叠。

AI 应继续作为上下文入口：
- 选中标题：✨ 标题建议；
- 选中背景：✨ 构图建议；
- 未选中对象：✨ 封面建议；
- 永不自动调用，结果缓存。

## 17. 设计纪律：功能要能删

后续功能评审不以“能不能做”为标准，而以“真实切片封面工作流里是否高频、有明显收益”为标准。
必须允许删功能：
- 如果功能极少使用、与用户工作流冲突、增加认知负担或维护成本，就不进入核心界面；
- 可以有高级功能，但默认隐藏在上下文、折叠区或快捷操作中；
- AutoCover 目标不是复刻 Canva/Photoshop，而是覆盖切片封面的高频 20% 操作；
- 后续将通过真实 Bilibili 切片员封面样本反推工具需求，再决定哪些功能保留、删除或延后。

## 18. Bilibili 切片封面样本观察（初步，待继续讨论）

本轮开始从真实 Bilibili 切片样本反推功能，不再从 Canva / Photoshop 的功能清单倒推。
观察范围包含用户主页“绝对忠诚的Y”可检索到的大量泽音切片，以及其他 VUP / 直播切片封面样本。

目前看到的高频封面结构大致有：
- 直播 / 视频原帧作为整张背景，再叠大标题；
- 主播立绘 / 抠图人物 + 纯色、渐变或装饰背景 + 大标题；
- 人物特写 + 极大关键词；
- 双人 / 多人物拼接；
- 主画面 + 小型 meme / 截图插图；
- 歌回 / 录播等场景直接使用较干净的画面，文字很少甚至无额外标题。

因此 AutoCover 不应只围绕“单背景 + 单标题”设计，但也不应直接做完整图层设计软件。

### 初步高价值能力

P0 / 高频基础：
- 视频候选帧与精确选帧；
- 背景裁切、平移、缩放；
- 文字多行、自动适配、字体、颜色、描边、阴影；
- Ctrl+Z / Redo；
- 对齐线 / 安全区 / 吸附；
- 自动保存；
- 预览与导出一致。

P1 / 很可能需要：
- 2~3 个独立文字块，而不是永远只有一个标题；
- 添加额外图片元素（透明 PNG、表情包、截图、小图）；
- 图片元素的移动、缩放、裁切、前后层级；
- 简单的背景压暗 / 渐变遮罩，让文字更易读；
- 一键复制元素 / 删除元素；
- 简单模板 / 样式预设只保存“样式组合”，不做模板市场。

### 初步应克制或延后的能力

- 完整 Photoshop / Canva 式图层系统；
- 贝塞尔钢笔、自由路径、复杂矢量图形；
- 大量滤镜和调色模块；
- 动画、时间轴、关键帧；
- 复杂蒙版与布尔运算；
- 内置海量素材商城；
- 重型 AI 自动生成整张封面；
- 复杂 3D / 特效文字。

判断原则：如果真实切片封面中只是偶尔出现、可以通过导入现成 PNG / 图片解决，就不优先在 AutoCover 内自己造一个编辑子系统。

## 19. 产品定位补充：速切优先，而不是精切工具

用户明确说明自己的主要工作方式是“速切”：
- 直播过程中就快速截取值得发布的片段；
- 快速剪辑；
- 添加字幕；
- 加开头 / 结尾；
- 做字幕校正；
- 做一张简单但尽量好看的封面；
- 尽快上传。

与之相对，“精切”通常会投入更多时间：
- 精细剪辑节奏；
- 大量字幕特效；
- 各种视觉特效；
- 更复杂的素材拼接；
- 更费时的封面设计；
- 追求作品级包装，而不是最快发布。

AutoSlice vNext 的目标应明确站在“速切”一侧：
- 目标不是提供完整的专业后期工作站；
- 目标不是让用户为了封面再花 20~60 分钟设计；
- 目标是让用户在几分钟内把“够用的封面”提升到“明显更好”的水平；
- AI 的价值主要是减少思考、找帧、提炼文案、给构图建议，而不是替用户生成复杂作品；
- 功能取舍必须优先考虑“是否缩短从直播片段到发布的总时间”。

因此 AutoCover 的成功指标不应只是“功能丰富”或“设计自由度高”，而应包含：
- 从字幕页切入后多久能选好封面帧；
- 多久能得到一个可发布标题；
- 多久能完成基本构图；
- 是否可以在极少点击内完成导出；
- 是否能在不增加明显认知负担的前提下，让速切封面比当前重复模板明显更好看。

## 20. 功能评审的新约束：速切成本预算

后续每个 AutoCover 功能都应同时评估“视觉收益”和“时间成本”。

可以接受：
- 1~2 秒理解、一次点击就生效的功能；
- 直接拖拽完成的操作；
- 自动保存；
- AI 给出少量可直接选用的候选；
- 可复用的个人样式 / 常用素材；
- 能显著减少重复劳动的快捷操作。

谨慎加入：
- 需要多层设置才能得到结果的工具；
- 使用频率低但长期占界面的高级参数；
- 需要用户学习复杂图层 / 蒙版 / 专业术语的能力；
- 会让用户从“快发”转变成“开始设计半小时”的功能。

后续将继续研究真实速切切片员的封面和发布节奏，再据此收缩 P0/P1/P2 功能范围。

## 21. 速切 / 精切研究后的产品结论（2026-10-01）

公开样本进一步确认，速切与精切不是单纯“剪得快 / 慢”，而是目标函数不同。

速切常见特征：
- 强调时效和发布速度；
- 单条时长普遍较短，常见几十秒到数分钟；
- 高频批量投稿，同一主播 / 事件可连续产出多条；
- 剪辑重点是找对片段、删掉冗余、字幕可读、标题抓人、封面能看；
- 包装通常克制，可重复使用固定字体、描边、布局和素材；
- 真正有价值的是“少步骤、少等待、少返工”。

精切常见特征：
- 更重视成片完整度和作品感；
- 会投入额外字幕设计、特效、转场、素材拼接、节奏处理；
- 封面也更可能做复杂人物、背景、装饰和局部设计；
- 单条视频的单位时间成本明显更高。

公开样本中可见：
- 有作者自称“光速切片”，大量账号/播放列表以 1~10 分钟直播反应片段连续发布；
- 也有作品明确把“粗切”和“精切 / 字幕 / 特效”拆给不同人员，说明精切本身就是额外后期阶段；
- 有“早上速切不小心删片段”的实例，反映速切的主要风险不是缺高级特效，而是赶时间下的错误与返工；
- 高产切片账号通常标题结构明显、视频数量极高，进一步说明批量效率和一致性很重要。

因此 AutoSlice / AutoCover 应优先服务“快速但不粗制滥造”的路线，而不是把用户引向精切工作流。

## 22. 速切导向下的 AutoCover 功能筛选

### P0：必须有，且要极快
- 从当前 playhead 直接进入封面；
- 当前时间附近候选帧；
- 一键选择背景帧；
- 背景平移 / 缩放；
- 一到三个文字块；
- 多行、字号、颜色、描边、阴影；
- 直接拖文字；
- Undo / Redo；
- 自动保存；
- 16:9 / 4:3 安全区与预览；
- 个人样式预设；
- 一键导出。

### P1：能提升质量但不应拖慢主流程
- 额外 PNG / 截图元素；
- 常用素材；
- 简单前后层级；
- AI 从长投稿标题提炼 3~5 个短封面文案；
- AI 在当前时间附近挑 3~5 张更适合的帧；
- 简单背景压暗 / 模糊 / 渐变遮罩；
- 构图预设。

### P2：暂缓或不要
- 完整 Photoshop / Canva 图层系统；
- 钢笔、自由路径、复杂蒙版；
- 大量滤镜 / 调色；
- 动画 / 关键帧；
- 模板市场 / 素材商城；
- 复杂矢量形状；
- 3D 文字；
- 重型 AI 自动生成整张封面。

关键判断：
AutoCover 的目标不是“能做出最复杂的封面”，而是让速切作者在额外 1~3 分钟内，把原本重复、随手的封面提升一个明显档次。

优先级公式可以近似理解为：
视觉收益 ÷ 额外操作时间 ÷ 学习成本。

## 23. 对当前用户工作流的直接推论

用户已有剪映负责：
- 快速剪辑；
- 开头 / 结尾；
- 字幕基础生成；
- 视频主体编辑。

AutoSlice 已负责：
- AI 字幕校对；
- 人工快速修正；
- 字幕预览与压制。

AutoCover 最合理的职责是：
- 快速选到更好的帧；
- 快速把长标题压成短封面文案；
- 快速套个人高质量样式；
- 允许少量图片 / 人物素材补充；
- 一两分钟内结束，而不是开启第二个完整设计工程。

因此任何会让用户明显进入“精切心态”的功能，都应该默认隐藏、延后，甚至直接砍掉。

## 24. 旧 AutoCover 回顾：值得保留的核心思路

旧工具虽然 UI 偏 Web 工作台、项目体系也已不适合 vNext，但里面有一批真正针对切片封面的能力，不应丢掉：

- 视频候选帧不是简单等距抽帧，而是支持“全片均匀候选 + 爆点锚点附近加密采样”；
- 候选帧有质量评分：曝光、对比度、锐度、饱和度，并额外估算烧录字幕风险；
- 对字幕风险高的候选，会尝试在 ±0.5s / ±1s 邻域寻找更干净的瞬间；
- 候选帧结果有基于视频路径 / 文件大小 / mtime / 参数的缓存；
- 支持精确时间轴选帧，不只依赖固定候选；
- 4:3 与 16:9 从一开始就是独立画布状态，并可选择同步；
- 背景焦点和背景缩放是每个比例独立保存的；
- 预览与最终成品使用同一套渲染逻辑。

## 25. 旧 AutoCover 回顾：文字与样式中最有价值的部分

旧工具并不是只把完整投稿标题盖到图上，它已经有“投稿标题 -> 封面短文案”的独立层：
- strip 统一账号前缀；
- 按标点、emoji、语义片段拆句；
- 按视觉宽度估算自动换行；
- 根据模板限制最大行数和单行宽度；
- 给文字行分配 context / quote / emphasis / neutral 语义角色；
- 支持多行独立文字，而不是单一 text box；
- 每行可以有独立文字色与描边色；
- 有多套针对直播切片的模板和配色，而不是通用设计模板。

这个方向值得保留，但 vNext 应简化成“个人样式预设 + 少数构图预设”，不要把旧模板列表原样搬进主界面。

## 26. 旧 AutoCover 回顾：AI、贴图和连续生产

旧工具已经具备一些很贴合未来 vNext 的能力：
- AI 文案是显式按钮触发，不会后台自动消耗；
- AI 读取精确任务对应的最终校对 SRT，而不是只看投稿标题；
- Luna 生成恰好 3 组候选，再由 Terra 做事实 / 爆点复核；
- 候选包含 reason、模板、配色和多行语义角色；
- AI 失败时有确定性规则回退；
- 已有本地贴图库：按主播分组、搜索、点击加入、导入本地图；
- 贴图可移动、缩放、删除，并支持简单层叠；
- 草稿不仅保留文字设置，也保留选帧、4:3/16:9 布局、贴图和预览；
- 切换任务前会立即持久化当前草稿，重开后可恢复上次编辑；
- 旧工具支持队列、排序和批量导出，说明当时已经考虑连续生产场景。

这些都比重新造一套更值得复用，但 UI 应按“速切优先”重新收口。

## 27. 旧 AutoCover 回顾：不应照搬的部分

不应直接迁移：
- 旧 CoverWorkspace 独立扫描切片目录；vNext 必须共用投稿项目体系；
- Web 工作台的三栏长期展开结构；
- 顶部大量“当前视频 / 阶段 / 上一步产物 / 下一步 / 主播 / 结果目录”的状态事实，对个人速切过重；
- 常驻模板、调色板、焦点 X/Y、背景缩放等参数面板；
- “刷新预览 / 导出当前比例 / 保存双比例”等多个显式操作，未来应由自动预览 + 顶层单一导出取代；
- 独立目录选择、标题 Markdown、manifest JSON 等工作区配置入口；
- 批量导出不是当前 vNext P0；它可以作为以后连续生产能力，但不应干扰单条速切主流程。

旧工具最值得继承的是“底层能力和速切经验”，不是它的页面结构。
