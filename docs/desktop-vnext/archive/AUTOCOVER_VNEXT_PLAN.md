# AutoCover vNext 产品与实现计划书

> 状态：2026-10-01 讨论收敛版
> 用途：作为后续 AutoCover vNext 设计与实现的主计划
> 当前阶段：冻结产品方向与交互假设，尚未要求开始大规模实现
> 原讨论记录继续保留在 `AUTOCOVER_EDITOR_PLAN.md`

## 1. 一句话定位

AutoCover vNext 不是“小 Canva”，也不是精切封面工作站。
它是 AutoSlice 的“速切提质器”：让用户在直播切片的高频生产中，几乎不增加等待和认知负担，就能把原本随手、重复的封面稳定提升一个档次。

核心目标：
- 不卡；
- 马上能做；
- 默认就能发；
- 快速不等于模板化；
- AI 只在用户主动召唤时提供变化；
- AI 永远不能挡住手工；
- 确定性系统保证下限，AI 尝试抬高上限。

## 2. 真实工作流

用户的主要工作方式是“速切”：
- 直播过程中发现值得发布的片段；
- 在剪映快速剪辑、加开头结尾、生成基础字幕；
- 在 AutoSlice 做字幕 AI 校对和人工修正；
- 同时或随后进入 AutoCover 快速制作封面；
- 保存字幕、压制、上传 Bilibili。

“精切”不是当前主要目标。
精切通常意味着复杂字幕特效、视觉包装、素材拼接、节奏处理和长时间封面设计。

AutoCover 不应把用户诱导进精切工作流。
它的价值是：在额外几十秒到几分钟内，让速切封面明显更好，而不是把速切变成第二个设计工程。

## 3. 成功标准

按优先级：
1. 切项目和进封面页时不卡。
2. 很快出现一个可编辑、可发布的基础封面。
3. 普通封面约 30~60 秒完成，想做好一点约 1~3 分钟。
4. 默认方案至少不能比旧 AutoCover 的“能用”水平更差。
5. 连续投稿时减少明显重复。
6. AI 可选，不是前置依赖。
7. AI/分析失败后仍可立即继续手工。

## 4. 设计总原则

### 4.1 固定流程，不固定结果
速切需要流程稳定，但视觉结果不能长期重复。
可以稳定的是字体体系、描边语言、少量颜色和操作方式；
应该变化的是构图、主体位置、标题区域、文字块数量、图片元素组合和画面选择。

### 4.2 画布优先
中心画布是主对象，参数表单不是主对象。
高频操作直接发生在画布上，属性面板只在需要时出现。

### 4.3 阶段上下文 + 对象上下文
阶段上下文决定“现在是在选帧、构图还是输出”。
对象上下文决定“当前编辑的是标题、背景、图片元素还是画布本身”。

### 4.4 先立即可用，再渐进变聪明
项目打开后先提供当前帧和基础封面；
候选帧、评分、字幕风险、AI 结果在后台逐步补充。
智能功能绝不能成为手工操作的阻塞点。

### 4.5 功能要敢删
“能做”不是加入功能的理由。
低频、学习成本高、会长期占界面或容易把用户拖进精切的功能，应延后、隐藏或直接砍掉。

## 5. 第一分钟体验（已明确）

用户进入 AutoCover 后最先需要的是：
**不卡、简单直接选帧、根据投稿标题先放一个还可以的封面文字。**

### 0~1 秒
- 瞬间切换到当前项目；
- 显示字幕页当前 playhead 对应画面，或缓存中的最近可用画面；
- 使用确定性逻辑生成一份基础封面文案；
- 套用最近/默认个人样式；
- 画布立即可拖、可改字、可导出；
- 不等待 AI，不等待全片候选评分。

### 随后几秒
- 当前时间附近候选帧逐张补齐；
- 精确选帧条可用；
- 缓存存在时直接复用；
- 后台可低优先级补充更远候选或质量信息。

### 用户不调用 AI 时
AutoCover 仍必须是一套完整、快速、好用的封面工具。
AI 不是完成任务所必需的依赖。

## 6. 主界面骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ 当前项目          ↶  ↷          画布缩放        [导出]      │
├────┬───────────────────────────────────────────────┬─────────┤
│ 帧 │                                               │         │
│ 图 │                  大 画 布                      │  上下文 │
│ 字 │                                               │  属性   │
│ ✨ │                                               │         │
├────┴───────────────────────────────────────────────┴─────────┤
│          可收起的候选帧 / 精确选帧条                         │
└──────────────────────────────────────────────────────────────┘
```

左侧仅保留窄入口：
- 帧：候选帧 / 精确选帧；
- 图：常用素材、最近素材、导入图片；
- 字：新增/选中文字；
- ✨：用户主动召唤 AI。

全局“投稿项目”区域在封面编辑时允许弱化或折叠。
顶层只放文档级操作：Undo、Redo、画布缩放、保存状态、导出。

## 7. 画布与对象交互

### 7.1 标题
- 点击选中；
- 拖动移动；
- resize handle 或上下文控件调整大小；
- 方向键微调；
- 对齐到画布中心与安全线时轻量吸附；
- 选中时显示边界框，不选中时保持干净。

### 7.2 背景
背景不应始终“拖哪儿都能动”。
建议使用明确的“调整构图”状态：
- 平时点击背景只代表选中；
- 进入调整构图后，拖动=平移，滚轮=缩放；
- Enter/完成提交，Esc/取消回退；
- 状态栏动态提示当前操作。

### 7.3 图片元素
- 添加后可拖动、缩放、删除；
- 支持简单前移/后移；
- 第一阶段不做复杂蒙版、混合模式或完整图层系统。

### 7.4 Undo / Redo
P0 必须支持，并覆盖标题、背景、图片、样式、文案和换帧。

## 8. 选帧：重新定义旧版能力

旧 AutoCover 的选帧属于“能用”，但用户实际体验并不觉得特别聪明。
因此 vNext 不再把“自动选帧评分”当主角。

真正的主体验：
- 当前 playhead 立即可用；
- 附近帧快速出现；
- 一眼能连续浏览；
- 点击即选；
- 能迅速前后微调；
- 精确选帧不需要等待整段分析。

旧版可复用为后台辅助：
- 全片均匀候选；
- 爆点锚点附近加密采样；
- 曝光、对比度、锐度、饱和度评分；
- 烧录字幕风险估算；
- 在 ±0.5s / ±1s 邻域找更干净画面；
- ffmpeg/ffprobe 缓存与源文件身份校验。

原则：后台能力只能“补推荐”，不能锁住 UI。

## 9. 性能与渐进式计算（P0）

旧 AutoCover 切项目时会因为自动选帧卡住，这是必须消灭的问题。

推荐执行层级：
1. 立即：切换项目状态、显示缓存/当前帧、加载草稿；
2. 优先后台：生成当前 playhead 附近少量缩略图；
3. 低优先级后台：生成全片候选、质量评分、字幕风险；
4. 用户召唤后：才运行 AI。

强制规则：
- ffmpeg、ffprobe、图像分析、AI 全部不在 UI 线程；
- 项目切换后，旧项目回调通过 generation/task id 失效；
- 新项目不能等待旧项目任务结束；
- 有缓存先显示缓存；
- 缩略图允许渐进填充；
- 后台失败只显示局部错误，不禁用画布；
- 预览可防抖，但拖动过程必须跟手。

## 10. 文案：旧逻辑需要重做

旧版已经区分“投稿标题”和“封面文案”，但实际主要是：
长标题拆句、完整截取、自动换行。
它解决了排版，不真正解决“封面应该写什么”。

vNext 的确定性基础文案应做到：
- 去掉账号统一前缀；
- 优先提取标题中的核心短句、原话或最明显事件点；
- 控制为 1~3 个短文字块；
- 自动限制单行宽度与行数；
- 默认宁可少字，不把完整长标题铺满画面；
- 用户可直接覆盖，不和投稿标题双向绑定。

旧版可继续复用：
- visual_units；
- 中文/emoji 安全换行；
- 多行独立位置；
- 每行独立文字色/描边色；
- context / quote / emphasis / neutral 等语义角色思想。

旧“自动拆句=封面文案”不再视为最终产品方案。

## 11. 文字系统

AutoCover 应把精力更多放在文字，而不是复杂图形工具。

P0：
- 1~3 个独立文字块；
- 多行；
- 字体；
- 字号；
- 字色；
- 描边颜色与粗细；
- 阴影；
- 行距；
- 对齐；
- 最大宽度；
- 画布直接拖动/缩放；
- 安全区与中心吸附。

P1：
- 关键词局部强调；
- 快速复制文字块；
- 少量个人文字样式预设。

默认不提供：
- 3D 文字；
- 大量艺术字特效；
- 复杂路径文字；
- 专业排版工作站。

## 12. 素材与图片系统

旧版贴图库方向有价值，但需要从“全部素材平铺”改成“真正顺手”。

入口优先顺序：
1. 最近使用；
2. 手动收藏/置顶的常用素材；
3. 当前主播相关素材；
4. 全部素材与搜索；
5. 导入本地图；
6. 后续可考虑拖入文件和剪贴板粘贴。

系统可默默统计使用频率，但不能要求用户整理素材库。
高频主播表情包应自然越来越靠前；低频素材不占主要空间。

图片元素第一阶段只做：
- 添加；
- 拖动；
- 缩放；
- 删除；
- 复制；
- 简单前后层级。

如果某效果可通过导入 PNG 解决，就不急着开发专业子系统。

## 13. 4:3 / 16:9 双比例

旧版这一点总体成功，应继续保留并优化。

底层：
- 4:3 与 16:9 共用同一组内容对象；
- 每个比例允许独立保存背景焦点、缩放和少量位置覆盖；
- 默认可同步修改；
- 必要时可解除同步做比例专属微调。

交互优化：
- 以一个比例作为主画布；
- 第二比例持续提供小预览/风险提示；
- 只有发现裁字、主体被截或构图明显失衡时，才要求用户切过去微调；
- 不要求用户每次手动来回检查两个 tab。

自动检查：
- 文字是否超安全区；
- 主体/关键词是否被 4:3 裁掉；
- 第二比例是否存在明显布局风险。

“导出”仍是一个文档级动作，而不是多个比例各一个保存按钮。

## 14. 自动保存、草稿与导出

### 自动保存
草稿持续自动保存。
不保留“保存草稿”作为主要操作。
只弱提示：正在保存 / 已保存 / 保存失败。

### 草稿保存内容
- 当前选帧；
- 4:3 / 16:9 布局；
- 背景焦点/缩放；
- 文字块；
- 图片元素；
- 当前样式；
- 必要的缓存引用。

### 导出
- 顶层只有一个清晰的“导出”动作；
- 预览和最终 JPG 必须共享同一渲染逻辑；
- 保留安全递增命名；
- 不因缓存删除破坏正式产物。

### 连续生产
切项目前立即持久化当前草稿；
恢复上次项目时不重新做无意义分析；
未来可考虑“导出后切下一条”，但不是第一阶段必做。

## 15. AI 总原则（已冻结）

AI 默认不参与。
只有用户主动召唤时才调用。

AI 不能：
- 阻塞手工；
- 自动替用户应用最终方案；
- 让用户为了等 AI 停止工作；
- 以“创新”为理由破坏基本可读性；
- 把整张封面交给不可控的重型生成模型作为默认路线。

AI 应该：
- 提案；
- 提供变化；
- 帮用户摆脱重复；
- 允许明确下判断；
- 在没有更好方案时承认“没有明显更优方案”。

确定性系统负责保证下限；
AI 负责尝试抬高上限。

## 16. AI 方案交互（本轮冻结）

用户点击：
**✨ 给我几个方案**

系统展示 3 张真正渲染出来的完整封面候选，而不是只给文字说明。

三个候选的风险角色：
- **稳妥**：接近已验证风格，目标是至少不比基础封面差；
- **换个构图**：保持账号视觉语言，但明显避开近期重复；
- **大胆一点**：允许更明显的构图、素材或配色变化，但仍需通过基本质量检查。

每张只附一句很短的差异说明。
系统必须明确推荐其中一个，不能用“各有优点”逃避判断。
推荐只是推荐，用户自己点击“使用”。

如果都不喜欢：
- 用户可直接关闭继续手工；
- 可选提供“太花 / 太像以前 / 文案不对 / 画面不对”等快速反馈；
- 反馈不是必填。

## 17. AI 不是“一次全改”

AI 不应该每次同时：
换帧 + 换标题 + 换字体 + 换配色 + 加贴纸 + 改布局。

更合理的流程：
1. 先判断当前基础封面最大问题；
2. 再围绕主要问题产生候选变化；
3. 保留其它已经不错的部分。

例如：
- 构图重复 -> 重点换布局；
- 文案过长 -> 重点改短文案；
- 当前帧表情弱 -> 重点换帧；
- 背景太乱 -> 重点处理构图/压暗；
- 最近作品太相似 -> 优先制造结构变化。

这样用户能理解方案为什么变化，也更容易应用后继续微调。

## 18. AI 审美与质量控制

不能把“审美”简化成一个玄学分数。

先由本地规则淘汰明显坏的方案：
- 字超安全区；
- 4:3 裁掉关键词；
- 文字/图片互相重叠；
- 主体明显被挡；
- 标题过长；
- 对比度太差；
- 与基础封面相比明显退化；
- 与最近作品结构几乎完全相同。

视觉模型更适合做相对比较，而不是绝对评分：
- A/B 哪张缩略图更易读；
- 哪张第一眼焦点更明确；
- 哪张人物遮挡更少；
- 哪张和近期封面重复更低；
- 哪张标题信息量更合适。

如果 AI 没有明显更优结果，可以直接返回“这次没有明显更优方案”。

## 19. 反重复：一致但不重复

AutoCover 的目标不是每天随机一个新风格。
目标是：账号视觉语言稳定，但连续作品不要像同一张模板。

可为每张封面保存轻量“设计指纹”：
- 背景类型；
- 主体大致位置；
- 文字块数量；
- 文字区域；
- 字号等级；
- 主色；
- 图片/贴图数量；
- 构图类别。

系统本地统计最近若干封面的结构分布。
例如最近 10 张中 8 张“左字右人”，下一次 AI 提案就主动降低该结构权重。

反重复默认在后台发生，不要求用户管理。
它是 AI 的约束之一，而不是用户额外的一步。

## 20. 默默学习用户，而不是训练用户

用户明确不希望为了“教 AI”浪费时间。
第一阶段不做复杂在线学习或训练流程。

可被动记录：
- 用户最终选择哪个 AI 方案；
- AI 文案被改了多少；
- AI 放的图片/贴纸是否被删除；
- 元素最后被拖到什么区域；
- 哪些素材高频使用；
- 哪些配色/文字样式经常保留；
- 哪类方案经常被完全放弃。

第一版甚至只需要本地偏好统计 / JSON，不需要机器学习模型。
所有学习必须：
- 静默；
- 本地优先；
- 不影响正常编辑；
- 不增加必填评分；
- 可随产品成熟再决定是否升级。

## 21. “好封面”的暂定评价框架

当前不做单一“封面评分”。

### 第一层：硬错误
由程序自动检查：
- 文字可读性；
- 安全区；
- 双比例裁切；
- 主体遮挡；
- 元素越界；
- 明显重复。

### 第二层：传播表达
AI 可辅助判断：
- 情绪是否明确；
- 第一眼能否理解发生了什么；
- 梗点/冲突是否突出；
- 标题是否过载；
- 主体和文字是否有清楚视觉关系。

### 第三层：长期主页观感
关注：
- 是否连续高度重复；
- 是否保持账号风格；
- 是否适度出现新的构图和素材关系。

这一框架后续通过真实使用再调整，不提前过度理论化。

## 22. 旧 AutoCover：保留、重做、淘汰

### 保留底层思想
- 候选帧缓存与评分；
- 爆点附近加密采样；
- 字幕风险回避；
- 精确选帧；
- 中文/emoji 换行；
- 多行独立文字；
- 对齐吸附；
- 4:3 / 16:9 独立状态；
- 本地贴图库；
- 草稿恢复；
- 预览/导出一致。

### 重做产品层
- 自动选帧：从“主流程等待”改成后台辅助；
- 标题拆分：从“截取长标题”改成真正的封面短文案；

### Phase A：先重建编辑器骨架
只重构 AutoCover UI/交互骨架：

- 左侧轻量入口；
- 可收起帧条；
- 上下文属性栏；
- 不再美化旧参数表单。

### Phase B：接回已验证功能
- 真实 MP4 取帧；
- 当前 playhead 交接；
- 导入图片；
- 标题/背景拖动；
- 背景缩放；
- 草稿；
- 导出；
- 预览/导出一致。

### Phase C：性能与选帧
- 渐进式缩略图；
- 切项目取消/失效旧任务；
- 缓存优先；
- 精确选帧；
- 后台复用旧选帧算法。

### Phase D：文字、素材、双比例
- 1~3 文字块；
- 文字样式；
- 常用素材；
- 图片元素；
- 双比例优化。

### Phase E：AI 假原型
先不接完整 AI。
用人为准备/确定性生成的 3 个方案模拟：
- 稳妥；
- 换个构图；
- 大胆一点。

目的：验证“看三张完整图 -> 选一张 -> 微调”这个交互本身是否顺手。
如果流程本身让用户烦，就不投入复杂 AI。

### Phase F：再接真实 AI
只有在 Phase E 交互验证通过后：
- 先接最小成本的结构化方案生成；
- 控制超时；
- 结果异步返回；
- 不阻塞手工；
- 后续再考虑视觉复核与偏好学习。

## 26. 设计红线

后续实现不得违反：
1. 字幕模块已冻结，AutoCover 不得破坏其现有语义。
2. AutoCover 切换不能 seek / pause / 修改字幕页状态，除非用户明确操作。
3. 后台任务不得占住 UI。
4. AI 默认不自动调用。
5. 缓存删除不能破坏正式输出。
6. 不因“功能丰富”重新长回旧 Web 工作台。
7. 不因“追求变化”牺牲速切速度与可读性。
8. 不因“追求安全”把 AI 限制成永远只会同一模板。

## 27. 冻结决策清单

截至本版计划，已经可以视为冻结的方向：
- AutoCover = 速切提质器，而不是精切工具；
- 第一分钟体验以“不卡 + 立即能做”为第一优先；
- AI 由用户主动召唤；
- AI 结果以 3 张完整可视化候选呈现；
- 三候选分别承担“稳妥 / 换个构图 / 大胆一点”；
- AI 必须推荐一个，但不自动应用；
- 如果没有明显更优方案，可以不硬凑；
- 用户最终拍板；
- 反重复和偏好学习应尽量静默；
- 旧 AutoCover 的底层能力是矿山，旧页面结构不是目标；
- 选帧算法保留为后台辅助，不再成为阻塞主流程；
- 旧 AI 文案流程不作为 vNext 主 AI 方案；
- 对齐吸附继续保留；
- 4:3 / 16:9 继续保留并优化；
- 素材库改为最近 / 常用 / 当前主播优先。

## 29. 基础封面默认行为补充（2026-10-01 冻结）

用户已明确：
- 默认允许自动生成最多 **2 个独立文字块**；
- 默认主画布为 **4:3**；
- 16:9 作为第二比例持续预览 / 风险检查；
- 继承上一张的“视觉语言”，不继承具体构图。

“视觉语言”可继承：
- 字体；
- 常用字号层级；
- 文字颜色；
- 描边颜色 / 粗细；
- 阴影；
- 行距；
- A/B 的层级关系（例如 A 较小、B 较大）。

不继承：
- 具体 X/Y；
- 视频帧；
- 背景焦点；
- 文案；
- 素材 / 贴图；
- 上一张的具体构图。

### 两块文字的定义

最多两块，但不强制两块。

- **A = 让 B 成立所需的最少上下文**；
- **B = 最值得占据视觉注意力的信息**。

A 可能是背景、诱因、对方原话、问题、对象或时间。
B 优先为强原话、强梗、荒诞结果、强情绪反应或异常事件。

若 B 单独已经成立，则只生成 B。
基础模式只做“抽取 + 压缩”，不允许凭空改写事实。
AI 被用户主动召唤后，才拥有重新概括 / 改写文案的权限。

### 基础自动摆放

文案系统只决定“说什么、谁强谁弱”，构图系统决定“放哪里”。
第一版基础排版只使用少量可靠安全关系：
- 左侧文字 / 右侧留主体；
- 右侧文字 / 左侧留主体；
- 上方文字 / 中下留主体；
- 下方文字 / 中上留主体；
- 单 B 的居中偏上 / 偏下。

位置由当前帧空区 / 复杂度决定；近期使用记录用于平局时避免连续重复。

### 基础文案候选

本地确定性系统可为同一标题瞬间生成 2~4 套“抽取型”文案组合，但默认只展示其认为最优的一套。
用户可用轻量“换文案”操作在这些组合间循环，不调用 AI。

基础文案优先级暂定：
强原话 > 荒诞 / 反差结果 > 强情绪反应 > 数字 / 异常事件 > 普通事件描述 > UP 主总结评价。

该规则不视为最终真理，必须通过真实标题黄金测试集迭代。

## 30. 基础构图黄金集与自动摆放方向（2026-10-01）

下一阶段把“文字放哪里”从抽象讨论压成可测试规格。

基础系统的目标不是做复杂视觉理解，而是：
- 识别画面中哪些区域最不适合盖字；
- 在少量可靠安全布局中选一个；
- 让 A/B 的视觉层级稳定；
- 在多个同样合理的位置之间，用近期历史做轻量反重复；
- 全过程不阻塞项目切换和画布编辑。

原则：
- **文案系统决定说什么、谁强谁弱；构图系统决定放哪里。**
- 4:3 是主画布，16:9 同步检查；
- 默认构图只能做保守、可靠的事；
- AI 方案才允许突破基础槽位。

### 基础构图候选关系

第一版只保留少量“关系原语”，而不是模板库：
1. 左侧文字 / 右侧留主体；
2. 右侧文字 / 左侧留主体；
3. 上方文字 / 中下留主体；
4. 下方文字 / 中上留主体；
5. 单 B 居中偏上；
6. 单 B 居中偏下；
7. A/B 分置两侧（仅双人 / 对话 / 两个明确视觉主体时）。

A/B 同时存在时：
- B 永远是视觉主块；
- A 尺寸与面积明显弱于 B；
- A 可以贴近 B，也可以作为独立上下文放到另一安全区域；
- 不允许默认生成两个同等重量的大字块。

### 基础区域评分
初版可以只看：
- 局部边缘/纹理复杂度；
- 明暗与文字对比潜力；
- 是否靠近安全区边缘；
- 是否覆盖明显高显著性主体；
- 是否会在 16:9 同步视图中产生明显越界；
- 最近若干封面是否刚连续使用同类布局。

若多个位置分数相近，优先选择近期使用更少的布局。
