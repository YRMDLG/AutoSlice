# 配置说明

本文是面向安装者和维护者的参考手册，说明公开版的平台、依赖、媒体格式、LLM 代理、目录、主播 profile、任务历史、安全边界、FunASR、字幕和 AutoCover 配置。所有示例都使用占位值，请在本机替换，不要把真实 token 写进 Git。

## 1. 平台与能力边界

| 平台 | 支持级别 | 说明 |
|---|---|---|
| Windows 10/11 | 完整主平台 | 支持统一启动器、Windows 隔离 CUDA 运行时、FFmpeg/ffprobe、本机字体、剪映衔接、字幕压制和 AutoCover 完整媒体工作流。|
| Linux | 纯逻辑 CI / 部分 CPU 代码路径 | CI 只安装 Flask 与 requests，并运行架构、解析、评分、标题、路径和任务存储等显式白名单；不验证 Windows CUDA 隔离运行时、剪映、本机字体、FFmpeg 媒体处理或完整端到端工作流。|
| macOS | 未验证 | 没有 CI 或完整媒体验收，不承诺 GPU、字体、启动器和端到端媒体兼容性。|

Linux 上的 `Linux logic only (no media support)` GitHub Actions job 只是跨平台纯逻辑护栏，**不代表完整 Linux 支持**。正式媒体工作流以 Windows 10/11 为准。

## 2. 安装依赖

在项目根目录执行：

```powershell
python --version
python -m pip install --upgrade pip
python -m pip install -e .
```

这会按 `pyproject.toml` 安装统一依赖并提供 `autoslice`、
`autoslice-cover` 命令；原有
`python 启动.py` 入口保持不变。只想沿用旧安装方式时仍可执行
`python -m pip install -r requirements.txt`。只单独运行 AutoCover 时才需要
它自己的 `autocover_tool/requirements.txt`。

依赖按实际安装边界声明：

| 来源 | 实际依赖 | 说明 |
|---|---|---|
| `pyproject.toml` | `Flask`、`Pillow`、`FunASR`、`soxr`、`python-docx`、`requests` | 统一安装与 `autoslice`/`autoslice-cover` 命令的权威声明 |
| `requirements.txt` | 与 `pyproject.toml` 同步的运行依赖 | 兼容旧脚本和手动安装流程 |
| `pyproject.toml` 的 `asr-cpu` 可选组 | `torch` | 当前 Python 缺少 CPU FunASR 运行依赖时安装；不会把 GPU Torch 放入通用依赖 |
| `autocover_tool/requirements.txt` | `Flask>=3.0,<4.0`、`Pillow>=10.0,<13.0` | 仅供 AutoCover 独立运行 |
| `setup_gpu_runtime.py` | 隔离 GPU 运行时中的 `torch` 依赖 | 只用于 64 位 Windows 的受控 CUDA 环境，不应加入通用根依赖 |
| 系统安装 | `ffmpeg`、`ffprobe` | 外部可执行程序，不是 Python 包 |

`ffmpeg` 与 `ffprobe` 必须单独安装并加入 `PATH`：

```powershell
Get-Command ffmpeg
Get-Command ffprobe
```

两个命令都能找到可执行文件后，视频探测、切片、候选帧提取和字幕压制才具备完整条件。GPU 不是必需项；不要为了 CPU 使用场景手工把 `torch` 写入根 `requirements.txt`。当前 Python 如果缺少 CPU FunASR 所需的 PyTorch，请安装 `asr-cpu` 可选组；隔离 CUDA 运行时只在明确启用 GPU 时安装匹配的 Torch wheel。

如果运行时提示缺少 PyTorch，可以按当前设备选择安装方式：

```powershell
# 当前 Python 使用 CPU FunASR
python -m pip install -e ".[asr-cpu]"

# 使用项目提供的隔离 CUDA 运行时
python setup_gpu_runtime.py
```

安装元数据可用以下命令做无启动检查：

```powershell
python -B scripts\smoke_packaging.py
python -B scripts\verify_distribution.py
python 启动.py --help
autoslice --help
```

`smoke_packaging.py` 检查当前安装的元数据、命令入口和包资源；
`verify_distribution.py` 会从待发布文件构建 wheel，在临时 Python 3.10 环境中
安装，并从仓库外运行 AutoSlice/AutoCover 帮助入口。该验收还会确认模板、
静态资源和 JSON 已随 wheel 分发，帮助和导入过程不会向 `site-packages` 写入
配置、SQLite、缓存或用户素材。临时环境完成后自动清理，不读取本机 API token。

### 支持的录播容器

录播扫描、分析、精确切片和字幕工作台输入统一支持 `.flv`、`.mp4`、`.mkv`、`.mov`、`.avi`，扩展名大小写不敏感。精确切片会重新编码视频流、尽量直接复制音频流，并默认保留源容器后缀：MP4 输入优先输出 MP4，MKV 输入优先输出 MKV。为了读取旧版本生成的结果，非 FLV 源仍兼容历史 `.flv` 切片；这只是兼容查找，不代表新任务会统一改成 FLV。字幕压制输出仍以 MP4 为主。

## 3. API 与代理配置

复制示例：

```powershell
Copy-Item api_config.example.json api_config.json
```

如果要使用 `python setup_asr_model.py` 下载推荐模型，先安装模型下载器：

```powershell
python -m pip install -e ".[asr-models]"
```

最小配置如下：

```json
{
  "base_url": "https://api.example.com/v1",
  "token": "YOUR_API_TOKEN",
  "model": "gpt-5.6-terra",
  "api_type": "openai"
}
```

### `base_url` 的填写规则

`base_url` 必须是 API 的 HTTP(S) 根地址，例如 `https://api.example.com/v1`。不要填写完整的 `/chat/completions`、`/messages` 或带 token 的 URL。程序会根据协议自动追加路径：

- `api_type: "openai"`：追加 `/chat/completions`，使用 `Authorization: Bearer ...`。
- `api_type: "anthropic"`：追加 `/messages`，使用 `x-api-key` 和 Anthropic 版本请求头。

服务商必须提供对应的兼容协议；“看起来像 OpenAI”的地址不代表一定支持 JSON 输出或指定模型。

### 模型分工

- `model` 是配置文件中的默认模型，主要用于候选复核、标题和最终投稿价值判断。
- `AUTOSLICE_ANALYSIS_MODEL` 控制首轮整场分块分析，默认是 `gpt-5.6-luna`。
- `AUTOSLICE_LLM_MODEL` 控制复核和需要更强判断的阶段，默认是 `gpt-5.6-terra`，也会覆盖配置文件中的 `model`。

例如：

```powershell
$env:AUTOSLICE_API_BASE_URL = "https://api.example.com/v1"
$env:AUTOSLICE_API_TOKEN = "YOUR_API_TOKEN"
$env:AUTOSLICE_API_TYPE = "openai"
$env:AUTOSLICE_ANALYSIS_MODEL = "gpt-5.6-luna"
$env:AUTOSLICE_LLM_MODEL = "gpt-5.6-terra"
python 启动.py
```

API 配置按以下优先级解析：

1. 只要显式设置了 `AUTOSLICE_API_BASE_URL`、`AUTOSLICE_API_TOKEN`、`AUTOSLICE_API_TYPE` 中任意一项，就选择环境变量作为 API 来源；这三项必须完整，不能再从 `api_config.json` 混补。
2. 未设置上述 API 环境变量时，读取项目内已忽略的 `api_config.json`。
3. `AUTOSLICE_LLM_MODEL`、推理强度变量和 `AUTOSLICE_LLM_PROXY_*` 在各自字段上优先于 `api_config.json`。

程序不会自动加载仓库中的 PowerShell 示例；请复制为已忽略的本机文件后再编辑和加载：

```powershell
Copy-Item environment.example.ps1 environment.local.ps1
notepad environment.local.ps1
. .\environment.local.ps1
```

### LLM 代理模式

`proxy_mode` 只支持 `direct`、`system`、`custom`：

| 模式 | `requests` 行为 | 适用场景 |
|---|---|---|
| `direct` | 默认值；专用 `Session` 设置 `trust_env=False`，忽略 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` | API 可直连，或不希望系统/开发工具代理影响 AutoSlice |
| `system` | `Session.trust_env=True`，使用 requests 识别的环境代理配置 | 当前 PowerShell/系统代理已经正确配置 |
| `custom` | `trust_env=False`，只传入 AutoSlice 明确配置的 HTTP(S) 代理 | 只让 LLM 请求经过专用代理，不继承其他进程代理 |

默认 `api_config.example.json` 使用 `direct`。配置文件示例：

```json
{
  "base_url": "https://api.example.com/v1",
  "token": "YOUR_API_TOKEN",
  "model": "gpt-5.6-terra",
  "api_type": "openai",
  "proxy_mode": "custom",
  "http_proxy": null,
  "https_proxy": "http://proxy.example.com:8080"
}
```

也可以使用环境变量；环境变量覆盖同名 `api_config.json` 字段：

```powershell
$env:AUTOSLICE_LLM_PROXY_MODE = "custom"
$env:AUTOSLICE_LLM_PROXY_HTTPS = "http://proxy.example.com:8080"
python 启动.py
```

`custom` 至少要配置 `AUTOSLICE_LLM_PROXY_HTTP`/`http_proxy` 或 `AUTOSLICE_LLM_PROXY_HTTPS`/`https_proxy` 之一。代理值必须是 HTTP(S) URL，不接受代理端点路径、查询参数或片段；请为 API 实际使用的协议配置对应代理。URL 可以包含代理认证信息，但不要把认证 URL 提交到 Git、粘贴到 issue 或截图中。配置对象、mock 输出和 requests 异常会脱敏代理凭据，但脱敏日志不能代替安全保管。

token 只放在本地配置或当前 PowerShell 会话中；不要直接修改并提交示例文件，也不要把 token 写入 README、截图、日志或提交记录。

AutoSlice 不会读取 `Claude`、`Codex`、编辑器插件或其他项目的配置文件，也不会自动寻找别的 API key。发送给模型的内容只包括当前任务需要的字幕、有限弹幕摘要和可选时间轴线索。

## 4. 目录环境变量

默认目录都在项目根目录下：

| 环境变量 | 默认目录 | 用途 |
|---|---|---|
| `AUTOSLICE_VIDEO_DIR` | `recordings` | 录播扫描目录 |
| `AUTOSLICE_OUTPUT_DIR` | `output` | 报告、JSON、自动切片 |
| `AUTOSLICE_TIMELINE_DIR` | `timelines` | 人工时间轴 DOCX |
| `AUTOSLICE_SUBMISSION_DIR` | `submissions` | 字幕校对与投稿素材 |
| `AUTOSLICE_REFINEMENT_QUEUE_DIR` | `output` | 精调任务清单 |
| `AUTOSLICE_TITLE_STYLE_PROFILE` | 示例配置 | 私人标题风格样本 |
| `AUTOSLICE_STREAMER_PROFILES` | `streamer_profiles.json` | 主播称呼、标题前缀和 ASR 规则 |
| `AUTOCOVER_INPUT_DIR` | `output` | AutoCover 默认切片目录 |
| `AUTOCOVER_OUTPUT_DIR` | `covers` | AutoCover 封面输出目录 |
| `AUTOCOVER_STICKER_DIR` | `stickers` | 本机贴图库 |
| `AUTOCOVER_FONT_PATH` | 未配置 | AutoCover 本机字体文件 |

应用根与可写状态另有明确边界：

| 变量 | 用途 |
|---|---|
| `AUTOSLICE_WORKSPACE_DIR` | 显式指定源码工作区；主要用于开发、多 worktree 或受控部署 |
| `AUTOSLICE_USER_DATA_DIR` | 安装包脱离源码仓库运行时的 AutoSlice 用户数据根 |
| `AUTOSLICE_STATE_DIR` | 覆盖任务 SQLite 与事件状态目录 |
| `AUTOSLICE_TASK_DB` | 只覆盖任务数据库文件，优先级高于状态目录默认值 |
| `AUTOCOVER_DATA_DIR` | 安装态 AutoCover 的缓存、默认输入输出与本地素材数据根 |

源码克隆模式继续把 `autoslice.local.json`、`api_config.json` 和
`.autoslice-state` 放在仓库根目录，兼容现有使用方式。安装包无法发现源码工作区
时，默认改用当前用户的数据目录，不会尝试向 `site-packages` 写配置、SQLite 或
缓存。Flask 模板和静态文件始终从包资源或已识别的源码工作区定位，不依赖启动
命令的当前目录。

PowerShell 示例：

```powershell
$env:AUTOSLICE_VIDEO_DIR = "$HOME\直播录播"
$env:AUTOSLICE_OUTPUT_DIR = "$HOME\自动切片结果"
$env:AUTOCOVER_OUTPUT_DIR = "$HOME\封面"
$env:AUTOCOVER_STICKER_DIR = "$HOME\表情包"
$env:AUTOCOVER_FONT_PATH = "$HOME\字体\seto-bilibili.ttf"
python 启动.py
```

路径可以是绝对路径，也可以在代码中通过环境变量传入；公开仓库本身不预设任何个人盘符。标题风格需要私人样本时，复制 `title_style_profile.example.json` 为本地的 `title_style_profile.json` 后再修改，私有文件不会被 Git 跟踪。

### 本机私有目录配置（推荐）

不想在每次打开 PowerShell 时重复设置目录环境变量，可复制仓库根目录的示例文件：

```powershell
Copy-Item autoslice.local.example.json autoslice.local.json
notepad autoslice.local.json
```

`autoslice.local.json` 只接受代码白名单中的本机非秘密设置，包括本节目录/字体变量、FunASR 设备与热词，以及 `AUTOSLICE_LLM_PROXY_MODE`、`AUTOSLICE_LLM_PROXY_HTTP`、`AUTOSLICE_LLM_PROXY_HTTPS`。它已被 Git 忽略，不会被提交；优先级为“当前 PowerShell 中显式设置的环境变量” > “`autoslice.local.json`” > “仓库内公开默认值”。需要为多个实例或自动测试隔离本机配置时，可把 `AUTOSLICE_LOCAL_CONFIG` 设为另一个 JSON 文件路径；它只改变配置文件位置，不会放宽可读取字段。API token 仍只应放在 `api_config.json` 或当前会话环境变量中，不能写进该文件。

## 5. 服务访问边界

旧版“高级重新切片”页面和 `/api/slice` 默认关闭，不会出现在导航中。只有需要兼容历史 JSON/DOCX 直切操作时，才在启动前临时设置：

```powershell
$env:AUTOSLICE_ENABLE_LEGACY_DIRECT_SLICE = "1"
python 启动.py
```

日常分析应继续使用首页的智能分析流水线。该兼容开关不影响录播扫描、人工时间轴辅助、字幕工作台或 AutoCover。

默认启动不需要任何网络安全配置，AutoSlice 和 AutoCover 都只供本机访问。AutoSlice 默认绑定 `127.0.0.1`，只接受 loopback Host，并拒绝跨站写请求。浏览器通过仅保存在内存中的随机 HttpOnly Cookie 建立本机会话；会话绑定协议、Host 和端口，写请求还必须提供同源 Origin/Referer 或有效会话。服务重启后旧会话失效，重新加载页面即可建立新会话。

只有明确需要从局域网其他设备访问 AutoSlice 时，才启用高级 LAN 模式：

```powershell
$env:AUTOSLICE_LAN_MODE = "1"
$env:AUTOSLICE_LAN_TOKEN = "REPLACE_WITH_AT_LEAST_32_RANDOM_CHARACTERS"
$env:AUTOSLICE_LAN_HOSTS = "192.168.1.20"
$env:AUTOSLICE_LAN_ORIGINS = "http://192.168.1.20:5002"
$env:AUTOSLICE_ALLOWED_ROOTS = "$HOME\直播录播;$HOME\自动切片结果"
python 启动.py
```

- `AUTOSLICE_LAN_TOKEN` 必须是至少 32 个字符的强随机 token；短 token 或明显重复的占位符会使 LAN 配置失效；
- `AUTOSLICE_LAN_HOSTS` 是允许出现在请求 Host 中的主机名或 IP，可用分号分隔；
- `AUTOSLICE_LAN_ORIGINS` 是允许发起写请求的完整来源，包含协议和端口；
- `AUTOSLICE_ALLOWED_ROOTS` 必须列出显式的绝对路径根目录，并限制 LAN 请求可扫描、读取或写入的范围；
- AutoCover 仍保持本机 loopback 服务，不应直接暴露到局域网。

LAN 模式不等于公网部署方案。不要直接做路由器端口映射；需要跨网络访问时，应使用带 HTTPS 和额外认证的反向代理或 VPN。

## 6. 主播识别与投稿标题前缀

仓库默认的 `generic` profile 只包含通用词表和通用行为，不带泽音标题前缀、泽音专名、固定错词映射、专属收播规则或私人标题样本。无法可靠识别主播时必须保持 generic，不能回退到泽音。主播专属能力由 `streamer_profiles.json` 中对应 profile 显式提供：

- `aliases`、`path_keywords`：识别主播身份；
- `subtitle_glossary`、`asr_replacements`：专名词表与“错误词 → 正确词”映射；
- `outro_clip`：该主播的收播系列、搜索范围和触发话术；
- `title_prefix`、`title_style_profile`：投稿标题前缀与标题风格样本。

自动模式会优先识别录播文件名中的主播名。推荐以下命名：

```text
泽音-2026-07-22 19_58-周三歌杂.flv
七海Nana7mi-2026年07月22日20点00分.flv
主播名_20260722_2000.flv
```

程序只在主播名后存在明确日期标记时提取文件名前缀，避免把普通视频标题随意当成主播名。已知主播会匹配 `streamer_profiles.json` 中的专属配置；未知但符合“主播名-日期”格式的文件只会在当前任务中基于 generic 规则生成 `【文件名前缀】`，不会继承其他主播的词表、错词、收播或标题样本，也不会写回配置文件。模型返回了错误的旧账号前缀时，程序会先删除旧前缀，再统一添加当前录播对应的前缀。

旧式录播文件名可能以直播标题开头。这种情况下可以在 `streamer_profiles.json` 的 `path_keywords` 中配置稳定的父目录关键词，或显式增加主播配置。自定义配置建议复制到本机其他路径，再设置：

```powershell
$env:AUTOSLICE_STREAMER_PROFILES = "$HOME\AutoSlice\streamer_profiles.local.json"
```

配置中的 `title_style_profile` 必须是相对于主播配置文件所在目录的路径。API token 不属于主播配置，不要写入该文件。

字幕校对页面中的“本视频额外词条”只保存在当前浏览器的当前视频设置中；在 AI 建议中明确确认“加入主播词库”后，新增的 `错误词 → 正确词` 会写入本机的
`.autoslice-state/streamer_profile_overrides.json` 覆盖文件，不会改写仓库公开的
`streamer_profiles.json`。该映射会影响该主播后续的 FunASR 热词、字幕归一化和 AI 校对，
并通过 profile 指纹使旧检查点和校对缓存重新校验；页面可以撤销本机新增映射，公开默认映射不能从页面删除。

## 7. FunASR CPU/GPU

没有同名 SRT 时，AutoSlice 会提取音频并调用 FunASR。可显式选择设备：

首次使用建议安装支持热词的免费开源模型及配套 VAD、标点、CAM++ 说话人模型：

```powershell
python setup_asr_model.py
```

安装成功后，AutoSlice 会自动优先使用 Fun-ASR-Nano-2512，并将字幕校对词表和当前
主播称呼作为受限热词；模型不存在时自动回退普通 Paraformer，不会在
日常启动时隐式下载大模型。FunASR 最低版本为 `1.4.1`，旧版本会在启动依赖检查
中提示并升级。

字幕校对工作台的新字幕识别默认勾选“排除背景音”。程序只对临时 16 kHz 单声道 WAV
应用高低通、降噪和门限，不修改源视频音轨；CAM++ 已安装时还会在每个识别块内聚类说话人，
只保留发言时长和段数占优的主要说话人。智能分析录播的原始字幕识别仍保留完整语音，不会因为
这个工作台选项默认丢弃其他说话人。

```powershell
$env:AUTOSLICE_FUNASR_DEVICE = "cpu"
python 启动.py
```

可用 CUDA、PyTorch 和对应驱动时可以使用：

```powershell
$env:AUTOSLICE_FUNASR_DEVICE = "cuda:0"
python 启动.py
```

`auto` 会尝试使用启动器管理的隔离 GPU 运行时，无法确认健康时回退到当前 Python 的 CPU/默认路径。首次下载模型时允许 ModelScope 网络访问；模型已经缓存后可以设置 `MODELSCOPE_LOCAL_ONLY=1` 离线运行。GPU 不是硬性要求，CPU 会更慢但不改变分析逻辑。

可选环境变量：

| 环境变量 | 用途 |
|---|---|
| `AUTOSLICE_FUNASR_MODEL_DIR` | 指定已下载的主识别模型目录 |
| `AUTOSLICE_FUNASR_VAD_DIR` | 指定 VAD 模型目录 |
| `AUTOSLICE_FUNASR_PUNC_DIR` | 指定标点模型目录 |
| `AUTOSLICE_FUNASR_SPK_DIR` | 指定已下载的 CAM++ 说话人模型目录 |
| `AUTOSLICE_FUNASR_SPK_MODEL` | 覆盖说话人模型 ID；仍只从对应本地 ModelScope 缓存读取 |
| `AUTOSLICE_FUNASR_HOTWORDS` | 追加空格、逗号或换行分隔的热词 |

智能分析页和字幕校对页会显示当前实际选择的 FunASR 模型、设备及是否处于兼容回退状态；
启动控制台也会输出同样提示。常见调整分为两类：

- 临时增加人名、作品名或活动名：在 `autoslice.local.json` 中设置
  `AUTOSLICE_FUNASR_HOTWORDS`，多个词用空格分隔，重启服务后生效。
- 某个主播经常把同一个词识别错：编辑 `streamer_profiles.json` 中该主播的
  `asr_replacements`，按 `["错误写法", "正确写法"]` 添加固定纠错。

普通 Paraformer 兼容模型不能直接使用热词，只会应用识别后的 `asr_replacements`；
需要原生热词时应安装推荐的 Fun-ASR-Nano-2512。修改模型、热词或专名纠错后，旧 ASR
检查点会按运行签名或热词摘要自动失效，重新识别即可应用新配置。

CAM++ 缺失时，字幕工作台仍会使用 FFmpeg 基础降噪和音量门限，并在页面明确提示当前是
“基础背景音门限”而不是主要说话人聚类。运行 `python setup_asr_model.py` 后重启服务即可启用
CAM++。单一混合音轨中同时出现且音量接近的多人声音无法被任何门限或聚类方法保证完全分离，
因此该功能是减少误识别，不是 100% 消除背景对白。

## 8. 人工时间轴

人工时间轴记录的是北京时间（现实钟点），不是视频播放进度。例如录播文件名包含开播时刻时，程序会将时间轴的钟点减去开播时刻，换算成当前视频内的秒数。多段录播属于同一场直播时，程序会按每段文件的起止范围匹配记录；不在当前段的记录不会直接套用。

时间轴只提供主题、星标和人工线索。自动分析仍然以字幕和弹幕为主，并会重新核对实际发生的前因后果、SC 起始和自然边界。详细时间轴可以先通过“优化人工时间轴”功能结合 SRT 对齐，再作为辅助输入。

## 9. AutoCover 字体与贴图

AutoCover 默认尝试使用濑户体。该字体及 B 站网页字体不随本仓库再分发；请使用自己有权使用的字体文件，并通过 `AUTOCOVER_FONT_PATH` 配置。缺少时会显示系统回退状态，不能把回退字体误认为濑户体。

贴图放在 `AUTOCOVER_STICKER_DIR` 指向的目录下，工具会扫描常见 PNG/JPG 图片。不要把个人贴图或字体加入公开仓库。AutoCover 支持 `4:3`（1440x1080）与 `16:9`（1920x1080），可分别或同步调整标题、颜色、描边、位置和缩放。

### 磁盘草稿目录

AutoCover 会在 `AUTOCOVER_OUTPUT_DIR` 指向的封面输出目录中创建 `_AutoCover草稿`。不同输入工作区使用“工作区名称 + 路径摘要”隔离；每个视频任务保存自己的 JSON 状态、选中帧、纯背景和两个比例的最后成功预览。该目录是本地编辑缓存，不应提交到 Git，也不需要手动修改其中的 JSON。

恢复草稿时必须同时满足：

- 重新扫描的是同一个输入工作区；
- 使用的是同一个封面输出目录；
- 源视频的相对路径、文件大小和修改时间没有变化；
- 保存的预览与当前比例的标题、颜色及布局指纹一致。

如果改变 `AUTOCOVER_OUTPUT_DIR`，新位置不会自动复制旧草稿。需要迁移时应在 AutoCover 关闭后整体复制 `_AutoCover草稿`，同时保持输入工作区路径不变。删除草稿目录不会影响正式导出的封面文件，但会清除所有视频的继续编辑状态。

## 10. SQLite 任务历史与检查点

源码克隆模式的任务状态保存在项目根目录的 `.autoslice-state/tasks.sqlite3`；安装态改用用户数据目录。整个状态目录都是本地运行数据并已被 Git 忽略；不要提交、共享或在服务运行时手工编辑数据库。需要隔离多实例时优先设置 `AUTOSLICE_STATE_DIR`，只需要改数据库文件时使用 `AUTOSLICE_TASK_DB`。SQLite 记录任务 ID、类型、输入/输出资源、状态、进度、安全摘要和冻结的 profile 快照，服务重启后仍可读取历史。

进程退出时，Python 后台线程会随进程结束，**不会在服务重启后继续运行**。下次启动时，遗留的 `queued` 或 `running` 任务会被幂等标记为 `interrupted`，并提示使用原资源和 profile 重新发起任务。ASR 分块、话题分析和候选复核等流水线会写独立检查点；重新发起相同工作且检查点与当前输入、profile 和策略兼容时，可从检查点续跑。不兼容或过期的检查点会重新计算，任务历史本身不等于可执行线程。
