# 开发与发布

本文说明本机开发目录、公开 staging 和 AutoCover 内置副本之间的边界。目标是避免遗漏功能，也避免把 API 配置、录播、字体、贴图或个人路径提交到 GitHub。

## 目录职责

推荐保留三个相互独立的工作区：

| 目录 | 用途 | 是否直接推送 |
|---|---|---|
| `AutoSlice` | 本机日常开发和真实录播调试 | 否 |
| `AutoCover` | AutoCover 独立开发和真实素材调试 | 否 |
| `AutoSlice-public` | 脱敏后的公开发布 staging | 是 |

本机目录允许保存忽略的配置和测试数据，但不要用 `git add .` 把整棵目录加入提交。公开提交和推送只从 `AutoSlice-public` 执行。

## 同步 AutoCover

公开仓库中的 `autocover_tool/` 是 AutoCover 的内置副本。同步脚本只管理以下白名单：

- `app.py`
- `autocover/*.py`
- `static/*.js`、`static/*.css`
- `templates/*.html`
- `tests/*.py`

README、PLAN、Git 元数据、`.codex/`、缓存、字体、贴图和导出文件不会复制。

在 `AutoSlice-public` 中先检查：

```powershell
python scripts/sync_autocover.py --check
```

确认差异后再应用：

```powershell
python scripts/sync_autocover.py --apply
git diff -- autocover_tool
```

如果目录不相邻，可以显式指定：

```powershell
python scripts/sync_autocover.py --source <AutoCover本机目录> --apply
```

## AutoSlice 模块边界

`topic_engine.py` 暂时保留为兼容 façade，现有 Web 路由、测试和外部脚本仍可从原模块导入公开函数。已经拆出的边界包括：

- `llm_client.py`：API 配置、OpenAI/Anthropic 兼容请求与响应传输；
- `streamer_profiles.py`：主播识别、称呼、标题前缀和字幕专名配置；
- `artifact_store.py`：整理包路径、原子文本/JSON 写入、旧检查点复制和相对链接。

后续拆分按“单一边界 → 定向测试 → 全量单元测试 → 真实录播续跑”的顺序进行。不要在一次提交中同时迁移字幕解析、候选判定和 FFmpeg 切片；这些模块共享时间契约，批量搬迁会放大回归风险。

## 发布前验证

在公开 staging 根目录运行：

```powershell
python -B -m unittest discover -q
python -B -m compileall -q .
node --check autocover_tool/static/app.js
python scripts/validate_public_docs.py
python scripts/scan_public_release.py
git diff --check
```

真实 LLM、FunASR、CUDA、FFmpeg 和长录播测试不应放进 GitHub Actions。完成相关业务改动后，先在本机真实录播上验证，再将脱敏代码同步到公开 staging。

## 提交与推送

1. 用 `git status --short` 和 `git diff` 检查 staging。
2. 只暂存本次逻辑变更涉及的文件。
3. 使用 Conventional Commit。
4. 正常推送 `main`，不要强推。
5. 在 GitHub Actions 中确认 Windows 测试通过。

公开仓库的自动测试位于 `.github/workflows/tests.yml`。它不会下载 FunASR 模型或 CUDA，只验证可重复的单元测试、Python 编译和 JavaScript 语法。
