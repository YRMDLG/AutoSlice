# 开发与发布

本文说明统一仓库中的开发、测试与公开发布边界。目标是避免遗漏功能，也避免把 API 配置、录播、字体、贴图或个人路径提交到 GitHub。

## 目录职责

生产代码以当前仓库为唯一来源：

| 目录 | 用途 | 是否提交 |
|---|---|---|
| `src/autoslice` | AutoSlice 唯一生产实现和包资源 | 是 |
| `src/autoslice_cover` | AutoCover 唯一生产实现和包资源 | 是 |
| `autocover_tool` | 旧启动入口、独立依赖和本机数据兼容目录 | 只提交公开源码文件 |
| `tests` | AutoSlice/AutoCover 单元、集成、架构和测试支持代码 | 是 |

本机可以继续保留相邻的历史 `AutoCover` 目录，但它不再是同步源，也不得覆盖
`src/autoslice_cover`。新功能和修复直接修改本仓库，按定向测试、完整回归、
敏感信息扫描和 Git 提交顺序发布。

## AutoCover 唯一 owner

过去使用 `scripts/sync_autocover.py` 在两个目录间复制代码，容易出现一边修复、
另一边遗漏。该同步入口已经停用；现在：

- Python owner 位于 `src/autoslice_cover`；
- HTML、CSS 和 JavaScript 位于 `src/autoslice_cover/resources`；
- `autocover_tool/app.py` 与 `autocover_tool/autocover/*.py` 只做旧导入兼容；
- 封面草稿、缓存、本机字体和贴图仍由忽略规则留在本机数据目录；
- 旧兼容模块不得加入新的业务逻辑。

## AutoSlice 模块边界

根目录 `topic_engine.py` 暂时保留为兼容 façade，现有外部脚本仍可从原模块导入公开函数。已经拆出的边界包括：

- `src/autoslice/llm`：API 契约、OpenAI/Anthropic 兼容请求与响应传输；
- `src/autoslice/streamer_profiles.py`：主播识别、称呼、标题前缀和字幕专名配置；
- `src/autoslice/artifact_store.py`：整理包路径、原子文本/JSON 写入、旧检查点复制和相对链接。

后续拆分按“单一边界 → 定向测试 → 全量单元测试 → 真实录播续跑”的顺序进行。不要在一次提交中同时迁移字幕解析、候选判定和 FFmpeg 切片；这些模块共享时间契约，批量搬迁会放大回归风险。

## 发布前验证

在公开 staging 根目录运行：

```powershell
python -B scripts/run_hermetic_tests.py -q
python -B scripts/compile_public.py
node --check src/autoslice_cover/resources/static/app.js
python -B scripts/validate_public_docs.py
python -B scripts/scan_public_release.py
git diff --check
```

真实 LLM、FunASR、CUDA 和长录播测试不应放进 GitHub Actions。完成相关业务改动后，先通过显式授权的人工冒烟入口在本机验证，再提交经过脱敏扫描的代码。

## 提交与推送

1. 用 `git status --short` 和 `git diff` 检查 staging。
2. 只暂存本次逻辑变更涉及的文件。
3. 使用 Conventional Commit。
4. 正常推送 `main`，不要强推。
5. 在 GitHub Actions 中确认 Windows 测试通过。

公开仓库的自动测试位于 `.github/workflows/tests.yml`。它不会下载 FunASR 模型或 CUDA，只验证可重复的单元测试、Python 编译和 JavaScript 语法。
