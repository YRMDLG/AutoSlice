# 故障排查

先保留控制台中第一条明确错误，确认任务 ID 和输入文件名，再按下面类别处理。不要把包含 token 的完整请求或日志直接发到公开 issue。

## API 返回 500、502、503 或 504

先确认状态码来自哪一层，不要把所有 500/503 都当成同一故障：

| 现象 | 含义 | 处理 |
|---|---|---|
| AutoSlice 接口返回 HTTP 500，并带任务 ID 或安全摘要 | 本地路由、任务调度或工作流发生未完成的服务端错误 | 记录任务 ID、第一条错误和失败步骤；到任务历史确认终态，不要盲目重启后假设线程仍在运行 |
| AutoSlice 返回 HTTP 503，内部策略类别为 `invalid_lan_configuration` | 本地 LAN 安全配置无效，请求尚未进入业务工作流；当前 JSON 响应主要显示中文错误信息 | 修复强随机 token、Host、Origin 和允许根目录，见“安全校验失败” |
| 任务/日志显示 `LLM HTTP 请求失败（HTTP 500）` | 上游模型服务内部错误，分类为一般 `server_error` | 程序会有限重试；持续出现时检查模型、协议和服务商状态 |
| 任务/日志显示 `LLM HTTP 请求失败（HTTP 503）` | 上游推理服务暂不可用，分类为 `provider_unavailable` | 并发阶段会执行有限的共享恢复探测；仍失败时保留已完成检查点，稍后重新发起任务 |
| LLM 返回 502/504 | 上游网关不可用或超时，与 503 一样进入暂不可用分类 | 稍后重试，并检查代理或服务商网关 |

排查上游 LLM：

1. 检查 `api_config.json` 的 `base_url` 是否为 API 根地址，不要重复写 `/chat/completions` 或 `/messages`。
2. 确认 `api_type` 与服务商协议一致：OpenAI 兼容用 `openai`，Anthropic 兼容用 `anthropic`。
3. 确认 token、模型名和账户额度有效；token 只在本机配置，不要复制到日志。
4. 检查 `AUTOSLICE_ANALYSIS_MODEL` 和 `AUTOSLICE_LLM_MODEL` 是否是服务商实际支持的模型。
5. 检查当前代理模式是否符合网络环境。程序不会无限重试，也不会把 API 失败伪装成“0 个高光”。

如果预检连续失败，先使用服务商提供的安全诊断方式核对 URL、协议和模型，再回到网页重跑。更换模型或提示策略后，旧的候选复核检查点可能因策略版本变化而重新复核。

## LLM 代理连接失败

按网络实际需求选择一种模式，不要同时依赖多套代理来源：

- **`direct`（默认）**：`Session.trust_env=False`，忽略 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`。API 本可直连但被系统代理干扰时选它；如果网络必须经过代理，direct 下连接失败是预期结果。
- **`system`**：使用 requests 的环境代理。当前 PowerShell 已正确配置环境代理时选它；环境代理地址失效、认证过期或指向错误端口时，应修复环境或切回 direct。
- **`custom`**：关闭环境代理，只使用 `AUTOSLICE_LLM_PROXY_HTTP`/`HTTPS` 或 `api_config.json` 的 `http_proxy`/`https_proxy`。至少配置一个 HTTP(S) URL，通常 HTTPS API 应配置 HTTPS 对应项。

环境变量优先于 `api_config.json` 的同名代理字段。出现“custom 代理模式必须配置”时，检查是否只设置了 `proxy_mode` 而没有代理 URL；出现“必须是有效的 HTTP(S) 代理 URL”时，移除路径、查询参数、片段或空白。代理 URL 可以含认证信息，但不要打印或上传；AutoSlice 会在配置表示和 requests 异常中脱敏凭据。

## 任务冲突、中断或无法恢复

- HTTP 409 通常表示同一输入/输出资源已有活动任务。先等待、取消或确认旧任务终态，不要通过改文件名制造并发写入。
- 任务历史保存在本地 `.autoslice-state/tasks.sqlite3`，服务重启后仍可读取。不要在服务运行时打开并修改 SQLite 文件。
- 服务退出时后台线程不会继续运行。下次启动会把遗留的 `queued`/`running` 标记为 `interrupted`；这不是“线程已自动恢复”。
- 使用原输入、输出和主播 profile 重新发起任务后，兼容的 ASR、话题分析或候选复核检查点可以续跑；输入、profile、热词或策略变化时可能重新计算。
- 如果提示数据库损坏，先保留 `.autoslice-state` 中的原文件、`.corrupt-*` 隔离副本和恢复审计，不要反复删除后重启。提交问题时只提供脱敏错误摘要，不上传任务数据库。

## 安全校验失败

默认模式只能通过 `127.0.0.1`、`localhost` 或 `::1` 等 loopback Host 访问。写请求需要同源 Origin/Referer 或当前协议、Host、端口对应的本机会话。

- **401（内部策略类别 `lan_authentication_required`）**：LAN 请求没有有效访问 token。确认请求头使用当前 token；不要把 token 放进 URL。
- **403（内部策略类别 `untrusted_host` / `cross_site_write`）**：Host 不在白名单，或 Origin 的协议、主机、端口与当前请求不完全一致。
- **403（内部策略类别 `path_outside_allowed_roots`）**：LAN 请求中的输入或输出路径不在 `AUTOSLICE_ALLOWED_ROOTS` 的绝对路径根目录内。
- **503（内部策略类别 `invalid_lan_configuration`）**：LAN 模式缺少至少 32 字符的强随机 token、显式 Host、完整 Origin 或绝对路径根目录。旧的 24 字符配置不再满足要求。

这些类别用于代码和自动测试定位；当前 HTTP JSON 响应主要返回对应的中文 `error` 文本，不应要求用户一定能在浏览器响应中看到类别字符串。

服务重启后内存会话失效，重新加载同源页面即可建立新会话。LAN 模式不是公网部署方案；不要通过关闭 Host/Origin 校验来“修复”访问问题。

## FunASR 模型下载失败

首次转录需要下载模型。确认网络可访问 ModelScope，并在首次运行前允许下载：

```powershell
$env:MODELSCOPE_LOCAL_ONLY = "0"
$env:AUTOSLICE_FUNASR_DEVICE = "cpu"
python 启动.py
```

下载完成后可以改回 `MODELSCOPE_LOCAL_ONLY=1` 离线使用。若网络中断，清理不完整的模型缓存后重试；已有同名前缀 SRT 时，也可以先使用现有字幕跳过转录。

## GPU 不可用或 CUDA 报错

GPU 不是必需条件。先强制 CPU 验证业务链路：

```powershell
$env:AUTOSLICE_FUNASR_DEVICE = "cpu"
$env:AUTOSLICE_DISABLE_GPU = "1"
python 启动.py
```

若 CPU 正常，说明问题在 CUDA/PyTorch/驱动组合。检查 `nvidia-smi` 和当前 Python 的 `torch.cuda.is_available()`，不要为了切片临时修改系统驱动。隔离 GPU 运行时不存在或健康检查失败时，启动器会回到当前 Python；这不会影响 AutoCover。

## 端口 5002 或 5010 被占用

启动器会识别兼容的已有服务；不兼容服务可能导致端口顺延或启动失败。查看占用进程：

```powershell
Get-NetTCPConnection -LocalPort 5002,5010 -State Listen |
  Select-Object LocalPort,OwningProcess
Get-Process -Id <进程号>
```

确认是本项目残留进程后再停止：

```powershell
Stop-Process -Id <进程号>
```

不要盲目结束不认识的进程。再次执行 `python 启动.py`，看到 AutoSlice 和 AutoCover 的服务契约后再打开网页。

## 找不到 ffmpeg 或 ffprobe

运行：

```powershell
Get-Command ffmpeg
Get-Command ffprobe
```

如果找不到，把 FFmpeg 的 `bin` 目录加入用户或系统 `PATH`，重新打开 PowerShell。候选帧提取、精确切片、字幕预览和压制都会依赖这两个程序。

## 扫描不到视频

- 确认页面中的目录是实际成品目录，而不是父目录下的快捷方式；
- 默认话题分析扫描 `recordings/`，AutoCover 默认扫描 `output/`；
- 确认扩展名是 `.flv`、`.mp4`、`.mkv`、`.mov` 或 `.avi`；
- 检查是否把视频放进了被忽略的 `封面`、`视频素材` 子目录；
- SRT/ASS 和视频最好使用相同文件名前缀；
- 目录路径包含空格或中文时，直接在网页选择，不要手工拼接 JSON 字符串。

## 人工时间轴对不上

人工时间轴是北京时间，视频报告是视频内秒数。确认录播文件名带有正确的开播日期和时间，并确认时间轴没有把“现实钟点”误写成“播放进度”。多段录播时，分别选择对应视频和人工时间轴；优化功能会按字幕寻找语义邻近位置，但仍应抽查边界。

## 字幕 AI 校对失败或反复重试

AI 校对只处理结构化建议，不会覆盖原 SRT。检查字幕编码、序号、时间轴顺序和空字幕；源 SRT 在检查过程中被其他程序修改时，任务会主动失败并要求重新检查。确认 API 可用后，使用“重新检查”会按当前字幕指纹和校对策略生成新结果，旧缓存不会被错误复用。

如果精剪成片显示“待识别”但自动识别失败，先确认 FFmpeg、FunASR 模型和 CPU/GPU 环境可用。失败时视频旁的 `*_asr_checkpoint.json` 会保留，修复环境后对同一视频重试可续跑；成功生成有效 SRT 后该检查点会自动清理。

如果“排除背景音”旁提示只启用了基础门限，说明本机没有完整的 CAM++ 缓存。关闭服务后运行：

```powershell
python setup_asr_model.py
python 启动.py
```

重新打开页面后应显示 CAM++ 主要说话人过滤已就绪。已经存在同名 SRT 时程序会保护并复用它，
不会自动重写；需要重新过滤时先备份并删除同名 SRT，再重新扫描。背景对白仍有少量残留通常是
因为它与主要说话人同时出现且音量接近，可在校对界面删除对应 cue；如果误删了需要保留的对白，
取消“排除背景音”后重新识别完整音轨。

## 字幕字体或压制失败

字幕默认要求精确字体 `Noto Sans S Chinese Black`。该字体不随仓库分发，需要在本机由 FFmpeg/libass 找到对应字体；程序会先验证解析到的字体家族。确认字体后再检查：

- 输出目录不是原视频目录或同名覆盖目标；
- `ffmpeg` 能读取输入视频和音频流；
- GPU 编码器失败时是否已自动回退 `libx264`；
- 磁盘空间是否足够写入临时 `.part.mp4`。

## AutoCover 贴图、字体或扫描失败

检查 `AUTOCOVER_INPUT_DIR`、`AUTOCOVER_OUTPUT_DIR`、`AUTOCOVER_STICKER_DIR` 和 `AUTOCOVER_FONT_PATH` 是否指向存在的本机目录/文件。贴图只扫描常见图片格式；字体缺失时可以先用系统回退验证界面，但正式导出前应配置濑户体或其他有授权字体。AutoCover 不需要 API 配置。

## AutoCover 刷新后没有恢复草稿

先确认重新扫描时使用的输入目录和封面输出目录与上次完全一致，然后检查输出目录下是否存在：

```text
_AutoCover草稿\<工作区名称>-<路径摘要>\工作区.json
```

常见原因：

- 上一次还没有成功生成过预览，因此只有浏览器即时设置，没有磁盘预览文件；
- 改用了另一个封面输出目录，对应的是另一套草稿；
- 源视频被重新导出、替换或修改，程序为避免错配而忽略旧草稿；
- 手动删除、移动或部分清理了 `_AutoCover草稿` 中的 JSON、选中帧或预览图；
- 页面仍连接旧版 AutoCover 服务。先在旧终端按 `Ctrl+C`，重新运行 `python 启动.py`，再在浏览器按 `Ctrl+F5`。

草稿 JSON 损坏时程序会忽略它而不是阻止工作区扫描。可以在 AutoCover 关闭后备份并删除对应工作区草稿目录，再重新生成预览。不要只移动 `工作区.json` 而留下图片，也不要在服务运行时手工编辑 JSON。

## 仍无法解决

收集以下脱敏信息：Windows/Python 版本、执行的入口、失败步骤、HTTP 状态码、`ffmpeg -version` 的版本号和不含 token 的错误摘要。不要上传录播、字幕、弹幕、DOCX、字体、贴图、cookies 或 `api_config.json`。
